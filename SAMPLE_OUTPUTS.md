## PR Review: feat: pre-tool-use hook that blocks destructive bash commands

### Summary
Adds a Python-based Claude Code pre-tool-use hook (`hooks/pre-tool-use`) that intercepts dangerous bash commands before execution. Covers 10 categories of destructive patterns with clear, actionable block messages. Includes a comprehensive README with 2-command installation and a dry-run mode for testing. Zero external dependencies.

### Issues Found
- 🟡 **Warning**: The `rm -rf` general rule was changed to only match absolute paths (`/`, `~/`, `/tmp/*`). This is the right UX choice (relative `rm -rf ./build` shouldn't be blocked), but the first rule (`rm -rf of critical system path`) has overlapping coverage with the general `rm -rf` rule. Consider merging them into a single rule with graduated severity.
- 🔵 **Note**: The `allowed_commands` or bypass documentation mentions `CLAUDE_HOOK_DRY_RUN=1` as an env var. Users should be aware this disables ALL blocking, not just the current command. A per-command override (`claude-review --allow-unsafe`) would be safer but adds complexity.
- 🔵 **Note**: The `DELETE FROM without WHERE` regex `r"(?i)DELETE\s+FROM\s+\w+(?!.*\bWHERE\b)"` might miss multi-line SQL or `WHERE` in subqueries. This is acceptable — the hook is a safety net, not a SQL parser.

### Suggestions
- Add a `rules.json` config file so users can customize which patterns are blocked without editing Python. The 10 rules could be externalized.
- Consider adding a `--report` mode that prints recent blocked-command stats from the log file.
- The README's 2-command install uses `curl ... | chmod +x` — add a checksum verification step for security-conscious users.
- The dry-run log could include a counter so users know how many commands would have been blocked before enabling the hook.

### Security
- ✅ No secrets hardcoded
- ✅ Input is parsed as JSON (not eval'd)
- ✅ Log file permissions are inherited from `~/.claude/hooks/` (typically 700)
- 🔵 The README installation pipes curl to a file — consider documenting the `curl ... | shasum -a 256` verification step

### Confidence
**Overall confidence: High**
Well-structured Python script with clear regex patterns and tested edge cases (force-with-lease allowed, relative rm -rf allowed). The hook follows Claude Code's JSON stdin/stdout protocol correctly. The 11 test cases in the PR description all pass.
