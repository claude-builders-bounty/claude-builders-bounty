# generate-changelog.sh

**Bounty #1 — $50**  
A Bash script that auto-generates a `CHANGELOG.md` from your git history using [Conventional Commits](https://www.conventionalcommits.org/).

## Features

- 📦 **One command** — point it at any git repo and get a formatted changelog.
- 🏷️ **Tag-aware** — automatically finds the latest tag and collects commits since then.
- 🧠 **Smart categorization** — parses conventional commit prefixes and maps them to keepachangelog-style sections:
  | Prefix    | Section   |
  |-----------|-----------|
  | `feat:`   | Added     |
  | `fix:`    | Fixed     |
  | `chore:`, `perf:`, `refactor:`, `docs:`, `style:`, `test:`, `ci:`, `build:` | Changed |
  | `!` suffix or `BREAKING CHANGE` footer | Removed |
- 📝 **Keep a Changelog** style output — follows [keepachangelog.com](https://keepachangelog.com/en/1.1.0/) format.
- 🎨 **Human-readable** — strips conventional commit prefixes and optionally keeps scope names for clarity.

## Quick Start

```bash
# 1. Make it executable
chmod +x generate-changelog.sh

# 2. Run inside any git repository
./generate-changelog.sh

# 3. Or point it at a repository
./generate-changelog.sh /path/to/my-project

# 4. Specify output path
./generate-changelog.sh -o docs/CHANGELOG.md
```

## Usage

```
generate-changelog.sh [OPTIONS] [REPO_PATH]

Options:
  -o, --output FILE     Write changelog to FILE (default: CHANGELOG.md)
  -t, --tag TAG         Start from TAG instead of the latest tag
  -r, --range RANGE     Custom git revision range (e.g. v1.0..HEAD)
  -h, --help            Show help message
```

## Examples

### Basic usage
```bash
./generate-changelog.sh
```
Produces `CHANGELOG.md` with commits since the most recent git tag.

### Custom tag
```bash
./generate-changelog.sh -t v1.2.0
```
Collects all commits from `v1.2.0` to `HEAD`.

### Custom range
```bash
./generate-changelog.sh -r "v1.0..v2.0"
```
Uses an arbitrary git revision range.

### Different output location
```bash
./generate-changelog.sh -o release-notes/CHANGELOG-v2.md
```

## How It Works

1. Validates that `git` is available and the target is a valid git repository.
2. Determines the commit range — latest tag → HEAD by default, or user-specified.
3. Fetches commit subjects via `git log`.
4. Parses each subject against the conventional commit regex:
   ```
   ^(type)(optional-scope)?!?:\s*(description)$
   ```
5. Maps each commit to **Added**, **Fixed**, **Changed**, or **Removed**.
6. Detects breaking changes via:
   - `!` before `:` in the subject (e.g., `feat!: drop support for Node 12`)
   - `BREAKING CHANGE:` / `BREAKING-CHANGE:` in the commit body
7. Writes the formatted `CHANGELOG.md` with a summary printed to stdout.

- **Git** ≥ 1.7
- Tested on: **Linux**, **macOS**, and **Windows (Git Bash / MSYS2 / WSL)**
