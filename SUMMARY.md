# Summary: CLAUDE.md Design Choices

This CLAUDE.md template is built around the conviction that **Next.js App Router's native primitives — server components, server actions, and streaming — eliminate the need for 80% of the third-party libraries typically bolted onto React projects**. Every choice flows from this: Drizzle over Prisma because it's SQL-first and generates auditable migrations; Better Auth over NextAuth because it's framework-native and typed; Turso/libsql over PostgreSQL because distributed SQLite is simpler, cheaper, and fast enough for SaaS; no tRPC because server actions already provide end-to-end type safety; no React Query because server components fetch on the server; no barrel exports because they hurt tree-shaking; and CUID2 primary keys because they enable client-side optimistic inserts without ID collisions. The folder structure separates reads (`queries/`) from writes (`mutations/`) for testability, co-locates server-only logic in `server/` to prevent accidental client bundling, and groups components by feature rather than type. The anti-patterns section explicitly bans the most common Next.js mistakes — `useEffect` data fetching, page-level `"use client"`, nested data waterfalls, and raw SQL in components — each with a concrete fix. Opinionated, with evidence. This file is designed to be dropped into any new Next.js 15 + SQLite project and immediately guide Claude Code to produce idiomatic, production-ready code without clarification loops.
