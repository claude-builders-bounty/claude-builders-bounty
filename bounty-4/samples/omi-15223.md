# Sample: BasedHardware/omi#15223

Source PR: `feat(cli): export conversation transcripts as SRT`

## Summary
The change adds an `omi conversation export` command that fetches transcript segments and writes UTF-8 SRT, with timestamp validation and overwrite protection. It also documents the command and adds focused CLI tests for Unicode output, API parameters, overwrite behavior, and malformed segments.

## Identified risks
- Output-path writability is only discovered after the conversation has already been fetched; a local path error therefore performs an unnecessary API request.
- When the output path is an existing directory and `--overwrite` is not supplied, the earlier “already exists” guard wins, so the more precise directory error is not surfaced. This is a diagnostic issue rather than data-loss risk.

## Improvement suggestions
- Validate that an existing output path is not a directory before the generic overwrite guard so the user always gets the specific path error.
- Consider validating/creating the parent directory before the network request, or explicitly keep the current ordering and test it, so local filesystem failures do not consume an API round trip.

## Confidence
High — the diff is narrowly scoped and includes direct regression coverage for the core export behavior.
