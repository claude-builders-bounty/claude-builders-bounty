## Summary
This PR adds a zero-dependency Claude Code `PreToolUse` hook that denies several destructive Bash and SQL patterns, records blocked attempts, and installs itself into the user's Claude settings. The guard is fail-closed for malformed Bash hook payloads and keeps ordinary Bash calls on Claude Code's normal permission path.

## Risks
- `DELETE FROM` is considered safe whenever the remaining statement text contains the token `WHERE`, even when that token appears only inside a SQL comment or quoted literal; an unbounded delete such as `DELETE FROM users -- WHERE intentionally absent` can therefore evade the intended guard.
- The SQL and shell detectors operate on raw command text, so benign quoted content such as `printf 'DROP TABLE is forbidden'` can be denied even though no destructive SQL is executed.
- `blocked.log` records full attempted commands. Commands frequently contain tokens, connection strings, or other secrets, while the code does not explicitly create or tighten the log file with a private mode.

## Improvement suggestions
- Tokenize or parse the SQL statement enough to distinguish executable `WHERE` clauses from comments and string literals before allowing `DELETE FROM`.
- Distinguish shell arguments/quoted data from executable command segments so destructive keywords inside `echo`/`printf` data do not trigger false positives.
- Create the log with an explicit owner-only mode such as `0600`, and consider redacting common credential-bearing arguments before persistence.
