# CLAUDE.md — Next.js 15 + SQLite SaaS

> Paste this file into the root of a greenfield Next.js 15 App Router + SQLite project. Claude Code will understand the context without asking clarifying questions.

## Stack

| Layer | Choice | Why |
|-------|--------|-----|
| Framework | Next.js 15 (App Router) | Server Components by default, streaming, partial prerendering |
| Language | TypeScript (strict) | Catch bugs at compile time, not runtime |
| Database | SQLite via better-sqlite3 | Zero-config, file-based, fast enough for SaaS scale. No Docker, no connection strings. |
| ORM | Drizzle | Type-safe, lightweight, generates SQL you can actually read |
| Validation | Zod | Runtime + compile-time, same schema for API and DB |
| Auth | Lucia v3 | Framework-agnostic, works with SQLite, no vendor lock-in |
| Styling | Tailwind CSS 4 | Utility-first, zero runtime cost |
| Package manager | pnpm | Fast, strict, disk-efficient |

## Dev Commands

```bash
pnpm dev          # Start dev server (port 3000)
pnpm build        # Type-check + production build
pnpm lint         # ESLint
pnpm db:generate  # Generate Drizzle migration SQL
pnpm db:migrate   # Apply migrations
pnpm db:studio    # Open Drizzle Studio (DB GUI)
```

## Naming Rules

- **Files**: kebab-case (`user-profile.tsx`, `get-session.ts`)
- **Components**: PascalCase exports, one per file
- **Server Actions**: `action` suffix (`create-user-action.ts`)
- **DB columns**: snake_case (SQL convention)
- **TypeScript types**: PascalCase interfaces, no `I` prefix

## Database Rules

1. **Schema lives in one file**: `src/lib/db/schema.ts`. All tables defined here. Don't scatter.
2. **Migrations are SQL files** generated by Drizzle. Never edit them by hand. If you need a manual migration, create a new `.sql` file.
3. **DB connection is a singleton**:

```typescript
// src/lib/db/index.ts
import Database from "better-sqlite3";
import { drizzle } from "drizzle-orm/better-sqlite3";
import * as schema from "./schema";

const sqlite = new Database("data.db");
export const db = drizzle(sqlite, { schema });
```

4. **Never use `SELECT *`**. Always specify columns. Drizzle handles this automatically if you use the query API.
5. **Soft deletes**: add `deletedAt` column. Never hard-delete user data.

## Server Actions vs API Routes

| Use | When |
|-----|------|
| Server Actions | Forms, mutations, data the browser submits |
| API Routes (`app/api/`) | Webhooks, third-party callbacks, public endpoints |

Server Actions must:
- Be in files with `"use server"` at the top
- Return serializable data (no `Date` objects — use strings)
- Validate input with Zod before touching the DB

## Component Patterns

- **Default to Server Components**. Only add `"use client"` when you need `useState`, `useEffect`, or browser APIs.
- **Don't wrap everything in a client boundary** just to use a hook. Lift the state up or use a smaller client component inside a server one.
- **UI primitives** go in `components/ui/`. They accept `className` and spread remaining props. No business logic.
- **Feature components** go in `components/features/`. They can call Server Actions directly.

## Auth Pattern

```typescript
// Every protected page:
import { getSession } from "@/lib/auth";
import { redirect } from "next/navigation";

export default async function DashboardPage() {
  const session = await getSession();
  if (!session) redirect("/login");
  // ...
}
```

Don't use middleware for auth checks on pages — Server Components are simpler and don't need edge runtime. Use middleware only for rate limiting or geo-blocking.

## Environment Variables

All env vars go through Zod validation at build time:

```typescript
// src/lib/env.ts
import { z } from "zod";

export const env = z.object({
  DATABASE_URL: z.string().default("file:data.db"),
  SESSION_SECRET: z.string().min(32),
  NODE_ENV: z.enum(["development", "production", "test"]).default("development"),
}).parse(process.env);
```

Never access `process.env` directly anywhere else.

## What We Don't Do (And Why)

| Don't | Why |
|-------|-----|
| Prisma | Drizzle is lighter, generates readable SQL, and doesn't need a separate client |
| NextAuth / Auth.js | Lucia is framework-agnostic and doesn't force OAuth flows |
| tRPC | Server Actions cover the same ground with less boilerplate in App Router |
| Global state (Redux, Zustand) | Server Components + URL state handles 95% of cases |
| CSS-in-JS (styled-components) | Tailwind is faster at build time and has zero runtime |
| `any` type | If TypeScript can't infer it, write the type explicitly |
| Barrel files (`index.ts` re-exports everywhere) | Tree-shaking fails, imports get confusing |
| Edge Runtime for DB queries | better-sqlite3 is synchronous, doesn't work on Edge |
