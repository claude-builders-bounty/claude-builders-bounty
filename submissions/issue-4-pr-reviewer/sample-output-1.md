## Summary

This PR implements a pre-tool-use hook for Claude Code that blocks destructive bash/SQL commands before execution. The hook intercepts dangerous commands like `rm -rf`, `DROP TABLE`, `git push --force`, and logs blocked attempts while providing Claude with clear explanations and safer alternatives.

## Identified Risks

- **Regex bypass potential**: The DELETE FROM pattern `r"\bDELETE\s+FROM\s+\S+\s*(?:;|$)"` could be bypassed with multiline statements or comments between DELETE and FROM
- **Case sensitivity gaps**: While `re.IGNORECASE` is used, some edge cases with mixed SQL/bash syntax might slip through
- **Log file permissions**: Writing to `~/.claude/hooks/blocked.log` without explicit permission checks could fail silently
- **Performance overhead**: Running regex checks on every bash command could add latency to tool execution

## Improvement Suggestions

1. **Strengthen DELETE FROM detection** in `hook.py` line 44: Replace the current pattern with `r"\bDELETE\s+FROM\s+\w+\s*(?!.*\bWHERE\b)"` to better handle multiline statements

3. **Add edge case tests** in `test_hook.py`: Include tests for multiline SQL statements, commands with embedded comments, and mixed case variations
4. **Consider adding configuration**: Allow users to customize blocked patterns or disable specific checks via a config file
5. **Improve error handling** in `main()`: Add specific exception handling for file I/O operations and provide fallback behavior when logging fails
