# CLAUDE.md — Next.js 15 + SQLite SaaS Project Guide

> Opinionated rules for building a production-ready SaaS with Next.js 15 App Router and SQLite.

```
│   │   ├── stripe.ts           # Stripe client init
│   │   ├── email.ts            # Email sending (Resend / SendGrid)
│   │   └── utils.ts            # Shared helpers (cn(), formatDate(), etc.)
│   ├── actions/                # Server Actions (one file per domain)
│   │   ├── auth.actions.ts
│   │   ├── billing.actions.ts
│   │   └── project.actions.ts
│   └── styles/
│       └── globals.css
├── public/                     # Static assets
├── drizzle.config.ts
├── next.config.ts
├── tailwind.config.ts
├── package.json
└── tsconfig.json
```

**Why this structure:**
- `(auth)` and `(dashboard)` route groups keep auth-gated routes physically separated; Next.js gracefully handles unauthorized access at the layout level.
- `db/schema/` per-file means you don't hunt through a 500-line schema file when adding a table.
- `actions/` per-domain keeps server actions discoverable — `auth.actions.ts` has signup/login/logout, `billing.actions.ts` has create-checkout-session/cancel-subscription.

## Naming Conventions

### Files
| Pattern | Example | When |
|---------|---------|------|
| `kebab-case.ts` | `auth.actions.ts` | All files except components |
| `PascalCase.tsx` | `SubscriptionCard.tsx` | React components |
| `kebab-case.css` | `globals.css` | Stylesheets |
| `snake_case` | `users_table` | Database tables |
| `camelCase` | `userId` | Database columns |

### Code
| Element | Convention | Example |
|---------|-----------|---------|
| Functions | `camelCase` | `getUserById()` |
| Server Actions | `camelCase.verbs` | `createCheckoutSession()` |
| Components | `PascalCase` | `export default function PricingCard()` |
| Types/Interfaces | `PascalCase` | `type UserProfile = {...}` |
| Enums | `PascalCase` | `enum SubscriptionTier { Free, Pro, Enterprise }` |
| Constants | `UPPER_SNAKE` | `const FREE_TIER_LIMIT = 3` |
| DB columns | `camelCase` | `stripeCustomerId` |

**Why kebab-case for files?** Next.js App Router uses kebab-case in URLs naturally. Consistency with the framework reduces cognitive load.

## Database & Migrations

### Stack: Drizzle ORM + better-sqlite3 (Turso for production)

```bash
# Commands
npm run db:generate    # Generate migration from schema changes
npm run db:push        # Push schema to local SQLite (dev only)
npm run db:studio      # Open Drizzle Studio (GUI viewer)
npm run db:seed        # Run seed.ts
npm run db:migrate     # Apply migrations in production (Turso)
```

### Migration Rules

1. **NEVER edit a committed migration file.** Generate a new one.
2. **One migration per change.** Don't bundle 3 table changes into one migration.
3. **Schema changes go in `db/schema/`.** The index re-exports everything.
4. **Soft deletes** with `deletedAt: timestamp` column — never `DELETE FROM`.
5. **Timestamps** on every table: `createdAt`, `updatedAt` (auto-updated via Drizzle `$onUpdate`).

### Migration Workflow

```
dev:    edit schema → npm run db:generate → npm run db:push → test
prod:   edit schema → npm run db:generate → npm run db:migrate → verify
```

```ts
// Example schema — db/schema/users.ts
import { sqliteTable, text, integer } from "drizzle-orm/sqlite-core";

export const users = sqliteTable("users", {
  id: text("id").primaryKey(),
  email: text("email").notNull().unique(),
  name: text("name"),
  stripeCustomerId: text("stripe_customer_id"),
  subscriptionTier: text("subscription_tier", {
    enum: ["free", "pro", "enterprise"],
  }).default("free"),
  createdAt: integer("created_at", { mode: "timestamp" })
    .notNull()
    .$default(() => new Date()),
  updatedAt: integer("updated_at", { mode: "timestamp" })
    .notNull()
    .$onUpdate(() => new Date()),
  deletedAt: integer("deleted_at", { mode: "timestamp" }),
});
```

## Patterns to Follow

### 1. Server Components by Default
Every component is a Server Component unless it needs interactivity. Add `"use client"` only when you need `useState`, `useEffect`, event handlers, or browser APIs.

```tsx
// ✅ Server Component (default)
export default async function DashboardPage() {
  const projects = await db.query.projects.findMany();
  return <ProjectList projects={projects} />;
}

// ✅ Client Component — only when needed
("use client");
export function CreateProjectButton() {
  const [open, setOpen] = useState(false);
  return <Button onClick={() => setOpen(true)}>New Project</Button>;
}
```

### 2. Server Actions for Data Mutations
Never write a raw API route for CRUD unless you need webhook compatibility. Server Actions are simpler, typed, and work without an extra endpoint.

```ts
// src/actions/project.actions.ts
"use server";

import { db } from "@/db";
import { projects } from "@/db/schema";
import { auth } from "@/lib/auth";
import { revalidatePath } from "next/cache";

export async function createProject(data: FormData) {
  const session = await auth();
  if (!session) throw new Error("Unauthorized");

  const name = data.get("name") as string;
  await db.insert(projects).values({ name, userId: session.userId });
  revalidatePath("/dashboard");
}
```

### 3. Route Handlers for External APIs
Use Route Handlers (`src/app/api/`) only for:
- Webhooks (Stripe, Clerk, etc.) — they need a raw POST endpoint
- External API proxies (add CORS headers, rate limiting)
- File upload presigned URLs

### 4. Auth: Lucia v3 (recommended) or NextAuth v5
- Session stored in SQLite (Lucia) or JWT (NextAuth)
- Auth guard in `(dashboard)/layout.tsx` — redirect unauthenticated users to `/login`
- Role-based access via middleware or `auth()` call at the top of every Server Action

```tsx
// src/app/(dashboard)/layout.tsx
import { redirect } from "next/navigation";
import { auth } from "@/lib/auth";

export default async function DashboardLayout({
  children,
}: { children: React.ReactNode }) {
  const session = await auth();
  if (!session) redirect("/login");
  return <>{children}</>;
}
```

### 5. Error Handling Pattern
```tsx
// src/app/error.tsx (Next.js Error Boundary)
"use client";
export default function ErrorPage({ error, reset }: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  return (
    <div className="flex flex-col items-center gap-4 p-8">
      <h2>Something went wrong</h2>
      <p className="text-muted-foreground">{error.message}</p>
      <Button onClick={reset}>Try again</Button>
    </div>
  );
}
```

```ts
// Server Action errors are caught and returned, not thrown
export async function deleteProject(id: string) {
  try {
    await db.delete(projects).where(eq(projects.id, id));
    revalidatePath("/dashboard");
    return { success: true };
  } catch (e) {
    return { error: "Failed to delete project" };
  }
}
```

## Anti-Patterns to Avoid

### ❌ `useEffect` for data fetching
Client component `useEffect` + `fetch` is obsolete. Use Server Components + async data fetching, or `react-query`/`swr` for client-side cache.

### ❌ Raw SQL in component files
SQL belongs in `db/schema/` and `db/index.ts`. Components and actions import typed query builders, not raw query strings.

### ❌ `pages/` directory
Next.js 15 is App Router. Don't mix `pages/` and `app/` — it creates confusion about which router handles which route.

### ❌ Storing files in SQLite
SQLite is not a file store. Use S3 / R2 / local filesystem for uploads; store only the URL in the database.

### ❌ `any` types
`strict: true` in tsconfig. Every function must have typed inputs and outputs. `any` is only acceptable in rare cases (third-party JS interop with a cast).

### ❌ Running migrations on every deploy
Generate migrations in CI, apply them as a separate step before the build. Never auto-run `db:push` in production.

### ❌ Exposing server action errors to the client
Return `{ error: "Something went wrong" }` — not the raw `Error` message which might leak stack traces or DB schema details.

### ❌ Mono-repo for a simple SaaS
A single Next.js repo is fine for < 10k LOC. Don't add turborepo/nx until you have measurable build-time pain.

## Tech Stack Summary

| Layer | Choice | Why |
|-------|--------|-----|
| Framework | Next.js 15 App Router | RSC, streaming, server actions |
| Database | SQLite (better-sqlite3) → Turso | Zero ops dev, scale-to-zero prod |
| ORM | Drizzle | Type-safe, SQL-like, tiny bundle |
| Auth | Lucia v3 | Simple, SQLite-native, no vendor lock-in |
| UI | Tailwind CSS + shadcn/ui | Copy-paste components, no npm dep |
| Forms | react-hook-form + zod | Best DX for validation |
| Payments | Stripe | Industry standard, Checkout is 3 lines |
| Email | Resend | React Email + simple API |
| Testing | Vitest + Playwright | Fast, modern, Next.js-native |
