# generate-changelog

Generate a structured `CHANGELOG.md` from a project's **git history** — no
dependencies, works on any git repo. Available two ways: a native Claude Code
skill (`/generate-changelog`) or a plain `bash changelog.sh`.

Commits are bucketed into **Added / Changed / Fixed / Removed** by reading
[Conventional Commit](https://www.conventionalcommits.org/) types (`feat:`,
`fix:`, …) with a keyword fallback for non-conventional messages, and output in
[Keep a Changelog](https://keepachangelog.com/) format.

## Setup (3 steps)

1. Copy `changelog.sh` into your repo (or `SKILL.md` into `.claude/skills/generate-changelog/`).
2. From the repo root, run **`bash changelog.sh`** — or, in Claude Code, **`/generate-changelog`**.
3. Review the generated `CHANGELOG.md` and commit it.

## Usage

```bash
bash changelog.sh                 # commits since the last tag → ./CHANGELOG.md
bash changelog.sh --stdout        # preview, write nothing
bash changelog.sh --since v1.2.0  # force the starting ref
bash changelog.sh -o NOTES.md     # custom output file
```

- **No tags?** It uses the full history and says so in the heading.
- **Version-bump commits** (`3.0.0`, `Release v1.2`) and housekeeping
  (`chore`/`docs`/`test`/`ci`) are filtered out automatically.

## Notes

- Pure Bash + git, POSIX-friendly (works on macOS's bash 3.2). No Node/Python needed.
- The script only reads commit subjects; the quality of the changelog tracks the
  quality of your commit messages. Adopt Conventional Commits for best results.
