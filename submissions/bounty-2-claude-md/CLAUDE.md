### Rules for this structure

- `app/` contains **only** Next.js page files, layouts, loading states, error boundaries, and API route handlers. No business logic.
- `lib/` contains everything that could theoretically run outside Next.js — queries, services, validation, auth.
- `components/` is purely presentational. Components do not import from `lib/db/` — ever.
- `hooks/` contains only client-side hooks (`"use client"` assumed). Never put server-only logic here.
- If a component is only used in one route, co-locate it in that route's folder. If it's used in two or more, promote it to `components/[feature]/`.

### Database tables

- **Plural snake_case**: `users`, `team_members`, `subscription_plans`
- **Junction tables**: `[table_a]_[table_b]` alphabetically: `team_members` (not `member_teams`)
- **Foreign keys**: `[referenced_table_singular]_id`: `user_id`, `team_id`
- **Timestamps**: always `created_at`, `updated_at` on every table (use `$defaultFn` in Drizzle)
- **Soft deletes**: `deleted_at DATETIME NULL` — never hard-delete user data

### API Routes

- REST-style, noun-first, kebab-case: `/api/team-members`, `/api/subscription-plans`
- Avoid verbs in route paths — use HTTP methods instead
- Stripe webhooks: `/api/stripe/webhook` (singular, no pluralization)
- Health check: `/api/health`

### Environment variables

- `SCREAMING_SNAKE_CASE`
- Prefix with service name: `STRIPE_SECRET_KEY`, `RESEND_API_KEY`, `DATABASE_URL`
- Next.js public vars: `NEXT_PUBLIC_` prefix — never put secrets here

### Rules

1. **Never commit `.env.local`**. It's in `.gitignore`. Keep it there.
2. Provide a `.env.example` with all keys and placeholder values. Keep it current.
3. In `lib/env.ts`, validate all env vars at startup with Zod:

```ts
// lib/env.ts
import { z } from "zod";

const envSchema = z.object({
  DATABASE_URL: z.string().min(1),
  AUTH_SECRET: z.string().min(32),
  NEXT_PUBLIC_APP_URL: z.string().url(),
  NODE_ENV: z.enum(["development", "test", "production"]).default("development"),
  // Add optional vars with .optional() or .default()
  STRIPE_SECRET_KEY: z.string().optional(),
  RESEND_API_KEY: z.string().optional(),
});

export const env = envSchema.parse(process.env);
```

4. Import `env` from `lib/env.ts` everywhere. Never access `process.env` directly in application code.
5. Server-only env vars go in `lib/env.ts` (server module). Client vars get a separate `lib/env.client.ts` that only contains `NEXT_PUBLIC_*` vars.

## Database — Drizzle + SQLite

### Client singleton

```ts
// lib/db/index.ts
import Database from "better-sqlite3";
import { drizzle } from "drizzle-orm/better-sqlite3";
import { env } from "@/lib/env";
import * as schema from "./schema";

const sqlite = new Database(env.DATABASE_URL.replace("file:", ""));

// Enable WAL mode for concurrent reads + writes
sqlite.pragma("journal_mode = WAL");
sqlite.pragma("foreign_keys = ON");

export const db = drizzle(sqlite, { schema });
export type DB = typeof db;
```

### Schema conventions

```ts
// lib/db/schema.ts
import { sql } from "drizzle-orm";
import {
  sqliteTable,
  text,
  integer,
  index,
  uniqueIndex,
} from "drizzle-orm/sqlite-core";

// ✅ Use cuid2 for IDs — not UUID, not auto-increment
// npm install @paralleldrive/cuid2
import { createId } from "@paralleldrive/cuid2";

export const users = sqliteTable(
  "users",
  {
    id: text("id")
      .primaryKey()
      .$defaultFn(() => createId()),
    email: text("email").notNull(),
    emailVerified: integer("email_verified", { mode: "boolean" })
      .notNull()
      .default(false),
    passwordHash: text("password_hash"),
    name: text("name"),
    avatarUrl: text("avatar_url"),
    createdAt: integer("created_at", { mode: "timestamp" })
      .notNull()
      .$defaultFn(() => new Date()),
    updatedAt: integer("updated_at", { mode: "timestamp" })
      .notNull()
      .$defaultFn(() => new Date()),
    deletedAt: integer("deleted_at", { mode: "timestamp" }),
  },
  (t) => ({
    emailIdx: uniqueIndex("users_email_idx").on(t.email),
  })
);

export const teams = sqliteTable("teams", {
  id: text("id")
    .primaryKey()
    .$defaultFn(() => createId()),
  name: text("name").notNull(),
  slug: text("slug").notNull().unique(),
  plan: text("plan", { enum: ["free", "pro", "enterprise"] })
    .notNull()
    .default("free"),
  stripeCustomerId: text("stripe_customer_id"),
  stripeSubscriptionId: text("stripe_subscription_id"),
  createdAt: integer("created_at", { mode: "timestamp" })
    .notNull()
    .$defaultFn(() => new Date()),
  updatedAt: integer("updated_at", { mode: "timestamp" })
    .notNull()
    .$defaultFn(() => new Date()),
});

// Relations
export const sessions = sqliteTable("sessions", {
  id: text("id").primaryKey(),
  userId: text("user_id")
    .notNull()
    .references(() => users.id, { onDelete: "cascade" }),
  expiresAt: integer("expires_at", { mode: "timestamp" }).notNull(),
});
```

### Migrations

**The golden rule: schema.ts is the source of truth. Migrations are generated from it. Never write SQL by hand unless absolutely necessary.**

```bash
# 1. Edit lib/db/schema.ts
# 2. Generate migration
npm run db:generate

# 3. Review the generated SQL in db/migrations/ — read it
# 4. Apply it
npm run db:migrate
```

- Migrations run automatically on `npm run build` (pre-deploy hook)
- Never run `db:push` in production — it skips the migration history
- Each migration file is immutable once pushed to main. Create a new migration to fix it.
- If a migration produces SQL you didn't expect, review the diff carefully before applying

### Query functions

All database access must go through named query functions in `lib/db/queries/`. No inline db calls in route handlers or server actions.

```ts
// lib/db/queries/users.ts
import { eq, and, isNull } from "drizzle-orm";
import { db } from "@/lib/db";
import { users } from "@/lib/db/schema";
import type { User } from "@/types";

export async function getUserById(id: string): Promise<User | null> {
  const result = await db
    .select()
    .from(users)
    .where(and(eq(users.id, id), isNull(users.deletedAt)))
    .get();

  return result ?? null;
}

export async function getUserByEmail(email: string): Promise<User | null> {
  return db
    .select()
    .from(users)
    .where(and(eq(users.email, email.toLowerCase()), isNull(users.deletedAt)))
    .get() ?? null;
}

export async function createUser(data: {
  email: string;
  passwordHash?: string;
  name?: string;
}): Promise<User> {
  const [user] = await db
    .insert(users)
    .values({
      email: data.email.toLowerCase(),
      passwordHash: data.passwordHash,
      name: data.name,
    })
    .returning();

  return user;
}

export async function updateUser(
  id: string,
  data: Partial<Pick<User, "name" | "avatarUrl" | "emailVerified">>
): Promise<User | null> {
  const [updated] = await db
    .update(users)
    .set({ ...data, updatedAt: new Date() })
    .where(eq(users.id, id))
    .returning();

  return updated ?? null;
}
```

### Transactions

Use transactions for any multi-step write operation:

```ts
// lib/db/queries/teams.ts
import { db } from "@/lib/db";
import { teams, teamMembers } from "@/lib/db/schema";

export async function createTeamWithOwner(
  teamData: { name: string; slug: string },
  userId: string
) {
  return db.transaction((tx) => {
    const [team] = tx.insert(teams).values(teamData).returning();

    tx.insert(teamMembers).values({
      teamId: team.id,
      userId,
      role: "owner",
    });

    return team;
  });
}
```

## Authentication — Lucia v3

Lucia handles sessions. Password hashing is done with `@node-rs/argon2`.

### Setup

```ts
// lib/auth/index.ts
import { Lucia } from "lucia";
import { BetterSqlite3Adapter } from "@lucia-auth/adapter-sqlite";
import { sqlite } from "@/lib/db"; // raw better-sqlite3 instance
import { env } from "@/lib/env";

const adapter = new BetterSqlite3Adapter(sqlite, {
  user: "users",
  session: "sessions",
});

export const lucia = new Lucia(adapter, {
  sessionCookie: {
    attributes: {
      secure: env.NODE_ENV === "production",
    },
  },
  getUserAttributes: (attributes) => ({
    email: attributes.email,
    name: attributes.name,
    emailVerified: attributes.email_verified,
  }),
});

declare module "lucia" {
  interface Register {
    Lucia: typeof lucia;
    DatabaseUserAttributes: {
      email: string;
      name: string | null;
      email_verified: boolean;
    };
  }
}
```

### Session validation

Every server component or action that needs auth calls `validateRequest()`. Do not inline session reads.

```ts
// lib/auth/session.ts
import { cookies } from "next/headers";
import { cache } from "react";
import { lucia } from "./index";
import type { Session, User } from "lucia";

export const validateRequest = cache(
  async (): Promise<
    { user: User; session: Session } | { user: null; session: null }
  > => {
    const sessionId =
      (await cookies()).get(lucia.sessionCookieName)?.value ?? null;

    if (!sessionId) {
      return { user: null, session: null };
    }

    const result = await lucia.validateSession(sessionId);

    try {
      const cookieStore = await cookies();
      if (result.session?.fresh) {
        const sessionCookie = lucia.createSessionCookie(result.session.id);
        cookieStore.set(
          sessionCookie.name,
          sessionCookie.value,
          sessionCookie.attributes
        );
      }
      if (!result.session) {
        const sessionCookie = lucia.createBlankSessionCookie();
        cookieStore.set(
          sessionCookie.name,
          sessionCookie.value,
          sessionCookie.attributes
        );
      }
    } catch {
      // Cookie setting throws in RSC — that's fine
    }

    return result;
  }
);

// Throws redirect to /login if unauthenticated
export async function requireAuth() {
  const { user, session } = await validateRequest();
  if (!user) {
    // Import redirect from next/navigation in server context
    const { redirect } = await import("next/navigation");
    redirect("/login");
  }
  return { user, session };
}
```

### Auth flow rules

1. **Registration**: hash password → create user → create session → set session cookie
2. **Login**: fetch user by email → verify password → invalidate old sessions → create session
3. **Logout**: invalidate session → set blank cookie → redirect
4. **Password reset**: generate time-limited token (store in `password_reset_tokens` table, expires 1hr) → email link → verify token → update password → invalidate all sessions
5. **Email verification**: generate token → email → mark `email_verified = true`

Never store plain passwords. Never store auth tokens in localStorage. Sessions only in httpOnly cookies.

## API Routes & Server Actions

### When to use which

| Scenario | Use |
|---|---|
| Form submission from a page component | Server Action |
| Webhook receiver (Stripe, etc.) | API Route Handler |
| Data needed by client-side JS (e.g., charts) | API Route Handler |
| Auth flows | API Route Handler (Lucia adapter) |
| Everything else server-side | Server Action |

### Server Actions

```ts
// app/(dashboard)/settings/actions.ts
"use server";

import { revalidatePath } from "next/cache";
import { requireAuth } from "@/lib/auth/session";
import { updateTeam } from "@/lib/db/queries/teams";
import { teamSettingsSchema } from "@/lib/validations/team";
import { AppError } from "@/lib/errors";

export async function updateTeamSettingsAction(
  _prevState: unknown,
  formData: FormData
) {
  const { user } = await requireAuth();

  const raw = {
    name: formData.get("name"),
    slug: formData.get("slug"),
  };

  const parsed = teamSettingsSchema.safeParse(raw);
  if (!parsed.success) {
    return {
      success: false,
      errors: parsed.error.flatten().fieldErrors,
    };
  }

  try {
    await updateTeam(parsed.data.teamId, parsed.data, user.id);
    revalidatePath("/settings");
    return { success: true };
  } catch (error) {
    if (error instanceof AppError) {
      return { success: false, message: error.message };
    }
    // Log unexpected errors, don't expose internals
    console.error("updateTeamSettingsAction failed:", error);
    return { success: false, message: "Something went wrong. Please try again." };
  }
}
```

### API Route Handlers

```ts
// app/api/stripe/webhook/route.ts
import { NextRequest, NextResponse } from "next/server";
import Stripe from "stripe";
import { stripe } from "@/lib/stripe";
import { env } from "@/lib/env";
import { handleStripeEvent } from "@/lib/stripe/webhooks";

export async function POST(req: NextRequest) {
  const body = await req.text();
  const sig = req.headers.get("stripe-signature");

  if (!sig) {
    return NextResponse.json({ error: "No signature" }, { status: 400 });
  }

  let event: Stripe.Event;
  try {
    event = stripe.webhooks.constructEvent(body, sig, env.STRIPE_WEBHOOK_SECRET!);
  } catch (err) {
    console.error("Stripe webhook signature verification failed:", err);
    return NextResponse.json({ error: "Invalid signature" }, { status: 400 });
  }

  try {
    await handleStripeEvent(event);
    return NextResponse.json({ received: true });
  } catch (err) {
    console.error("Stripe webhook handler failed:", err);
    // Return 200 to prevent Stripe retries for non-transient errors
    // Return 500 for transient errors you want retried
    return NextResponse.json({ error: "Handler failed" }, { status: 500 });
  }
}

// Required: disable body parsing for raw body access
export const config = {
  api: { bodyParser: false },
};
```

### Route handler conventions

- Always return `NextResponse.json()`
- Auth check at the top — fail fast
- Validate input with Zod before touching the database
- Never return stack traces or internal error messages to the client
- HTTP status codes: 400 (bad input), 401 (unauthenticated), 403 (unauthorized), 404 (not found), 422 (validation), 500 (unexpected)

## Error Handling

### AppError class

```ts
// lib/errors.ts
export class AppError extends Error {
  constructor(
    message: string,
    public code: string,
    public statusCode: number = 400,
    public data?: Record<string, unknown>
  ) {
    super(message);
    this.name = "AppError";
  }
}

// Common error factories
export const Errors = {
  unauthorized: () =>
    new AppError("You must be logged in", "UNAUTHORIZED", 401),
  forbidden: () =>
    new AppError("You don't have permission to do that", "FORBIDDEN", 403),
  notFound: (resource: string) =>
    new AppError(`${resource} not found`, "NOT_FOUND", 404),
  validation: (message: string, data?: Record<string, unknown>) =>
    new AppError(message, "VALIDATION_ERROR", 422, data),
  conflict: (message: string) =>
    new AppError(message, "CONFLICT", 409),
} as const;
```

### Error boundaries

Every route group should have an `error.tsx`:

```tsx
// app/(dashboard)/error.tsx
"use client";

import { useEffect } from "react";
import { Button } from "@/components/ui/button";

export default function DashboardError({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  useEffect(() => {
    // Log to error reporting service (Sentry, etc.)
    console.error(error);
  }, [error]);

  return (
    <div className="flex flex-col items-center justify-center min-h-[400px] gap-4">
      <h2 className="text-lg font-semibold">Something went wrong</h2>
      <p className="text-muted-foreground text-sm">
        {error.digest ? `Error ID: ${error.digest}` : "An unexpected error occurred"}
      </p>
      <Button onClick={reset}>Try again</Button>
    </div>
  );
}
```

### Rules

1. Query functions throw `AppError` for expected failures (not found, permission denied)
2. Route handlers and server actions catch `AppError` and return structured responses
3. Unexpected errors (`Error`) are logged with full context and return a generic 500 message
4. Never expose error.message from unknown errors to the client
5. In development, log everything. In production, log to a structured logger or error service.

## Component Architecture

### Server vs Client components

Default to **Server Components**. Add `"use client"` only when you need:
- `useState`, `useEffect`, or other React hooks
- Browser APIs (`window`, `document`, `localStorage`)
- Event handlers (onClick, onChange, etc.)
- Third-party client-only libraries

```tsx
// ✅ Server Component — fetches its own data, no JS bundle cost
// app/(dashboard)/page.tsx
import { requireAuth } from "@/lib/auth/session";
import { getTeamsByUserId } from "@/lib/db/queries/teams";
import { TeamCard } from "@/components/team/team-card";

export default async function DashboardPage() {
  const { user } = await requireAuth();
  const teams = await getTeamsByUserId(user.id);

  return (
    <div className="grid gap-4">
      {teams.map((team) => (
        <TeamCard key={team.id} team={team} />
      ))}
    </div>
  );
}
```

```tsx
// ✅ Client Component — only the interactive part
// components/team/delete-team-button.tsx
"use client";

import { useState } from "react";
import { Button } from "@/components/ui/button";
import { deleteTeamAction } from "@/app/(dashboard)/settings/actions";

export function DeleteTeamButton({ teamId }: { teamId: string }) {
  const [loading, setLoading] = useState(false);

  async function handleClick() {
    if (!confirm("Are you sure?")) return;
    setLoading(true);
    await deleteTeamAction(teamId);
  }

  return (
    <Button variant="destructive" onClick={handleClick} disabled={loading}>
      {loading ? "Deleting..." : "Delete team"}
    </Button>
  );
}
```

### Props discipline

- Every component has an explicit `Props` type
- No spreading unknown objects into components (`{...props}` is fine for HTML elements, not business components)
- Default exports for page/layout files, named exports for components
- Co-locate component and its types in the same file unless types are shared

### Form pattern

Use `react-hook-form` + Zod resolver + server actions via `useFormState`:

```tsx
// components/forms/update-profile-form.tsx
"use client";

import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { useFormState, useFormStatus } from "react-dom";
import { updateProfileSchema, type UpdateProfileInput } from "@/lib/validations/auth";
import { updateProfileAction } from "@/app/(dashboard)/settings/actions";

function SubmitButton() {
  const { pending } = useFormStatus();
  return <Button type="submit" disabled={pending}>{pending ? "Saving..." : "Save"}</Button>;
}

export function UpdateProfileForm({ defaultValues }: { defaultValues: UpdateProfileInput }) {
  const [state, action] = useFormState(updateProfileAction, null);

  const form = useForm<UpdateProfileInput>({
    resolver: zodResolver(updateProfileSchema),
    defaultValues,
  });

  return (
    <form action={action} className="space-y-4">
      {/* fields */}
      {state?.message && (
        <p className="text-sm text-destructive">{state.message}</p>
      )}
      <SubmitButton />
    </form>
  );
}
```

## Data Fetching & Rendering Strategy

### Decision tree

```
Is this data public and rarely changes?
  → SSG (generateStaticParams + fetch with cache)

Is this data public but changes frequently?
  → SSR (no-store cache) or ISR (revalidate: N)

Is this data user-specific or requires auth?
  → SSR (Server Component, validateRequest at top)

Does the user need to interact with it immediately?
  → Server Component + Client Component islands for interactivity

Does this data change in real-time or require optimistic updates?
  → Client Component + SWR/TanStack Query with API route
```

### Caching rules

```ts
// ✅ SSR — always fresh, auth-gated
export const dynamic = "force-dynamic"; // or: fetch(..., { cache: 'no-store' })

// ✅ ISR — revalidate every 60 seconds
export const revalidate = 60;

// ✅ SSG — build-time only
export const dynamic = "force-static";
```

- SQLite queries bypass Next.js fetch cache — they're always fresh unless you memoize with React `cache()`
- Use `revalidatePath()` or `revalidateTag()` in server actions after mutations
- Never use `export const dynamic = "force-dynamic"` on pages that could be static

### Parallel data fetching

```tsx
// ✅ Fetch in parallel in Server Components
export default async function TeamPage({ params }: { params: { teamSlug: string } }) {
  const [team, members, subscription] = await Promise.all([
    getTeamBySlug(params.teamSlug),
    getTeamMembers(params.teamSlug),
    getTeamSubscription(params.teamSlug),
  ]);

  // ...
}
```

## Performance Rules

### Bundle size

- Never import a full library when you need one function: `import { formatDate } from "date-fns"` not `import dateFns from "date-fns"`
- Check bundle impact before adding any client-side dependency: `npm run build && npx @next/bundle-analyzer`
- Keep page JS under 100KB gzipped for initial load
- Lazy-load heavy client components:

```tsx
import dynamic from "next/dynamic";

const RichTextEditor = dynamic(() => import("@/components/rich-text-editor"), {
  loading: () => <div className="h-32 bg-muted animate-pulse rounded" />,
  ssr: false, // Editor is DOM-dependent
});
```

### Images

- Always use `next/image` — never `<img>` for app content
- Specify `width` and `height` or use `fill` with a sized container
- Use `priority` on above-the-fold images
- Use `sizes` prop for responsive images

### Database

- Add indexes on every foreign key column and any column you filter/sort on
- Profile slow queries in development: enable Drizzle's `logger: true` in dev
- Use `EXPLAIN QUERY PLAN` for any query that joins 3+ tables
- Paginate all list endpoints — never return unbounded results
- Select only the columns you need — avoid `select()` (which returns all) on large tables

### SQLite-specific

```ts
// Enable WAL mode (already in db/index.ts — don't remove it)
sqlite.pragma("journal_mode = WAL");

// Batch writes in transactions — 1 transaction = 1 fsync
// Individually inserting 100 rows is 100x slower than a transaction
db.transaction((tx) => {
  for (const row of rows) {
    tx.insert(table).values(row);
  }
});
```

- **Unit tests**: pure functions in `lib/` — validations, utilities, business logic
- **Integration tests**: query functions against a real in-memory SQLite database

## Deployment

### Vercel

Best for: fast deploys, zero ops, preview environments per PR.

**Limitations with SQLite:**
- Vercel is stateless and serverless — SQLite files on the filesystem are ephemeral
- **You cannot use SQLite on Vercel's serverless functions without a persistent volume or edge DB**
- Solutions: (a) Turso (libSQL, SQLite-compatible, edge-distributed), (b) Switch to PostgreSQL with Neon

**If using Turso (recommended for Vercel):**

```bash
npm install @libsql/client drizzle-orm
```

```ts
// lib/db/index.ts (Vercel/Turso variant)
import { createClient } from "@libsql/client";
import { drizzle } from "drizzle-orm/libsql";
import { env } from "@/lib/env";

const client = createClient({
  url: env.TURSO_DATABASE_URL,
  authToken: env.TURSO_AUTH_TOKEN,
});

export const db = drizzle(client, { schema });
```

Vercel env vars: set in Dashboard → Project → Settings → Environment Variables.

### Railway

Best for: full server deployment, persistent filesystem, SQLite works natively.

```dockerfile
# Dockerfile
FROM node:20-slim AS base
RUN apt-get update && apt-get install -y python3 make g++ && rm -rf /var/lib/apt/lists/*
WORKDIR /app

FROM base AS deps
COPY package*.json ./
RUN npm ci

FROM base AS builder
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npm run build

FROM base AS runner
ENV NODE_ENV=production
COPY --from=builder /app/.next ./.next
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package.json ./
COPY --from=builder /app/db ./db
EXPOSE 3000
CMD ["npm", "run", "start"]
```

Railway persistent volume: mount at `/data`. Set `DATABASE_URL=file:/data/sqlite.db`.

**Railway deploy checklist:**
1. Add persistent volume mounted at `/data`
2. Set all env vars in Railway dashboard
3. Enable health check at `/api/health`
4. `npm run build` is the build command (runs migrations)
5. `npm run start` is the start command

### Fly.io

Best for: global distribution, persistent volumes, full control.

```toml
# fly.toml
app = "your-app-name"
primary_region = "ord"

[build]
  dockerfile = "Dockerfile"

[env]
  NODE_ENV = "production"
  PORT = "3000"

[[mounts]]
  source = "sqlite_data"
  destination = "/data"

[http_service]
  internal_port = 3000
  force_https = true
  auto_stop_machines = true
  auto_start_machines = true
  min_machines_running = 1

[[vm]]
  memory = "512mb"
  cpu_kind = "shared"
  cpus = 1
```

**Fly.io deploy commands:**

```bash

fly deploy           # Subsequent deploys
fly volumes create sqlite_data --size 1  # Create persistent volume
fly secrets set DATABASE_URL="file:/data/sqlite.db" AUTH_SECRET="..."
```

**Fly.io SQLite note:** Run only 1 instance (or use Litestream for replication). Multiple instances writing to SQLite without coordination will corrupt data.

### All platforms — production checklist

- [ ] `NODE_ENV=production`
- [ ] All required env vars set
- [ ] Database file on persistent volume (not ephemeral filesystem)
- [ ] Health check endpoint responds at `/api/health`
- [ ] Stripe webhook endpoint registered and secret set
- [ ] `AUTH_SECRET` is a cryptographically random 32+ byte value
- [ ] `NEXT_PUBLIC_APP_URL` matches the actual domain
- [ ] Error reporting configured (Sentry recommended)
- [ ] Migrations run as part of deploy (already in `npm run build`)

## Anti-Patterns

These are banned. Don't do them. Don't argue about them in code review.

### Database

```ts
// ❌ BANNED: DB import in a component
import { db } from "@/lib/db";
export default function UserProfile({ id }) {
  const user = db.select().from(users).where(eq(users.id, id)).get(); // NO
}

// ✅ DO: Server Component calls a query function
import { getUserById } from "@/lib/db/queries/users";
export default async function UserProfile({ id }) {
  const user = await getUserById(id);
}
```

```ts
// ❌ BANNED: Raw SQL strings anywhere
db.run(`SELECT * FROM users WHERE email = '${email}'`); // SQL injection + no type safety

// ✅ DO: Drizzle query builder
db.select().from(users).where(eq(users.email, email)).get();
```

```ts
// ❌ BANNED: db:push in production
// "It's fine, I'll just push the schema"
// NO. Use migrations. Always.
```

### Components

```ts
// ❌ BANNED: useEffect for data fetching
useEffect(() => {
  fetch("/api/users").then(r => r.json()).then(setUsers);
}, []); // waterfall, no loading state, no error handling

// ✅ DO: Fetch in Server Component, or use SWR/TanStack Query in Client Component
```

```ts
// ❌ BANNED: any type
const handleSubmit = (data: any) => { ... };

// ✅ DO: Explicit types or inferred from Zod schema
const handleSubmit = (data: z.infer<typeof formSchema>) => { ... };
```

### Auth

```ts
// ❌ BANNED: Rolling your own session IDs
const sessionId = Math.random().toString(36); // not cryptographically secure

// ✅ DO: Let Lucia generate session IDs (it uses crypto.randomBytes)
const session = await lucia.createSession(userId, {});
```

```ts
// ❌ BANNED: Storing sensitive data in cookies directly
cookies().set("user_id", userId); // not signed, not encrypted

// ✅ DO: Store only the Lucia session ID in the cookie; session data in DB
```

### Environment

```ts
// ❌ BANNED: Hardcoded secrets
const stripe = new Stripe("sk_live_abc123...");

// ✅ DO: Always from env
import { env } from "@/lib/env";
const stripe = new Stripe(env.STRIPE_SECRET_KEY!);
```

```ts
// ❌ BANNED: process.env direct access in components or query functions
const url = process.env.DATABASE_URL;

// ✅ DO: Import validated env
import { env } from "@/lib/env";
const url = env.DATABASE_URL;
```

### Error handling

```ts
// ❌ BANNED: Swallowing errors
try {
  await doThing();
} catch { /* nothing */ }

// ❌ BANNED: Exposing internals to client
return NextResponse.json({ error: error.message }, { status: 500 }); // stack trace goes to client

// ✅ DO: Log internally, return safe message
} catch (error) {
  console.error("doThing failed:", error);
  return NextResponse.json({ error: "An unexpected error occurred" }, { status: 500 });
}
```

## Code Style

### TypeScript settings

```json
// tsconfig.json — these are non-negotiable
{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "noImplicitReturns": true,
    "noFallthroughCasesInSwitch": true
  }
}
```

### ESLint rules that matter

- `no-console: warn` in production builds (use a logger instead)
- `@typescript-eslint/no-explicit-any: error`
- `@typescript-eslint/no-unused-vars: error`
- `import/no-default-export` except in Next.js page/layout files

### Import order

```ts
// 1. Node built-ins
import path from "path";

// 2. External packages
import { z } from "zod";
import { eq } from "drizzle-orm";

// 3. Internal — absolute paths with @/
import { db } from "@/lib/db";
import { users } from "@/lib/db/schema";

// 4. Relative
import { formatDate } from "./utils";

// 5. Types (last)
import type { User } from "@/types";
```

### General

- Functions over classes for everything except Error subclasses
- `async/await` over `.then()` chains
- Explicit return types on exported functions
- Named exports everywhere except Next.js pages and layouts
- No barrel files (`index.ts` re-exporting everything) — they break tree shaking and make grep worse
- Comments explain **why**, not **what**. If you need to explain what, rename the function.
