# CLAUDE.md — Next.js 15 + SQLite SaaS

## Stack

- **Framework**: Next.js 15 (App Router, React 19, Server Components by default)
- **Language**: TypeScript 5.x (strict mode, no `any`)
- **Database**: SQLite via `better-sqlite3` (single-file, zero-config, ACID)
- **ORM**: Drizzle ORM (type-safe, SQL-like, SQLite-native)
- **Auth**: `next-auth` v5 (credentials + OAuth providers)
- **Styling**: Tailwind CSS 4 (utility-first, no CSS modules)
- **Validation**: Zod (runtime + compile-time type safety)
- **Package Manager**: pnpm (strict, deterministic, fast)
- **Node**: 20 LTS

## Dev Commands

```bash
pnpm dev              # Start dev server (port 3000)
pnpm build            # Production build
pnpm start            # Start production server
pnpm lint             # ESLint + Prettier check

```

## Database Rules

### Schema (`lib/db/schema.ts`)

Every table MUST have these columns:

```typescript
import { sqliteTable, text, integer } from "drizzle-orm/sqlite-core";
import { sql } from "drizzle-orm";

export const users = sqliteTable("users", {
  id: text("id").primaryKey().$defaultFn(() => crypto.randomUUID()),
  // ... domain columns ...
  createdAt: integer("created_at", { mode: "timestamp" })
    .default(sql`(unixepoch())`).notNull(),
  updatedAt: integer("updated_at", { mode: "timestamp" })
    .default(sql`(unixepoch())`).notNull(),
});
```

Rules:
- Use `text` for IDs (UUIDs). Never auto-increment integers for primary keys.
- Use `integer` with `{ mode: "timestamp" }` for dates (Unix epoch seconds).
- Use `text` for enums (SQLite has no enum type). Validate with Zod at the boundary.
- All columns are `NOT NULL` unless there is an explicit reason to allow NULL.
- Foreign keys always use `references(() => parentTable.id)` with `onDelete: "cascade"`.
- Table names are plural snake_case (`users`, `billing_plans`).
- Column names are singular snake_case (`email`, `created_at`).

### Migrations

```bash
# After changing schema.ts:
pnpm db:generate      # Creates SQL file in lib/db/migrations/
pnpm db:migrate       # Applies it to data/app.db
```

Rules:
- NEVER edit migration files after they are generated. If you made a mistake, generate a new corrective migration.
- NEVER delete migration files. They form an immutable history.
- NEVER use raw SQL outside of migrations. All queries go through Drizzle ORM.
- Run `db:migrate` on app startup in production (in `lib/db/index.ts`).
- Backup `data/app.db` before destructive migrations. SQLite has no `ALTER COLUMN` — Drizzle handles this with table recreation.

### Connection (`lib/db/index.ts`)

```typescript
import Database from "better-sqlite3";
import { drizzle } from "drizzle-orm/better-sqlite3";
import * as schema from "./schema";

const sqlite = new Database("data/app.db", {
  // WAL mode: concurrent reads, better write performance
  // Set ONCE at connection time, persists in the file
});
sqlite.pragma("journal_mode = WAL");
sqlite.pragma("busy_timeout = 5000");
sqlite.pragma("synchronous = NORMAL");
sqlite.pragma("cache_size = -64000"); // 64MB cache
sqlite.pragma("foreign_keys = ON");

export const db = drizzle(sqlite, { schema });
```

Rules:
- ONE connection instance, exported as singleton. Never create multiple connections.
- WAL mode is mandatory. It allows concurrent reads during writes.
- `busy_timeout` prevents "database is locked" errors under load.
- `foreign_keys = ON` must be set per-connection (SQLite disables by default).

## Component Patterns

### Server Components (default)

All components in `app/` are Server Components unless marked otherwise.

```typescript
// app/(dashboard)/page.tsx — Server Component (default)
import { db } from "@/lib/db";
import { users } from "@/lib/db/schema";
import { DashboardStats } from "@/components/layouts/DashboardStats";

export default async function DashboardPage() {
  const totalUsers = await db.select().from(users);
  return <DashboardStats count={totalUsers.length} />;
}
```

Rules:
- Fetch data directly in Server Components. No `useEffect` for data loading.
- Pass serializable props to Client Components. No functions, no class instances.
- Use `loading.tsx` for Suspense boundaries, not manual loading states.

### Client Components

Only use `"use client"` when you need: `useState`, `useEffect`, event handlers, or browser APIs.

```typescript
// components/ui/Counter.tsx
"use client";

import { useState } from "react";

export function Counter({ initial }: { initial: number }) {
  const [count, setCount] = useState(initial);
  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}
```

Rules:
- Mark `"use client"` at the TOP of the file, first line.
- Keep Client Components small and leaf-level. Push state down, not up.
- Never import Server Components inside Client Components.

### Server Actions

Use Server Actions for mutations (forms, buttons that change data).

```typescript
// app/(dashboard)/settings/actions.ts
"use server";

import { db } from "@/lib/db";
import { users } from "@/lib/db/schema";
import { eq } from "drizzle-orm";
import { revalidatePath } from "next/cache";
import { z } from "zod";

const updateNameSchema = z.object({
  userId: z.string().uuid(),
  name: z.string().min(1).max(100),
});

export async function updateName(formData: FormData) {
  const parsed = updateNameSchema.safeParse({
    userId: formData.get("userId"),
    name: formData.get("name"),
  });

  if (!parsed.success) {
    return { error: parsed.error.flatten().fieldErrors };
  }

  await db.update(users)
    .set({ name: parsed.data.name, updatedAt: new Date() })
    .where(eq(users.id, parsed.data.userId));

  revalidatePath("/settings");
  return { success: true };
}
```

Rules:
- Server Actions go in a separate `actions.ts` file (not inline in components).
- Always validate input with Zod. Never trust form data.
- Always call `revalidatePath` or `revalidateTag` after mutations.
- Return `{ error }` or `{ success }` objects. Never throw from Server Actions.

### Forms

```typescript
// components/forms/UpdateNameForm.tsx
"use client";

import { useActionState } from "react";
import { updateName } from "@/app/(dashboard)/settings/actions";

export function UpdateNameForm({ userId }: { userId: string }) {
  const [state, action, isPending] = useActionState(updateName, null);

  return (
    <form action={action}>
      <input type="hidden" name="userId" value={userId} />
      <input name="name" required minLength={1} maxLength={100} />
      <button type="submit" disabled={isPending}>
        {isPending ? "Saving..." : "Save"}
      </button>
      {state?.error?.name && <p className="text-red-500">{state.error.name}</p>}
    </form>
  );
}
```

Rules:
- Use `useActionState` (React 19) for form state, not `useFormStatus`.
- Use native HTML validation attributes as first line of defense.
- Show loading state via `isPending`, not a separate state variable.

## API Routes

Only use API routes (`app/api/`) for:
- Webhook handlers (Stripe, OAuth callbacks)
- External API consumers (mobile apps, third-party integrations)
- Streaming responses

For internal data mutations, use Server Actions instead.

```typescript
// app/api/webhooks/stripe/route.ts
import { NextRequest, NextResponse } from "next/server";

export async function POST(request: NextRequest) {
  const body = await request.text();
  const signature = request.headers.get("stripe-signature");

  // Verify webhook signature before processing
  // ...

  return NextResponse.json({ received: true });
}
```

Rules:
- Always verify webhook signatures. Never trust unverified payloads.
- Use `NextRequest`/`NextResponse` (not the deprecated `req`/`res` API).
- Return proper HTTP status codes (200, 400, 401, 404, 500).

| Thing | Convention | Example |
|-------|-----------|---------|
| Files (components) | PascalCase | `UserProfile.tsx` |
| Files (utilities) | camelCase | `formatDate.ts` |
| Files (routes) | kebab-case folders | `app/billing/page.tsx` |
| React components | PascalCase | `export function UserProfile()` |
| Hooks | camelCase, `use` prefix | `useAuth()`, `useDebounce()` |
| Server Actions | camelCase, verb prefix | `createUser()`, `deletePost()` |
| DB tables | snake_case, plural | `billing_plans` |
| DB columns | snake_case, singular | `created_at` |
| Zod schemas | camelCase, `Schema` suffix | `createUserSchema` |
| TypeScript types | PascalCase | `type User = ...` |
| Environment variables | SCREAMING_SNAKE | `DATABASE_URL` |
| CSS classes | Tailwind utilities only | `className="flex items-center"` |

## What We Don't Do (and Why)

| Anti-Pattern | Why We Avoid It | What We Do Instead |
|-------------|----------------|-------------------|
| `useEffect` for data fetching | Race conditions, no SSR, waterfall requests | Server Components with direct `db` queries |
| CSS Modules / styled-components | Extra build complexity, harder to scan | Tailwind CSS utilities |
| Prisma ORM | Heavy, slow cold starts, generates too much code | Drizzle ORM (lighter, SQL-like, faster) |
| PostgreSQL / MySQL | Requires separate server, connection management | SQLite (single file, zero-config, embedded) |
| `any` type | Defeats TypeScript's purpose entirely | Explicit types, `unknown` + narrowing |
| Barrel exports (`index.ts`) | Breaks tree-shaking, circular dependencies | Direct imports from specific files |
| `console.log` for debugging | Leaks into production, no structure | Structured logger or remove before commit |
| Relative imports (`../../../`) | Fragile, hard to refactor | Path alias `@/` (configured in `tsconfig.json`) |
| `getServerSideProps` / `getStaticProps` | Pages Router API, not App Router | Server Components + `generateStaticParams` |
| Global state (Redux, Zustand) for server data | Duplicates server state on client | Server Components + `revalidatePath` |
| Manual `fetch` in Client Components | Missing caching, error handling, types | Server Actions or React Query (if truly needed) |
| Integer auto-increment IDs | Predictable, exposes entity count, migration headaches | UUIDs (`crypto.randomUUID()`) |
| `.env.local` for production secrets | Risk of committing secrets | Environment variables set in deployment platform |
| `npm` / `yarn` | Phantom dependencies, slower installs | `pnpm` (strict, fast, disk-efficient) |

## Environment Variables

```bash
# .env.local (development only — never commit)
DATABASE_URL=data/app.db
NEXTAUTH_SECRET=<random-32-char-string>
NEXTAUTH_URL=http://localhost:3000

# OAuth providers (optional)
GITHUB_ID=
GITHUB_SECRET=
GOOGLE_ID=
GOOGLE_SECRET=

# Stripe (optional)
STRIPE_SECRET_KEY=
STRIPE_WEBHOOK_SECRET=
```

Rules:
- All secrets go in `.env.local` (gitignored by default in Next.js).
- Access via `process.env.VARIABLE_NAME` in server-side code only.
- For client-side env vars, prefix with `NEXT_PUBLIC_` (use sparingly).
- Never put secrets in `NEXT_PUBLIC_` variables.

## Error Handling

- Use `error.tsx` boundary files for page-level error recovery.
- Use `not-found.tsx` for 404 pages (call `notFound()` from server code).
- In Server Actions, return error objects. Never throw.
- In API routes, always return appropriate HTTP status codes with JSON bodies.
- Log errors server-side with context (user ID, action, input). Never expose stack traces to clients.

## Testing

- **Unit tests**: Vitest for utilities, hooks, and Zod schemas.
- **Integration tests**: Vitest + `better-sqlite3` in-memory DB for database logic.
- **E2E tests**: Playwright for critical user flows (auth, billing, CRUD).
- Test files live next to the code they test: `utils/formatDate.ts` → `utils/formatDate.test.ts`.
- Minimum coverage for merge: 80% on `lib/` and `utils/`.

## Performance

- Use `React.lazy` and dynamic imports for heavy client components.
- Use `<Image>` from `next/image` for all images (automatic optimization).
- Use `<Link>` from `next/link` for all internal navigation (prefetching).
- Keep SQLite queries under 10ms. Use `EXPLAIN QUERY PLAN` to check indexes.
- Add indexes for any column used in `WHERE`, `ORDER BY`, or `JOIN`.
