# 🤖 claude-review — Structured PR Review Sub-Agent

A Claude Code sub-agent that takes a GitHub pull request, analyzes its diff, and
produces a **structured Markdown review** — Summary, Risks, Suggestions, and a
Confidence score. Run it from the CLI, or wire it into CI as a GitHub Action so
every PR gets an automatic review comment.

> Bounty: [#4 — AGENT: Claude Code sub-agent that reviews a PR and posts a structured comment](https://github.com/claude-builders-bounty/claude-builders-bounty/issues/4)

---

## What you get

Every review follows the same shape, so it's skimmable and CI-friendly:

```markdown
## 📋 Summary
2–3 sentences on what the PR changes and why.

## ⚠️ Risks
- Concrete bugs / regressions / security concerns, citing files from the diff.

## 💡 Suggestions
- Specific, actionable improvements (tests, edge cases, naming, docs).

## 🎯 Confidence
**Low | Medium | High** — one sentence justifying the score.
```

See real, unedited outputs in [`samples/`](./samples) — both generated by this
tool against live PRs in [`cli/cli`](https://github.com/cli/cli):

| Sample | PR | Size |
|--------|----|------|
| [`cli-cli-13599.md`](./samples/cli-cli-13599.md) | [cli/cli#13599 — alias `gh extension uninstall`](https://github.com/cli/cli/pull/13599) | +4 / -3, 1 file |

## Requirements

- [`gh`](https://cli.github.com) — GitHub CLI, authenticated (`gh auth login`)
- [`claude`](https://docs.claude.com/claude-code) — Claude Code CLI, authenticated
- `bash` and `python3` (both standard on macOS/Linux)

---

## Setup

```bash
# From the repo root:
chmod +x agents/pr-review/claude-review

# (optional) put it on your PATH
ln -s "$PWD/agents/pr-review/claude-review" /usr/local/bin/claude-review
```

That's it — no build step, no dependencies to install.

## Usage (CLI)

```bash
# Review a PR by URL and print the Markdown to stdout
claude-review --pr https://github.com/owner/repo/pull/123

# Shorthand ref also works
claude-review --pr owner/repo#123

# Review AND post the result as a comment on the PR
claude-review --pr https://github.com/owner/repo/pull/123 --post

# Pick a specific model
claude-review --pr owner/repo#123 --model claude-opus-4-8

# Save to a file
claude-review --pr owner/repo#123 > review.md
```

| Flag | Description |
|------|-------------|
| `--pr <ref>` | **Required.** PR URL (`.../pull/123`) or `owner/repo#123`. |
| `--post` | Post the review back to the PR as a comment (needs write access). |
| `--model <name>` | Override the Claude model. Defaults to your CLI's configured model. |
| `-h`, `--help` | Show usage. |

### How it works

1. `gh pr view` fetches PR metadata (title, author, body, change stats).
2. `gh pr diff` fetches the unified diff (truncated past ~120k chars to stay
   within the model's context window — truncation is flagged in the output).
3. The diff + metadata are piped to `claude -p` with the **pr-reviewer**
   sub-agent's instructions, which force the structured Markdown format.
4. The result is printed, and optionally posted with `gh pr comment`.

The review prompt lives in two places kept in sync: inline in the
[`claude-review`](./claude-review) script (so the CLI is self-contained) and as
a native Claude Code sub-agent in
[`.claude/agents/pr-reviewer.md`](./.claude/agents/pr-reviewer.md) (so you can
also invoke it interactively — just copy it into your project's `.claude/agents/`
and ask Claude to "review PR #123 with the pr-reviewer agent").

## Usage (GitHub Action)

Copy [`github-action/claude-review.yml`](./github-action/claude-review.yml) to
`.github/workflows/claude-review.yml` in your repository, then add one secret:

1. **Settings → Secrets and variables → Actions → New repository secret**
2. Name: `ANTHROPIC_API_KEY`, value: your Anthropic API key.

The workflow runs on every `pull_request` (opened / synchronize / reopened),
installs the Claude Code CLI, runs `claude-review --pr <pr-url> --post`, and
comments the structured review on the PR. It uses the built-in `GITHUB_TOKEN`
(no extra setup) and the `pull-requests: write` permission to post.

## Design notes

- **Grounded reviews.** The prompt instructs the model to base every statement
  only on the visible diff and to explicitly say when a hunk is partial — this
  keeps it from hallucinating files or behavior, and is reflected in honest
  Confidence scores (see the samples).
- **Deterministic structure.** The four-section format is fixed, so output is
  consumable by humans and by downstream tooling alike.
- **No lock-in.** Plain `bash` + `gh` + `claude`. Swap the model, fork the
  prompt, or call it from any CI system.
