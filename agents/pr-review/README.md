# claude-review

A zero-dependency PR review agent: give it a GitHub PR URL, it fetches the
diff and returns a structured Markdown review — summary, risks, suggestions,
confidence score. No LLM API key, no build step, fully auditable.

Built for the
[claude-builders-bounty #4](https://github.com/claude-builders-bounty/claude-builders-bounty/issues/4)
`$150` bounty.

## Install

```bash
curl -sL https://raw.githubusercontent.com/claude-builders-bounty/claude-builders-bounty/main/agents/pr-review/claude-review -o claude-review
chmod +x claude-review
```

(Note: the `raw.githubusercontent.com` URL above resolves once this PR is
merged; until then, grab `claude-review` from the PR branch.)

Requires `curl` and `python3` (preinstalled on macOS, Linux, GitHub runners).

## Usage

```bash
# review a PR
./claude-review --pr https://github.com/owner/repo/pull/123

# save the review to a file
./claude-review --pr https://github.com/owner/repo/pull/123 --output review.md

# offline: review a local unified diff (also useful for testing)
./claude-review --diff-file changes.diff --title "my change"
```

Set `GITHUB_TOKEN` to raise the API rate limit (optional for public PRs).

## What it checks

| # | Check | Severity |
|---|-------|----------|
| 1 | Secrets in added lines: AWS keys, GitHub tokens, `sk-` keys, Slack tokens, private keys, hardcoded passwords | HIGH |
| 2 | Dangerous patterns: `rm -rf`, `curl\|wget … \| sh`, `eval`, `chmod 777` | HIGH |
| 3 | Diff > 500 added lines; binary files changed | MED |
| 4 | Lockfiles changed; TODO/FIXME markers; no test files touched | suggestion |

Every HIGH finding includes a file location and a "verify intentional" note —
e.g. a safety tool's own source legitimately contains `rm -rf` strings, and
the review says so instead of crying wolf.

### Confidence score

- **High** — small, focused diff, no high-severity findings
- **Medium** — sizable diff or high-severity findings needing human verification
- **Low** — large diff where heuristic review may miss context

## Sample output

```markdown
## PR Review: `owner/repo#123` — Add login page

### Summary

This PR changes 4 file(s) (+250/-12 lines, including 2 new file(s)),
mostly tsx,ts files under src/components. No high-severity findings
from static checks.

### Risks

- [MED] Binary files changed — cannot be reviewed as text; verify provenance.

### Suggestions

- Diff is sizable (+250 lines); a focused re-read of the core logic is worthwhile.
- No test files touched — consider adding tests for the changed behavior.

### Confidence: Medium
_Sizable diff (+250 lines)._

---
_Generated by claude-review (heuristic, zero-dependency). Human review still recommended._
```

Real outputs against two live PRs are in [`samples/`](samples/).

## GitHub Action

`.github/workflows/claude-review.yml` posts the review as a PR comment on
every opened/updated PR:

```yaml
on:
  pull_request_target:
    types: [opened, synchronize]
```

Copy the workflow into your repo and it just works — `GITHUB_TOKEN` is
provided by Actions automatically.

## Design notes

Most PR-review bots shell out to an LLM, which means an API key, per-run
cost, and non-reproducible output. `claude-review` goes the other way:
deterministic heuristics, zero secrets, identical input → identical output.
It complements human review; it does not replace it.
