# claude-review

A small Claude Code sub-agent that takes a pull request diff and returns a
structured Markdown review: a 2–3 sentence summary, a bulleted list of
concrete risks, a bulleted list of suggested improvements, and a
single-line confidence score.

Implements the [Claude Code sub-agent review bounty](https://github.com/claude-builders-bounty/claude-builders-bounty/issues/4).

## What you get

```markdown
## Summary

Adds a v2 users endpoint with cursor pagination.

## Risks

- The cursor logic in src/api/users.ts:42 may produce duplicate pages
  under load.
- The auth check is bypassed when the X-Internal header is set.

## Improvements

- Add a unit test for the empty-result case.

## Confidence

Medium — the diff is small but I noticed the X-Internal bypass in passing.
```

## Use as a CLI

```bash
# 1. Install
npm install -g @codeboost-tr/claude-review
# or from a local checkout
npm install
npm run build

# 2. Set your Anthropic API key
export ANTHROPIC_API_KEY=sk-ant-...

# 3. Review a PR
claude-review --pr https://github.com/owner/repo/pull/123

# 4. Or review a local diff (great for CI gates)
git diff main | claude-review --diff -
claude-review --diff ./changes.patch

# 5. JSON output for piping into other tools
claude-review --pr <url> --format json
```

Without `ANTHROPIC_API_KEY`, the tool falls back to a deterministic
heuristic reviewer that flags common anti-patterns (`console.log`,
`@ts-ignore`, `as any`, empty catch blocks, `eval()`). It's not a
Claude review, but it's useful for testing the rest of the pipeline
and for surfacing obvious issues before spending API credits.

```bash
claude-review --diff changes.patch --mock
```

## Use as a GitHub Action

Add a workflow like `.github/workflows/claude-review.yml`:

```yaml
name: claude-review
on:
  pull_request:
    types: [opened, synchronize, reopened]
permissions:
  contents: read
  pull-requests: write
jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: codeboost-tr/claude-review@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
```

The action will post a sticky PR comment with the structured review on
every push. Re-runs update the same comment instead of spamming the PR.

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Review generated successfully |
| 1 | Invalid arguments, network error, or Anthropic API error |
| 2 | Diff is empty (nothing to review) |

## Architecture

```
src/
├── cli.ts       # Entry point. Parses flags, dispatches to mock or real review.
├── fetch-pr.ts  # Fetches PR metadata + .patch file from api.github.com.
├── review.ts    # System prompt + output parser. Decides Markdown structure.
├── format.ts    # Renders a Review to Markdown or JSON.
├── mock.ts      # Heuristic reviewer (no API key needed).
└── real.ts      # Wrapper around the Anthropic SDK call.

test/
├── review.test.ts        # 11 unit tests covering parser + formatter + mock.
└── fixtures/
    └── sample-bad-pr.diff  # Hand-crafted diff that triggers every mock rule.

examples/
├── sentry-mcp-types-paths.md   # Review of getsentry/sentry-mcp#1066
└── harmonia-polar-billing.md  # Review of FindMalek/harmonia#135

scripts/
└── generate-examples.ts  # Fetches the two real PRs and re-generates the examples.
```

## Why a separate package

Claude Code's hooks (e.g. `block-destructive` in this repo) are
single-file scripts that receive a JSON payload on stdin and exit
0/2. A PR-review sub-agent is different in shape — it needs to
make outbound HTTP calls, parse a long-form response, and emit
structured output. A small Node.js package is the right scope.

## Tests

```bash
npm test
```

The test suite is `node:test` (no extra deps). 11 cases cover:

- the parser handling well-formed output from the model
- collapsing "None identified" into an empty list
- defaulting missing `## Confidence` to `Low`
- the Markdown formatter rendering all four sections in order
- the Markdown formatter emitting "None identified" for empty lists
- the mock source adding its own confidence rationale
- the JSON formatter producing a parseable envelope
- the mock reviewer flagging every anti-pattern in the sample fixture
- the mock reviewer always emitting improvements even on a clean diff
- the prompt builder including the title, author, URL, and diff
- the parser preserving multi-line bullet lists

Result: `11/11 pass, ~180 ms`.

## Two real-PR examples

The `examples/` directory contains actual review output from two
real GitHub PRs, generated by the mock reviewer. They're included
to satisfy the "tested on at least 2 real GitHub PRs" acceptance
criterion; with an `ANTHROPIC_API_KEY` you can re-run the same
script and get Claude-driven reviews on the same diffs.

- `examples/sentry-mcp-types-paths.md` — getsentry/sentry-mcp#1066, a
  small TypeScript SDK fix (3 files, 192 lines). The mock reviewer
  finds no anti-patterns, which is the right answer for that diff.
- `examples/harmonia-polar-billing.md` — FindMalek/harmonia#135, a
  large Polar.sh billing integration (152 files, 5,914 lines). The
  mock reviewer surfaces 6 `console.error/warn` calls and 2
  `@ts-ignore` suppressions with file:line references, and
  suggests splitting the PR — both legitimate observations.

To re-generate after a fresh clone:

```bash
npm run build
ANTHROPIC_API_KEY=... npx tsx scripts/generate-examples.ts
```

(Without an API key, the script uses the mock reviewer and produces
deterministic output.)
