## Summary

Preserves cancel-vs-timeout semantics in the fetch adapter when Safari's fetch rejects with a DOMException-like object whose `name` and `message` getters throw. The new branch in `lib/adapters/fetch.js` checks the composed signal's `aborted` state and `reason` before reading the caught error, so a user-initiated `controller.abort()` surfaces as `CanceledError` and a timeout surfaces as `AxiosError(ETIMEDOUT)` even when the underlying fetch error is unreadable.

## Identified risks

- The new branch is positioned before the existing `TypeError + /Load failed|fetch/i.test(err.message)` fallback. If a Safari fetch throws a TypeError that is *unrelated* to abort but the composed signal happens to be in an aborted state for any reason, the new branch now intercepts and the prior TypeError handling is skipped. The PR's tests do not cover this overlap; the failure mode would be a user-visible classification regression for a niche Safari path.
- A behavior change is shipped without explicit changelog mention: the smoke test in `tests/smoke/bun/tests/timeout.smoke.test.ts` is updated from `ECONNABORTED` to `ETIMEDOUT`. Any consumer matching on `err.code === 'ECONNABORTED'` for fetch-adapter timeouts will silently break on upgrade. This is the right code, but the silence is the issue.
- `composedSignal.reason instanceof AxiosError` assumes reasons set by axios internals are always AxiosError instances. If a future internal site sets the abort reason to a different error class (e.g. a CanceledError that does not extend AxiosError, depending on the inheritance chain), this branch silently bypasses preservation. There is no test fence for "reason is a non-AxiosError abort cause."
- The `request` reference is captured by `request && (canceledError.request = request)` after `unsubscribe()` runs. If the previous unsubscribe path nulls out `request` on certain platforms, the canceled error loses request context. The test mocks do not exercise this teardown ordering.

## Improvement suggestions

- Add a test in `tests/unit/adapters/fetch.test.js` for `controller.abort(new Error('custom reason'))`. Assert that the new branch is *not* taken (because the reason is not an `AxiosError`) and the existing TypeError fallback handles the path. This pins the branch's exclusivity.
- Add an entry to `CHANGELOG.md` under fixes: "fetch adapter timeout error code is now ETIMEDOUT (was ECONNABORTED in some browsers)." A consumer who matches on the old code can then update intentionally rather than discovering the change in production.
- At `lib/adapters/fetch.js:412`, add a short comment explaining *why* the branch is positioned before the TypeError fallback (Safari emits broken DOMException → reading `.message` throws → reason-first path is the only readable signal). A future maintainer reordering for "cleanliness" would otherwise be likely to break Safari.
- The three new test cases share the same `safariFetch` factory pattern. Extract into a `createSafariFetchMock(onSignal)` helper to keep the second test (user-initiated abort) and third test (timeout under Safari) visually focused on their assertion, not on the boilerplate setup.

The fix targets a real Safari behavior and the new tests cover the headline cases (timeout → ETIMEDOUT, user abort → CanceledError, Safari + broken DOMException → ETIMEDOUT).
