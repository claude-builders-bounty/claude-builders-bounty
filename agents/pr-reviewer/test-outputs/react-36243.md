# PR Review: facebook/react#36243

## Summary
This PR fixes a build issue in the eslint-plugin-react-hooks www build where a bare `require('ReactFeatureFlags')` call from the www Haste module system survives Rollup bundling. The fix replaces the full `ReactFeatureFlags.www.js` fork with a minimal shim that only exports the specific flags needed by the eslint plugin, avoiding the CJS require that Rollup cannot tree-shake. Clean, targeted fix for a real build breakage.

## Identified Risks
- The minimal shim hardcodes specific feature flag values rather than reading them dynamically. If new flags are added to the www build that the eslint plugin needs, the shim must be manually updated (potential maintenance burden).
- The approach of creating a separate fork file specifically for the eslint plugin increases the surface area of feature flag forks. If the fork naming convention changes, this file could be overlooked.
- No test explicitly validates that `require('ReactFeatureFlags')` does NOT appear in the final bundle output. The fix relies on the Rollup behavior being correct rather than asserting it.

## Improvement Suggestions
- Add a build-time assertion or grep check in CI that validates the eslint-plugin bundle does not contain `require('ReactFeatureFlags')` to prevent regression.
- Add a code comment in the new shim file explaining WHY it exists and linking back to this PR for future maintainers.
- Consider whether the eslint plugin could avoid depending on feature flags entirely by making the flagged behaviors configurable at the plugin level instead.

## Confidence Score
**High**
Small, focused 3-file change with clear problem statement. The fix is straightforward and the build issue is well-documented in the PR description.
