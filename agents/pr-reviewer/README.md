# pr-reviewer

A Claude Code **sub-agent** that reviews a GitHub PR diff and returns a structured Markdown comment a maintainer could paste directly. Plus a CLI wrapper (`claude-review`) and a GitHub Action workflow for automated review on PR open.

Submitted for [claude-builders-bounty issue #4](../../issues/4).

## What you get

```
agents/pr-reviewer/
  agent.md                     # Sub-agent definition (drop into ~/.claude/agents/)
  claude-review                # Bash CLI wrapper around the agent
  .github/workflows/
    pr-review.yml              # GitHub Action workflow (drop into any repo)
  samples/
    cli-cli-13272.md           # Real review of a real merged PR
    axios-axios-10806.md       # Real review of a real merged PR
```

## Output shape

The agent always emits four sections in this order, with these exact headings:

```markdown
## Summary

<2-3 sentences capturing intent + mechanism>

## Identified risks

- <one risk per bullet, complete sentence, lead with failure mode>

## Improvement suggestions

- <one suggestion per bullet, concrete: name file, function, or line>

## Confidence: <Low | Medium | High>

<one paragraph explaining why that level>
```

No emoji, no preamble, no `## Verdict` section — the agent advises, the maintainer decides.

## Setup

### Local CLI usage

```bash
# 1. Install the agent definition into your Claude Code agents folder.
mkdir -p ~/.claude/agents
cp agents/pr-reviewer/agent.md ~/.claude/agents/pr-reviewer.md

# 2. Put the wrapper somewhere on PATH.
sudo install -m 755 agents/pr-reviewer/claude-review /usr/local/bin/claude-review
# Or symlink: ln -s "$PWD/agents/pr-reviewer/claude-review" ~/bin/claude-review

# 3. Make sure gh and claude CLIs are installed and authenticated.
gh auth status
claude --version
```

Then:

```bash
claude-review --pr https://github.com/cli/cli/pull/13272
claude-review --pr 10806 --repo axios/axios
gh pr diff 5 | claude-review --stdin --pr-url https://github.com/me/repo/pull/5
claude-review --diff /tmp/pr.diff --pr-url https://github.com/me/repo/pull/5
```

### CI usage (GitHub Action)

```bash
# In any repo you want auto-reviewed:
mkdir -p .github/workflows
cp agents/pr-reviewer/.github/workflows/pr-review.yml .github/workflows/

# Add a repo secret:
gh secret set ANTHROPIC_API_KEY --body "sk-ant-api..."
```

The workflow triggers on `opened`, `reopened`, and `synchronize` (new commits). It posts a sticky review comment using `marocchino/sticky-pull-request-comment@v2`, so subsequent runs overwrite the previous review rather than spamming the PR.

The workflow needs an `ANTHROPIC_API_KEY` repo secret. This is an API key from `console.anthropic.com`, not a Claude Max subscription token (those are different products).

## How to verify

The two files in `samples/` are real reviews of real merged PRs:

- [`samples/cli-cli-13272.md`](samples/cli-cli-13272.md) — review of [cli/cli#13272 "Fix log terminal injection"](https://github.com/cli/cli/pull/13272), 114 additions across 3 files, security-relevant
- [`samples/axios-axios-10806.md`](samples/axios-axios-10806.md) — review of [axios/axios#10806 "fix(fetch): preserve abort reasons in fetch adapter"](https://github.com/axios/axios/pull/10806), 131 additions across 3 files, browser-compat fix

Both samples were generated by feeding the actual PR diff and metadata (via `gh pr view --json` + `gh pr diff`) to the pr-reviewer agent, with no manual editing of the output. They demonstrate:
- The Summary section captures intent + mechanism without restating the title or listing files
- The Risks section calls out concrete failure modes with the conditions that trigger them, and explicitly flags when something is hypothetical
- The Suggestions section names files, functions, and line numbers (`lib/adapters/fetch.js:412`) — never generic advice
- Confidence is justified, not just claimed

## Design choices

**Why a sub-agent instead of a one-shot prompt:** the agent's behavior rules (no emoji, no LGTM, cite line numbers, cap at ~600 words, four exact section headings) are the actual product. Encoding them in the agent's frontmatter means anyone running `claude-review` gets the same review shape regardless of session context, and the rules can evolve via PRs to `agent.md` without consumers needing to re-paste a long prompt.

**Why both CLI and GitHub Action:** the CLI is for ad-hoc local review (a maintainer wanting a second opinion before merging). The Action is for shifting that review left to the moment the PR opens. Both invoke the same agent, so the output is consistent.

**Why a sticky comment in CI:** PR review is iterative. Posting a fresh comment on each push pollutes the timeline and makes it hard for the maintainer to find the *current* review. The sticky comment overwrites in place.

**What the agent will not do:** the agent does not approve or block PRs. There is no `## Verdict` section. The maintainer decides — the agent informs.
