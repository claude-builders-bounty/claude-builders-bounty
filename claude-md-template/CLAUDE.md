# CLAUDE.md — Next.js 15 + SQLite SaaS

> Opinionated project context for Claude Code. Every rule exists for a reason.

## Stack

| Layer | Choice | Why |
|-------|--------|-----|
| Framework | Next.js 15 (App Router) | Server Components, streaming, layouts |
| Database | SQLite via better-sqlite3 | Zero-latency reads, single-file deploys, no daemon |
| Auth | NextAuth.js v5 / Better Auth | Type-safe, SQLite-native, session-based |
| Styling | Tailwind CSS v4 + shadcn/ui | Utility-first, zero runtime CSS |
| Validation | Zod | Runtime + static types from one schema |
| ORM | Drizzle ORM | SQL-first, SQLite-native, type-safe, lightweight |
| Testing | Vitest | Fast, ESM-native, compatible with Vite |
| E2E | Playwright | Only when explicitly needed |
| Package Manager | pnpm | Fast, disk-efficient, strict hoisting |
| Runtime | Node.js 20 LTS | Long-term support, modern JS features |

## Database Rules

### Migrations

- **Never** edit generated migration files after they've been applied
- **Always** use `drizzle-kit generate` then `drizzle-kit migrate` — never raw SQL in production
- **One migration per feature branch** — squash before merge if needed
- Migration files live in `db/migrations/` — auto-generated, do NOT touch
- Run `drizzle-kit push` in dev only; generate proper migrations for prod

### Schema Conventions

```typescript
// ✅ DO: Explicit, typed, with sensible defaults
export const users = sqliteTable('users', {
  id: text('id').primaryKey().$defaultFn(() => createId()),
  email: text('email').notNull().unique(),
  name: text('name').notNull(),
  emailVerified: integer('email_verified', { mode: 'timestamp' }),
  createdAt: integer('created_at', { mode: 'timestamp' })
    .notNull().$defaultFn(() => new Date()),
  updatedAt: integer('updated_at', { mode: 'timestamp' })
    .notNull().$defaultFn(() => new Date()),
})

// ❌ DON'T: Use auto-increment IDs (breaks distributed deploys)
// ❌ DON'T: Use REAL for money — use integer cents
// ❌ DON'T: Nullable columns without a reason — prefer defaults
// ❌ DON'T: Define the same column pattern across files (DRY it)
```

### Every Table MUST Have

```typescript
id: text('id').primaryKey().$defaultFn(() => createId()),
createdAt: integer('created_at', { mode: 'timestamp' })
  .notNull().$defaultFn(() => new Date()),
updatedAt: integer('updated_at', { mode: 'timestamp' })
  .notNull().$defaultFn(() => new Date()),
```

- Indexes on: foreign keys, `email`, `slug`, any column used in WHERE
- For enums, use `text()` with a union type — NOT a separate enum table

### Query Patterns

```typescript
// ✅ DO: Use transactions for multi-step writes
import { db } from '@/lib/db'
import { users, subscriptions } from '@/db/schema'

const result = db.transaction((tx) => {
  const user = tx.insert(users).values(data).returning().get()
  tx.insert(subscriptions).values({ userId: user.id, plan: 'free' }).run()
  return user
})

// ✅ DO: Use .get() for single rows, .all() for multiple
const user = db.select().from(users).where(eq(users.id, id)).get()
const allUsers = db.select().from(users).all()

// ❌ DON'T: Chain multiple .get() calls outside a transaction
// ❌ DON'T: SELECT * when you only need 3 columns
// ❌ DON'T: Write raw SQL strings in components — use Drizzle queries
```

## Component Patterns

### Server Components (Default — always prefer these)

```typescript
// ✅ DO: Fetch data directly in Server Components — no API layer needed
import { getUsers } from '@/db/queries/users'

export default async function UserList() {
  const users = await getUsers()
  return <UserTable users={users} />
}

// ✅ DO: Use searchParams for list filtering/sorting/pagination
export default async function UsersPage({
  searchParams,
}: {
  searchParams: Promise<{ page?: string; q?: string }>
}) {
  const { page, q } = await searchParams
  const users = await getUsers({ page: Number(page) || 1, query: q })
  return <UserTable users={users} initialPage={Number(page) || 1} />
}
```

### Client Components (Minimal — use only when needed)

```typescript
// ✅ DO: Add 'use client' ONLY for interactivity (hooks, events, browser APIs)
'use client'

import { useState } from 'react'
import { useFormStatus } from 'react-dom'
import { Button } from '@/components/ui/button'

export function DeleteButton({ onDelete }: { onDelete: () => Promise<void> }) {
  const [pending, setPending] = useState(false)
  
  async function handleClick() {
    setPending(true)
    await onDelete()
    setPending(false)
  }

  return <Button disabled={pending} onClick={handleClick}>Delete</Button>
}

// ❌ DON'T: Fetch data in Client Components with useEffect
// ❌ DON'T: Add 'use client' to layout.tsx or page.tsx unless absolutely required
// ❌ DON'T: Use Redux / Zustand for global state — URL params + Server Components cover 95%
```

### Naming Conventions

| What | Convention | Example |
|------|-----------|---------|
| Files | `kebab-case.tsx` | `user-table.tsx` |
| Components | PascalCase | `UserTable` |
| Functions | camelCase | `getUsers()` |
| DB columns | snake_case in DB, camelCase in Drizzle | `created_at` → `createdAt` |
| Routes (app) | kebab-case | `app/(dashboard)/billing-history/` |
| Routes (api) | /api/[resource]/[action] | `/api/users/create` |

## API Route Handlers

```typescript
// ✅ DO: Thin handlers that validate + delegate to services
import { NextResponse } from 'next/server'
import { createUserSchema } from '@/lib/validations/user'
import { createUser } from '@/services/user'

export async function POST(req: Request) {
  const body = await req.json()
  
  // 1. Validate input
  const parsed = createUserSchema.safeParse(body)
  if (!parsed.success) {
    return NextResponse.json({ error: parsed.error.flatten() }, { status: 400 })
  }
  
  // 2. Delegate to service
  const user = await createUser(parsed.data)
  
  return NextResponse.json(user, { status: 201 })
}

// ❌ DON'T: Put business logic in route handlers
// ❌ DON'T: Skip Zod validation
// ❌ DON'T: Return raw DB errors to the client
```

## Auth Rules

- **Every dashboard route** is protected by the `(dashboard)` layout's auth check
- **API routes** that need auth: call `getSession()` from `lib/auth.ts` at the top
- **Never** trust client-side auth state for server decisions
- **Session cookies** must be: `httpOnly: true`, `secure: true`, `sameSite: 'lax'`
- **Rate limit** login/register endpoints — use middleware or Upstash
- **Password reset tokens** must have an expiry (1 hour max)

## What We Don't Do (And Why)

| Anti-pattern | Why Not |
|-------------|---------|
| Prisma | Overhead for SQLite; Drizzle is leaner and more SQL-native |
| Redux / Zustand / global state | Server Components + URL state cover 95% of cases |
| tRPC | Next.js Server Actions + Route Handlers replace this completely |
| Custom API client layer | Server Components fetch directly; no client round-trip needed |
| CSS-in-JS | Runtime cost; Tailwind is zero-runtime |
| `any` type | Use `unknown` + type guards — strict mode is on for a reason |
| Barrel exports (`index.ts`) | Tree-shaking is imperfect; import directly — causes circular deps |
| Monolithic components | Split into container (data) + presentational (UI) |
| Client-side data fetching | Use Server Components + Server Actions instead |
| Auto-increment IDs | Breaks distributed deploys and DB migrations |
| `REAL` for money | Use integer cents — floating point is unpredictable |

## Testing Conventions

```typescript
// ✅ DO: Test behavior, not implementation
import { describe, it, expect } from 'vitest'
import { createUser } from '@/services/user'

it('creates a user with a free subscription', async () => {
  const user = await createUser({ email: 'test@example.com', name: 'Test' })
  expect(user.email).toBe('test@example.com')
  expect(user.plan).toBe('free') // default subscription
})

// ❌ DON'T: Test internal state or mock everything
// ❌ DON'T: Use snapshot tests for UI (fragile, hard to review)
```

- **Unit tests** for services, utilities, and DB queries
- **Integration tests** for API routes — test the full request cycle
- **No E2E tests** unless the feature specifically requires it
- Test files: `*.test.ts` colocated with the source file

## Git Conventions

- **Conventional commits**: `feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`, `db:`
- **One feature per branch** — squash on merge
- **PR descriptions** must include: What changed, Why, How to test
- **No force pushes** on `main`

## Deployment

- **Target**: Vercel (default) or any Node.js host (Docker optional)
- **SQLite**: For production, use Turso (remote SQLite) or persist via volume mount
- **Migrations**: Run `pnpm db:migrate` as part of build/release step
- **Environment**: Secrets via `.env.local` (never committed) — documented in `.env.example`
- **Health check**: `GET /api/health` returns `{ status: "ok", db: "connected" }`

## Performance Rules

- **Server Components** for data fetching (no client waterfalls)
- **Suspense boundaries** for streaming slow queries
- **Images**: Always use `next/image` with explicit `width` and `height`
- **Fonts**: Load via `next/font` (Google Fonts or self-hosted)
- **Bundle analysis**: Run before merging large PRs — watch for unexpected bloat
