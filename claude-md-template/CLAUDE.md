# CLAUDE.md — Next.js 15 + SQLite SaaS

> Opinionated project context for Claude Code. Every rule has a reason.

## Stack & Versions

```
next@15          # App Router only. No Pages Router.
react@19         # Server Components by default.
better-sqlite3   # Synchronous, zero-config, single-file DB.
drizzle-orm      # Type-safe SQL. No magic, no runtime bloat.

```

**Runtime:** Node.js 20+ (LTS). Deploy target: Vercel or VPS with `next start`.

### Rules

- **One component per file.** Name matches export: `UserAvatar.tsx` → `export function UserAvatar`.
- **No barrel exports.** No `index.ts` re-exports. Import directly from the file.
- **Route Handlers over API routes.** Use `app/api/[resource]/route.ts`, not Pages API.
- **Server Components by default.** Add `'use client'` only when you need `useState`, `useEffect`, or browser APIs.

## SQL & Migration Conventions

### Schema (Drizzle)

```typescript
// db/schema.ts — THE source of truth
import { sqliteTable, text, integer } from 'drizzle-orm/sqlite-core';

export const users = sqliteTable('users', {
  id: text('id').primaryKey().$defaultFn(() => crypto.randomUUID()),
  email: text('email').notNull().unique(),
  name: text('name').notNull(),
  role: text('role', { enum: ['admin', 'member'] }).default('member').notNull(),
  createdAt: integer('created_at', { mode: 'timestamp' }).$defaultFn(() => new Date()),
  updatedAt: integer('updated_at', { mode: 'timestamp' }).$defaultFn(() => new Date()),
});
```

### Rules

- **UUIDs for primary keys.** Never auto-increment integers. UUIDs are merge-safe and non-guessable.
- **Timestamps as integers.** SQLite has no native datetime. Use `integer({ mode: 'timestamp' })`.
- **`createdAt` + `updatedAt` on every table.** No exceptions.
- **Soft delete with `deletedAt`.** Never `DELETE FROM` in application code. Add `deletedAt: integer('deleted_at', { mode: 'timestamp' })` and filter with `.where(isNull(users.deletedAt))`.
- **Enums as text with allowed values.** Use `text('role', { enum: [...] })` — not a separate table.

### Migrations

```bash
# Generate migration from schema changes
npx drizzle-kit generate

# Apply migrations
npx drizzle-kit migrate

# Never edit migration files manually.
# Never rename migration files.
# To fix a migration: revert schema change, generate new migration.
```

### Queries

```typescript
// lib/queries/users.ts
import { db } from '@/db';
import { users } from '@/db/schema';
import { eq, isNull } from 'drizzle-orm';

export async function getUserById(id: string) {
  return db.select().from(users)
    .where(eq(users.id, id))
    .where(isNull(users.deletedAt))
    .get();
}

// Always filter by deletedAt.
// Always use .get() for single row, .all() for lists.
// Never use raw SQL unless Drizzle can't express the query.
```

### Server Actions (mutations)

```typescript
// lib/actions/users.ts
'use server';

import { revalidatePath } from 'next/cache';
import { db } from '@/db';
import { users } from '@/db/schema';
import { createUserSchema } from '@/lib/validators/users';

export async function createUser(formData: FormData) {
  const parsed = createUserSchema.safeParse(Object.fromEntries(formData));
  if (!parsed.success) {
    return { error: parsed.error.flatten().fieldErrors };
  }

  await db.insert(users).values(parsed.data);
  revalidatePath('/users');
  return { success: true };
}
```

### Rules

- **Validate all inputs with Zod.** Never trust `formData` or request bodies directly.
- **Server Actions for mutations.** Not Route Handlers (unless you need a public API).
- **`revalidatePath` after every mutation.** Keep the cache fresh.
- **Return `{ error }` or `{ success }`.** Never throw from Server Actions — return structured errors.

## What We Don't Do (and Why)

| We Don't | Why |
|----------|-----|
| Use Prisma | Runtime bloat, slow cold starts. Drizzle is lighter and type-safe. |
| Use `any` type | Defeats TypeScript. Use `unknown` + type guards instead. |
| Use Pages Router | Legacy. App Router is the future. No `/pages` directory. |
| Use ORMs with lazy loading | Implicit N+1. Drizzle forces explicit joins. |
| Store files in SQLite | BLOBs degrade performance. Use S3/R2 + store the URL. |
| Use `fetch` in Server Components for internal APIs | Direct DB queries are faster. `fetch` is for external APIs only. |
| Use `getServerSideProps` / `getStaticProps` | App Router uses `async` Server Components directly. |
| Create `.css` files | Tailwind covers everything. Custom CSS is a maintenance burden. |
| Use `default export` for components | Named exports enable better refactoring and IDE support. |
| Skip error boundaries | Every route group needs an `error.tsx`. Crashes must be caught. |

## Error Handling

```tsx
// app/(dashboard)/error.tsx
'use client';

export default function ErrorBoundary({ error, reset }: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  return (
    <div>
      <h2>Something went wrong</h2>
      <button onClick={reset}>Try again</button>
    </div>
  );
}
```

- **Every route group gets an `error.tsx`.** No silent crashes.
- **Every route group gets a `loading.tsx`.** No layout shift.
- **Log errors server-side.** Never expose stack traces to users.
