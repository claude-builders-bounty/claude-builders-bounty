## Summary

This PR refactors the `useIntersectionObserver` hook to reduce unnecessary re-renders by using `useRef` for the callback instead of recreating it on every render. It also adds proper cleanup of the `IntersectionObserver` instance in the `useEffect` return function, which fixes a memory leak. The changes are generally sound and follow React best practices, but there are a few areas that could use tightening.

## Identified Risks

- **Stale closure over callback ref (MEDIUM)**: The `callbackRef` is updated in a `useEffect` with `[callback]` dependency, which means there's a one-render gap where the old callback fires before the ref is updated. If the callback captures props/state, this could fire with stale values. Consider using `useLayoutEffect` to synchronously update the ref before the browser paints, or use the functional updater pattern.
- **Multiple observer instances on rapid re-mounts (MEDIUM)**: The cleanup function calls `observer.disconnect()`, but if the component unmounts and remounts rapidly (e.g., React Strict Mode in development, or fast route changes), the `observerRef.current` might not be nulled out in time, leading to a new observer being created while the old one is still referenced. Set `observerRef.current = null` after calling `disconnect()`.
- **Missing `threshold` in dependency array (LOW)**: The `useEffect` that creates the observer depends on `rootMargin` but not `threshold`. If `threshold` changes after mount, the observer won't be recreated with the new value. Either add it to the dependency array or document that `threshold` is only read on mount.

## Improvement Suggestions

- Replace the `[callback]` dependency in the callback-updating effect with a ref pattern that syncs on every render: `callbackRef.current = callback` directly in the render body (no effect needed), which eliminates the one-frame gap
- Add `observerRef.current = null` immediately after `observerRef.current.disconnect()` in the cleanup function to prevent double-disconnect issues
- Consider extracting the observer creation logic into a `useMemo` or a separate effect that includes `threshold` in its dependency array, or add a comment explaining why `threshold` is intentionally excluded
- Add a unit test that verifies the observer is properly disconnected on unmount — currently the test suite only checks the callback firing, not cleanup
- The JSDoc comment says "returns a ref and a boolean" but actually returns a callback ref and a boolean — update documentation for accuracy
- Consider exposing an `enabled` parameter to allow conditional observation, a common pattern in production use cases
