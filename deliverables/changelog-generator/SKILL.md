# Changelog Generator — Claude Code Skill

> Automatically generates a structured `CHANGELOG.md` from a project's git history.

---

## Overview

This skill scans a git repository's commit history and produces a professional,
[Keep a Changelog](https://keepachangelog.com/)-formatted `CHANGELOG.md` with
automatic categorization by commit type.

## Usage

```bash
# From the project root
./scripts/generate-changelog.sh

# Generate since a specific version
./scripts/generate-changelog.sh --since v1.0.0

# Custom output path
./scripts/generate-changelog.sh --output docs/CHANGELOG.md

# Preview without writing
./scripts/generate-changelog.sh --dry-run
```

## How It Works

1. **Scans git history** — collects all non-merge commits in the specified range
2. **Categorizes by type** — uses conventional commit prefixes and keyword matching:
   - `feat` / `feature` / `add` / `new` / `implement` → **Added**
   - `fix` / `bug` / `repair` / `resolve` / `patch` → **Fixed**
   - `docs` / `doc` / `document` / `comment` / `readme` → **Documentation**
   - `refactor` / `ref` / `restructure` → **Refactored**
   - `break` / `breaking` / `feat!` → **Breaking Changes**
   - Everything else → **Other**
3. **Generates semantic version** — auto-increments the patch version from the latest tag
4. **Outputs structured markdown** — follows Keep a Changelog format

## Acceptance Criteria

- ✅ Generates a valid `CHANGELOG.md` with proper markdown formatting
- ✅ Categorizes commits into: Breaking Changes, Added, Fixed, Refactored, Documentation, Other
- ✅ Supports `--since` flag for incremental changelog generation
- ✅ Supports `--dry-run` for preview
- ✅ Auto-detects project name from git repo
- ✅ Auto-generates next semantic version from latest tag
- ✅ Prepend to existing CHANGELOG.md without duplicating header
- ✅ Uses [Keep a Changelog](https://keepachangelog.com/) format

- ✅ Zero dependencies — pure bash + git

## Limitations

- Requires a git repository
- Commit messages should follow conventional commit style for best categorization
- Does not parse commit bodies (only subjects)
- Semantic version increment assumes patch-level changes; manual override may be needed
