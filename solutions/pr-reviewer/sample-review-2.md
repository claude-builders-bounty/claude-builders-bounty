### 📝 Summary

This PR fixes a redirect loop that occurs when `trailingSlash: true` is configured and middleware issues a redirect to a path without a trailing slash. The fix normalizes the redirect target URL in the middleware adapter to respect the `trailingSlash` configuration before comparing it to the current URL. A regression test is added to prevent recurrence.

### ⚠️ Identified Risks

- **[Risk Level: Medium]** The URL normalization in `normalizeTrailingSlash()` does not account for query parameters or hash fragments. A URL like `/about?ref=home` could be incorrectly normalized to `/about/?ref=home` if the function naively appends a slash before the query string boundary. — `packages/next/src/server/web/adapter.ts:147`
- **[Risk Level: Medium]** The comparison `normalizedUrl === request.nextUrl.pathname` may fail for URLs with encoded characters (e.g., `%20` vs space). This could cause the redirect loop to persist for paths with special characters. — `packages/next/src/server/web/adapter.ts:152`
- **[Risk Level: Low]** The test only covers the basic `/about` → `/about/` case. Edge cases like root path `/`, API routes `/api/data`, and internationalized paths `/en/about` are not tested. — `test/e2e/middleware-trailing-slash/middleware-trailing-slash.test.ts:18`
