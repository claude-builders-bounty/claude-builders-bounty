## Naming Conventions

### Files
- Components: PascalCase.tsx
- Hooks: use{CamelCase}.ts
- Utilities: camelCase.ts
- API routes: kebab-case directory
- DB migrations: auto-generated by drizzle-kit (DO NOT rename)

### Variables and Functions
- React components: PascalCase
- Everything else: camelCase
- Constants (config, env vars): UPPER_SNAKE_CASE
- Database columns: snake_case (Drizzle maps to camelCase in queries)
- Types/interfaces: PascalCase prefixed with T or I

### Database
- Tables: plural snake_case (users, team_members, subscription_plans)
- Join tables: {table1}_{table2}
- Columns: created_at, updated_at on every table
- Primary keys: UUID v7 (preferred) or id auto-increment
- Foreign keys: {referenced_table}_id

## Patterns to Follow

### Server Actions (preferred over API routes)
Use server actions for mutations. Always validate input, check auth, use Drizzle ORM, and revalidatePath after success.

### Database Queries (Drizzle ORM)
Use Drizzle for type-safe queries with relations. Avoid raw SQL unless absolutely necessary. Do not use Prisma (slower for SQLite).

### Error Handling
Use server actions with try/catch. Return {success: true} or throw typed errors. Log server-side errors. Never expose internal error messages to clients.

## Anti-Patterns to Avoid

- Import server code in client components (use server actions)
- Store secrets in .env.local (use .env + .env.example)
- Use 'any' type (prefer 'unknown' with type guards)
- Skip input validation on server actions
- Commit .env files, node_modules, .next, dist/
- Use useEffect for data fetching (prefer server components + actions)
- Add dependencies without evaluating bundle impact
