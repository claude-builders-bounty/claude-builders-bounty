### 📋 Summary of Changes

This PR delivers a CHANGELOG generator as both a Claude Code SKILL (`/generate-changelog`) and a standalone bash script (`changelog.sh`). It parses git history since the last tag, categorizes commits by Conventional Commits type into Added/Fixed/Changed/Removed sections, and outputs Keep a Changelog-compliant markdown. Includes a SKILL.md with comprehensive Chinese/English documentation and a sample output file.

---

### ⚠️ Identified Risks

1. **Git tag dependency fragility**: The default mode uses `git describe --tags --abbrev=0` to find the last tag, which fails silently on repos with zero tags. The script falls back to all commits but doesn't warn the user — a new project's first release gets a full-history dump labeled as a point release.

2. **No duplicate deduplication**: The SAMPLE-CHANGELOG.md shows identical entries (e.g., `feat: add browser-harness lesson` appears twice) because the script doesn't merge identical commit messages from different branches after a merge. This produces noisy, unprofessional changelogs.

3. **Docker image reference is aspirational**: The SKILL.md documents `docker run ghcr.io/claude-builders-bounty/changelog-generator:latest` but there's no Dockerfile in this PR — the image doesn't exist. Users following the docs will get a pull error.

4. **Chinese-only commit type parsing**: The SKILL.md is heavily Chinese-focused (commit messages parsed as Chinese patterns). International teams using English-only Conventional Commits (the standard) may get unexpected categorization.

---

### 💡 Improvement Suggestions

1. **Add tag detection with user guidance**: When no tags exist, output a clear message like "No git tags found. Generating full history as initial changelog. Create a tag with `git tag v1.0.0` for versioned releases." and mark the section as `[Unreleased]` instead of guessing a version.

2. **Deduplicate entries post-merge**: After categorizing commits, pass the list through `sort -u` or use associative arrays to track seen `(type, scope, subject)` tuples before output.

3. **Either add a Dockerfile or remove the Docker docs**: If containerized delivery is desired, include a minimal `Dockerfile`. Otherwise, remove the Docker section to avoid broken documentation.

4. **Add an `--english` flag or auto-detect locale**: The commit type regex could accept both Chinese and English type prefixes (e.g., `feat` and `feat(scope)`) to work universally.

### 🟢 Confidence: `Medium`

Solid implementation of the core requirement — the script correctly fetches commits, categorizes, and formats output. The SKILL.md is thorough and the dual CLI + SKILL approach is smart. The tag-edge-case handling and Docker doc gap are the main quality concerns keeping this from "High" confidence.
