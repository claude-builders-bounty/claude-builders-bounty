### 📋 Summary of Changes

This PR adds a Claude Code `PreToolUse` hook (`destructive_command_guard.py`) that intercepts and blocks dangerous Bash commands before execution. It covers 4 destructive pattern categories (rm -rf, DROP TABLE, TRUNCATE, git push --force) using regex-based BlockRule classes, with a companion `install_settings.py` to register the hook in Claude's settings.json. Includes a test suite (5 tests) and documentation (DESTRUCTIVE_COMMAND_HOOK.md, PR_DESCRIPTION_HOOK.md).

---

### ⚠️ Identified Risks

1. **Missing `DELETE FROM without WHERE`**: The bounty explicitly requires blocking `DELETE FROM` statements lacking a WHERE clause, but this pattern is not included in BLOCK_RULES. The bounty acceptance criteria will reject this.

2. **`rm -r -f` (separated flags) not caught**: The regex `r"\brm\s+(?:-[^\s]*[rR][^\s]*[fF]|-[^\s]*[fF][^\s]*[rR])\b"` matches combined flags like `-rf` but misses space-separated `-r -f`. Commands like `rm -r -f /tmp/build` bypass the guard.

3. **Settings pollution**: `install_settings.py` injects the hook into `~/.claude/settings.json`, which is an undocumented dependency. Claude Code hooks in `~/.claude/hooks/` are auto-discovered by convention — the extra settings step is unnecessary and could conflict with other hook installations.

4. **Inconsistent output**: The hook exits with code `2` on block (line shown in PR description), but the bounty spec implies exit `1` for blocking. This may cause inconsistent behavior in Claude Code's hook runner.

---

### 💡 Improvement Suggestions

1. **Add the missing DELETE FROM rule** with a negative-lookahead for WHERE: `r"\bdelete\s+from\s+\w+(?:(?!\bwhere\b).)*$"` — this is a core bounty requirement.

2. **Extend rm regex** to catch separated flags by adding: `(?:-[^\s]*[rR].*-[^\s]*[fF])` alternation to also match `rm -r ... -f` pattern.

3. **Remove `install_settings.py`**: Claude Code auto-discovers hooks placed in `~/.claude/hooks/pre-tool-use/` — the settings injection is redundant and fragile.

4. **Use exit code 1** for blocked commands to follow standard Unix convention and match Claude Code's expected hook behavior.

5. **Consider making rules configurable**: A YAML or JSON config file would let users add/remove patterns without editing source code.

---

### 🟢 Confidence: `Medium`

The PR delivers working functionality for 4 of 5 required patterns. The missing DELETE FROM rule is a blocker for bounty acceptance. The rm regex limitation and unnecessary settings injection are quality issues that reduce robustness.
