# CLAUDE.md — Next.js 15 + SQLite SaaS

## Stack & Exact Versions

- **Next.js 15** App Router (no Pages Router — never)
- **React 19** with Server Components as default
- **SQLite** via `better-sqlite3` for synchronous local DB; use **Turso** (libsql) in production
- **TypeScript 5.x** — strict mode, no `any`
- **Tailwind CSS 4** — utility-first, no CSS modules
- **Drizzle ORM** — type-safe SQL, never Prisma (too heavy for SQLite)
- **Zod** — runtime validation at every boundary (form, API route, env)
- **next-auth v5** — authentication only, never roll your own
- **Node 20+**

## Folder Structure

```
src/
  app/                  # App Router only — no pages/
    (auth)/             # Route group: login, register (no layout chrome)
    (dashboard)/        # Route group: authenticated pages
      layout.tsx        # Auth guard here, not in middleware
    api/                # API routes ONLY for external webhooks/crons
  components/
    ui/                 # Dumb, stateless primitives (Button, Input, Card)
    features/           # Smart components tied to a domain (UserMenu, BillingCard)
  lib/
    db/
      schema.ts         # Drizzle schema — single source of truth
      migrations/       # Auto-generated by `drizzle-kit generate`
      index.ts          # Singleton db connection
    auth.ts             # next-auth config — options only, no logic
    validations/        # Zod schemas, colocated by domain
  hooks/                # Client-side hooks only (use client)
  types/                # Shared TypeScript types — no `interface`, use `type`
```

**Rules:**
- Server Components fetch their own data — no prop drilling from layout to page
- `"use client"` only on leaf nodes that need interactivity (forms, dropdowns)
- No `src/utils/` — logic goes in `lib/` (domain) or colocated with its component

## Database & Migrations (Drizzle + SQLite)

```ts
// lib/db/schema.ts
import { sqliteTable, text, integer } from "drizzle-orm/sqlite-core";

export const users = sqliteTable("users", {
  id: text("id").primaryKey().$defaultFn(() => crypto.randomUUID()),
  email: text("email").notNull().unique(),
  createdAt: integer("created_at", { mode: "timestamp" })
    .$defaultFn(() => new Date()),
});
```

**Migration rules:**
- Never edit generated migration files manually
- Every schema change = `pnpm db:generate` then `pnpm db:migrate`
- Migrations run at startup in `lib/db/index.ts`, never in middleware
- No nullable columns unless the business case demands it — prefer empty string over null for text
- Foreign keys always explicit with `references(() => table.id, { onDelete: "cascade" })`

**Dev commands:**
```bash
pnpm db:generate   # drizzle-kit generate
pnpm db:migrate    # drizzle-kit migrate
pnpm db:studio     # drizzle-kit studio (visual editor)
pnpm db:seed       # ts-node lib/db/seed.ts
```

## Component Patterns

**Server Component (default):**
```tsx
// app/(dashboard)/settings/page.tsx
import { db } from "@/lib/db";
import { getCurrentUser } from "@/lib/auth";

export default async function SettingsPage() {
  const user = await getCurrentUser();      // throws → redirect to /login
  const profile = await db.query.users.findFirst({
    where: (u, { eq }) => eq(u.id, user.id),
  });
  return <SettingsForm profile={profile} />;
}
```

**Client Component (only when needed):**
```tsx
"use client";
// components/features/SettingsForm.tsx
import { useTransition } from "react";
import { updateProfileAction } from "@/app/(dashboard)/settings/actions";

export function SettingsForm({ profile }: { profile: User }) {
  const [isPending, startTransition] = useTransition();
  // ...
}
```

**Server Actions (mutations only — never GET data):**
```ts
// app/(dashboard)/settings/actions.ts
"use server";
import { revalidatePath } from "next/cache";
import { profileSchema } from "@/lib/validations/user";

export async function updateProfileAction(formData: FormData) {
  const parsed = profileSchema.safeParse(Object.fromEntries(formData));
  if (!parsed.success) return { error: parsed.error.flatten() };
  // mutate db...
  revalidatePath("/settings");
}
```

## API Routes

Only use `app/api/` for:
1. External webhooks (Stripe, GitHub)
2. Cron jobs (Vercel cron)
3. OAuth callbacks (handled by next-auth — don't touch)

**Never** create API routes for internal data fetching — use Server Components instead.

```ts
// app/api/webhooks/stripe/route.ts
import { NextRequest } from "next/server";

export async function POST(req: NextRequest) {
  const sig = req.headers.get("stripe-signature")!;
  // verify + handle
  return Response.json({ received: true });
}
```

## Environment Variables

```bash
# .env.local
DATABASE_URL="file:./local.db"
NEXTAUTH_SECRET="generate-with-openssl-rand-base64-32"
NEXTAUTH_URL="http://localhost:3000"

# Production (Turso)
TURSO_DATABASE_URL="libsql://..."
TURSO_AUTH_TOKEN="..."
```

Validate at startup with Zod:
```ts
// lib/env.ts
import { z } from "zod";
const envSchema = z.object({
  DATABASE_URL: z.string().min(1),
  NEXTAUTH_SECRET: z.string().min(32),
});
export const env = envSchema.parse(process.env);
```

Import `@/lib/env` before any DB/auth code — crashes fast on misconfiguration.

## What We Don't Do (and Why)

| Anti-pattern | Why |
|---|---|
| `pages/` directory | App Router is the default since Next.js 13 — no reason to use Pages |
| `getServerSideProps` | Replaced by async Server Components |
| `axios` | Fetch API + `@/lib/fetcher.ts` wrapper is enough |
| `useState` for server data | Use Server Components + revalidatePath |
| Prisma | Adds 40MB bundle, slow cold starts — Drizzle is typed SQL |
| `try/catch` everywhere | Let errors bubble to error.tsx boundaries |
| `// TODO` comments | Either fix it now or open an issue |
| `console.log` in production | Use `pino` logger with log level via env |
| `any` type | Always specify — if unknown, use `unknown` and narrow |
| God components >200 LOC | Split at 200 lines, no exceptions |

## Error Handling

- **Server Components:** throw → caught by nearest `error.tsx`
- **Server Actions:** return `{ error: string }` — never throw
- **API Routes:** return `Response.json({ error }, { status: 4xx })`
- **Client:** display inline errors from action return value, never `alert()`
