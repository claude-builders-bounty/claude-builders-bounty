# Claude Code PR Review Agent

A Claude Code sub-agent that reviews pull requests and produces structured Markdown reviews.

**Bounty:** $150 — [claude-builders-bounty#4](https://github.com/claude-builders-bounty/claude-builders-bounty/issues/4)

## Features

- **CLI mode** — Review any public GitHub PR by URL
- **GitHub Action** — Auto-review on every PR
- **Structured output** — Summary, risks, suggestions, confidence score
- **10-point checklist** — Correctness, security, performance, testing, and more

## Quick Start

### 1. Claude Code usage (CLI)

```bash
# Via AGENT.md — let Claude Code review any PR
claude --agent AGENT.md -p "Review https://github.com/owner/repo/pull/123"

# Or use the helper script to fetch a diff first
./claude-review.sh --pr https://github.com/owner/repo/pull/123
```

### 2. GitHub Action

Add `CLAUDE_API_KEY` to your repository secrets, then copy `.github/workflows/pr-review.yml` into your repo.

The action triggers on every PR and posts a review comment automatically.

## Output Format

```markdown
## PR Review

### Summary
This PR adds user authentication with JWT tokens, including login/register
endpoints and middleware for protected routes.

### Files Changed
| File | Lines | Type |
|------|-------|------|
| src/auth/login.ts | +45/-0 | new |
| src/auth/middleware.ts | +30/-0 | new |
| src/routes.ts | +8/-2 | modification |

### Identified Risks
- **Risk**: JWT secret is hardcoded as a string literal
  **Severity**: HIGH
  **File**: `src/auth/login.ts:12`
  **Suggestion**: Move to an environment variable via `process.env.JWT_SECRET`

### Improvement Suggestions
- **Suggestion**: Add rate limiting to login endpoint
  **File**: `src/auth/login.ts`
  **Why**: Prevents brute-force attacks
  **How**: Wrap the handler with `express-rate-limit`

### Strengths
- Clean separation of auth logic into dedicated module
- Proper HTTP status codes used throughout

### Confidence Score
**Confidence: High**
The logic is straightforward and well-structured. No concurrency or
data integrity concerns.
```

## Review Checklist

The agent evaluates each change against 10 criteria:

1. **Correctness** — Edge cases, null handling, logic
2. **Security** — Injection, auth, input validation
3. **Performance** — Loops, queries, memory
4. **Error handling** — Catch blocks, error messages
5. **Type safety** — TypeScript types, generics
6. **Testing** — Coverage, edge cases
7. **Naming** — Intent-revealing names
8. **Documentation** — Public API docs
9. **Breaking changes** — Migration paths
10. **Dependencies** — Justification, versions
