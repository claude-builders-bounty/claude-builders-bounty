## PR Review — sindresorhus/slugify#57

## Summary
Adds a new `preserveTrailingDash` option (default `false`) that keeps a trailing
`-` in the slugified output when enabled. It declares the option with JSDoc in
`index.d.ts`, wires the default and the append logic in `index.js`
(`shouldAppendDash` → append `-` after processing), and adds a type-level assertion
in `index.test-d.ts`.

## Risks
- No runtime unit test is added — only a `test-d.ts` type assertion. The actual behavior (dash preserved only when the input ends with `-` and the option is on) is unverified by the test suite.
- The dash is appended as a literal `-`, ignoring a custom `separator`. With `{separator: '_'}` the output could end in `-`, which is inconsistent with the chosen separator.
- `shouldAppendDash` is computed from the original input's trailing `-`; if the string becomes empty after slugifying, the result may be a lone `-`.

## Suggestions
- Add unit tests in the main test file: option on with a trailing dash, option on without one, option off, and interaction with a custom `separator`.
- Document `preserveTrailingDash` in `readme.md`'s options list so it is discoverable alongside the existing options.
- Consider honoring `options.separator` for the appended character instead of a hard-coded `-`.
