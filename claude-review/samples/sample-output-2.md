- **Regex bypass surface**: `blocked_reason` only catches specific literal spellings (`-rf`/`-fr` combined flags, `--force`/`-f` for git push, etc.). Equivalent-but-differently-formed commands bypass it entirely, e.g. `rm -r -f /`, `rm --recursive --force`, `rm -Rf`, wrapping the destructive command in a subshell/alias/variable, or invoking a script file (`bash script.sh`) whose *contents* contain the destructive command — the hook never sees that text.
- **Fail-open on malformed input**: `main()` swallows any JSON-parsing exception (`except Exception: return 0`) and silently allows the tool call to proceed. Any unexpected/malformed stdin payload results in the command running instead of being safely blocked.
- **False sense of security**: The README and self-test present this as blocking "destructive Bash commands" generally, but it is a narrow denylist of five patterns; nothing prevents other equally destructive actions (e.g. `mkfs`, `dd if=/dev/zero of=/dev/sda`, `chmod -R 777 /`, curl-pipe-to-shell, credential exfiltration) from proceeding.
- **Self-test coverage is shallow**: `self_test()` only exercises the exact example strings already used to design the regexes, so it can't catch the bypass variants above — passing self-test gives false confidence.
- **Log file growth/permissions**: `blocked.log` is appended to indefinitely with no rotation, and commands (which may contain sensitive data/paths) are logged in plaintext under `~/.claude/hooks/` without any stated file permission hardening.

## Improvement Suggestions
- Drop the `familyguard-pages.yml` workflow and `familyguard/index.html` from this PR entirely — split them into their own PR (or remove if accidental) and strip the hardcoded personal email if the app is ever proposed for merge.
- Broaden pattern matching to cover flag-order/spacing variants (`-r -f`, `--recursive --force`), or better, parse arguments with `shlex.split` and check the resulting flag set rather than relying purely on regexes over the raw string.
- Change the "malformed JSON" and other unexpected-exception paths to a documented explicit "no decision" behavior, or at minimum log that the hook failed to parse input, so silent fail-open isn't invisible to the user.
- Clarify in the README that this is a best-effort heuristic denylist, not a complete destructive-command sandbox, and list known bypass classes (script files, aliases, encoded commands) as out of scope.
- Add rotation/size limits (or at least a note) for `blocked.log`, and consider restricting its file permissions since it stores raw command text.
- Expand `self_test()` with adversarial cases (`rm -r -f`, `git push --force-with-lease=refs/heads/main`, multi-statement commands) to catch regressions and document current known gaps.
