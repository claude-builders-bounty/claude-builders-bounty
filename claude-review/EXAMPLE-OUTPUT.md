### 📋 Change Summary

This PR fixes a crash in the Express JSON body parser when an empty request body is sent with `Content-Type: application/json`. It adds a length check before attempting `JSON.parse()`, returning an empty object `{}` instead of throwing a `SyntaxError`. The fix is minimal — 3 lines changed in `lib/middleware/express.json.js` — and includes a new test case for the empty body scenario.

### ⚠️ Identified Risks

- **Silent data loss**: Empty body now returns `{}` without any warning. Callers expecting a validation error for missing required fields might silently proceed with default values. Consider logging a debug message or adding a `strict` option.
- **Backward compatibility**: Existing code that catches the `SyntaxError` for empty bodies will no longer trigger. This is a behavioral change — worth noting in release notes.
- **Edge case: whitespace-only body**: The fix checks `buf.length === 0` but a body containing only whitespace (e.g., `"   "`) would still pass to `JSON.parse()` and fail. Consider trimming before the check.

### 💡 Improvement Suggestions

- Add a test for whitespace-only body (`"   "`) to ensure consistent behavior
- Consider exposing a `strict: true` option that rejects empty bodies (matching RFC 7231 which technically requires a body for POST/PUT)
- The new test could assert on the response status code in addition to the body content for better coverage
- Document the behavior change in the middleware's JSDoc comment
