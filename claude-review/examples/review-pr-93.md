### 📝 Summary

This PR implements a CHANGELOG generator skill that parses git history and produces a structured `CHANGELOG.md` following the Keep a Changelog format. It uses `git log` with custom formatting to group commits by type (feat, fix, docs, etc.) and organizes them under semantic versioning headers.

### ⚠️ Identified Risks

- 🔴 The script shells out to `git log` without sanitizing the output — commit messages containing backticks or shell metacharacters could cause formatting issues or injection in the generated Markdown.
- 🔴 No handling for repositories with no tags — the version detection falls back to "Unreleased" but doesn't communicate this clearly to the user.

### 💡 Improvement Suggestions

- Escape special Markdown characters in commit messages before inserting them into the CHANGELOG template
- Add a `--since` flag to limit the changelog to a specific date range or tag
- Include a `--dry-run` mode that previews the output without writing to disk
- Support conventional commits parser (e.g., `feat(scope):`) for more granular categorization

### 📊 Confidence Score

**🟡 Medium**

_The core logic is sound, but edge cases around shell escaping and repos without tags could cause issues in production. The PR would benefit from a few targeted tests._
