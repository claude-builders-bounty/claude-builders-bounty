# 网络暴露面复核结论（针对 Security_Audit_Report 的 F-01 / F-02）

**复核时间**：2026-11-10（报告生成后同一日）
**复核对象**：`Security_Audit_Report_20261110_170027.md` 第 4 节 F-01、F-02 两条 High
**复核方法**：原始证据包回读 + 本机实测 + 外部节点探测

---

## 一、结论

**这几个 0.0.0.0 端口没有暴露到公网。它们是内网暴露，不是公网暴露。**

原报告把"0.0.0.0 全接口监听"直接定性为"面向所有网络接口暴露"并挂 High，这个定性在 NAT 家庭宽带环境下**不成立**，属于方法论上的过度判定。

---

## 二、证据链

### 1. 本机不持有任何公网地址
| 项目 | 实测值 | 来源 |
|------|--------|------|
| 物理网卡 IPv4 | `192.168.1.3/24`（私有地址） | Phase04_Network\ipconfig_all.txt |
| 默认网关 | `192.168.1.1` | 同上 / route_table.txt |
| 全局 IPv6 地址 | **无**（仅 fe80:: 链路本地） | 本机 `Get-NetIPAddress -AddressFamily IPv6` 实测为空 |
| 网卡列表 | 1 物理网卡（Realtek）+ VMware VMnet1/VMnet8 虚拟网卡 | ipconfig_all.txt |

主机自己既没有公网 IPv4 绑定，也没有分配到全局 IPv6。**IPv6 方向暴露面为零。**

### 2. 所有 0.0.0.0 / :: 监听端口清单（实测）
| 端口 | 进程 PID | 说明 |
|------|---------|------|
| 135 | 1408 | RPC 端点映射（svchost） |
| 445 | 4 | SMB（System） |
| 3389 | 1628 | RDP（TermService，fDenyTSConnections=0 即允许） |
| 139 | 4 | NetBIOS，绑定在 192.168.1.3 / .119.1 / .157.1 三个具体地址 |
| 5357 | 4 | Web 服务发现（WSD） |
| 902 / 912 | 5592 | VMware 授权服务 |
| 5040 | 9948 | Windows 连接设备平台 |
| 9128 | 16216 | 第三方常驻服务 |
| 49664–49669 | 各 svchost | RPC 动态端口 |
| 63791 | 776 | 第三方（SSDP/UPnP 相关） |

`0.0.0.0` 的语义是"绑定本机所有网卡"，涵盖内网网卡、两块 VMware 虚拟网卡和回环。它只说明本机不挑客户端，**不产生任何 NAT 穿透能力**。

### 3. 当前无任何一条外部入站连接
实测 `Get-NetTCPConnection -State Established`：全部为 `192.168.1.3 → 公网地址` 的**出站**连接（443/8880/6666/12101 等），本地端口均为高位临时端口。
**没有一条是外部地址 → 3389/445/135 的入站 Established。**

### 4. 公网侧实测：WAN 口未对这些端口做转发
| 探测 | 结果 |
|------|------|
| 公网出口 IP | `120.15.39.151`（中国 河北 衡水 联通） |
| 本机 → `120.15.39.151:3389` | CLOSED，code=10061（RST 主动拒绝） |
| 本机 → `:445` / `:135` / `:139` / `:5357` | 同样 CLOSED / 10061 |
| 对照组：本机 → `192.168.1.3:3389/445/135/139` | 全部 OPEN（证明探测方法本身有效，且服务确实在跑） |

WAN 口收到包后直接回 RST、不向内网任何主机转发，指向**路由器上没有到本机的端口映射**。

### 5. 外部节点探测（check-host.net）
| 端口 | 节点 | 结果 |
|------|------|------|
| 3389 | es2 / pl1 / sg1 / ua1 / us5 | 全部 Connection timed out |
| 445 | de2 / de4 / sg1 / si1 | 全部 Connection timed out |
| 135 | de4 / ir8 / it2 / tr1 | 全部 Connection timed out |
| 80（对照） | es2 / ir8 / se1 / us4 | 全部 Connection timed out |

**这一项的局限要写明**：连对照端口 80 也从境外全部超时，说明从境外到 `120.15.39.151` 整条链路本身不通（运营商入站过滤或路由问题），因此该组数据**不能单独证明端口未映射**，只能说明"没有观察到开放"。它不构成反证。

## 三、真实风险在哪里（这才是要处理的）

公网这一层暂时没问题，风险全部落在**局域网内**：

1. **同一网段内任何设备都能直连本机 3389 / 445 / 135 / 139**。
   这个网段里可能有：手机、智能电视/音箱、摄像头等 IoT、访客设备、蹭网者。任意一台被拿下，就能直接打这台主机。
2. **445（SMB）是横向移动的经典入口**，一旦有内网主机被控，445 是最快的跳板。
3. **RDP 开着（fDenyTSConnections=0）+ 本地 Administrator 已启用（F-04）**，两者叠加 = 内网内只要拿到口令就能登录。
4. Windows 防火墙三个配置文件均为 ON，但 `DefaultInboundAction=NotConfigured` 且规则无法核验（F-03），**不能确认这些端口的放行是被有意配置的**。

## 四、从"内网暴露"变成"公网暴露"的三个触发条件（需要防住）

| 触发条件 | 位置 | 后果 |
|---------|------|------|
| 路由器开了 **DMZ 主机** 指向 192.168.1.3 | 路由器后台 | 全部端口直通公网，最严重 |
| 路由器配了**虚拟服务器/端口映射**（3389 或 445 → 192.168.1.3） | 路由器后台 | 对应端口公网可达 |
| 路由器 **UPnP 开启** 且某程序自行申请映射 | 路由器后台 | 随时可能被第三方程序开出端口，且用户不知情 |

华为设备的 UPnP 服务在 `192.168.1.34:37443` 上响应了 SSDP（声明自己是 InternetGatewayDevice），但描述文件返回 403，**无法从本机读到映射表**。这一项必须由用户登录路由器后台人工确认。

## 五、对原报告的修正建议

| 发现 ID | 原等级 | 原定性 | 建议改为 |
|---------|--------|--------|---------|
| F-01（RDP 3389 全接口监听） | High | "面向所有网络接口暴露" | **Medium**，定性改为"内网暴露 + RDP 处于可登录状态（Administrator 已启用）"；补注"公网可达性实测为不可达，且无端口映射迹象" |
| F-02（SMB/RPC/NetBIOS 全接口监听） | High | 同上 | **Medium**，定性改为"内网暴露面过大"；公网侧同样实测不可达 |

**修复动作不变**，仍按 P0/P1 执行：关掉不需要的 RDP、限制 SMB/NetBIOS、以管理员身份复核防火墙入站规则。改的只是定级口径和"是否已暴露到公网"这个事实判断。

## 六、待用户人工确认项（本机无法代做）

登录路由器 `192.168.1.1` 后台，确认三件事：

- [ ] 端口映射 / 虚拟服务器列表为**空**
- [ ] DMZ 主机为**关闭**
- [ ] UPnP 为**关闭**（或确认 UPnP 映射表中没有指向 192.168.1.3 的条目）

三项都确认后，可判定为"仅内网暴露，公网无暴露面"。

---

## 七、方法与局限声明

1. 全部探测为只读，未修改本机任何配置、未对路由器做任何写入。
2. 外部节点探测受"境外到国内 IP 链路不通"干扰，仅作辅助，不作定论依据。
3. 未登录路由器后台，端口映射/DMZ/UPnP 的实际配置**未直接读取**，结论基于"WAN 口 RST 拒绝 + 无入站连接 + 无公网地址"的间接推断，置信度高但非直接读取配置。
4. 公网 IP 为动态地址，IP 变化后本次公网侧探测结论需重做。
