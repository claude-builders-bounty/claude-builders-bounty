# claude-review-agent

CLI sub-agent that reviews a GitHub PR and posts a structured comment. Python stdlib only, no dependencies. Works on **Windows (PowerShell), Linux, and macOS**.

```bash
python claude_review.py --pr https://github.com/owner/repo/pull/123
```

Output is structured Markdown with the four required sections — **Summary** (2–3 sentences), **Risks** (list), **Suggestions** (list), **Confidence** (Low/Medium/High) — ready to paste as a PR comment, or posted directly with `--post`.

## How it works (no API keys)

1. **Fetch** — uses the `gh` CLI when available, otherwise the **public GitHub REST API** (`urllib`, unauthenticated: 60 req/hour is plenty at ~2 calls per PR). `GITHUB_TOKEN`/`GH_TOKEN` is picked up automatically if set (5000/hour) but **never required for public PRs**. Rate limits produce a clear retry message instead of a traceback.
2. **Analyze** — deterministic heuristics over every added diff line (risky shell/SQL patterns, secrets, insecure crypto, structural signals like size / missing tests / workflow changes). No Anthropic/OpenAI key needed.
3. **Render** — Markdown comment (default) or JSON (`--format json`) for automation.

## Install

No dependencies — just Python 3.8+:

```bash
git clone <this-repo> && cd claude-review-agent
# Optional: make `claude-review` directly runnable
chmod +x claude-review            # Linux / macOS
# Windows: use claude-review.bat, or call python claude_review.py
pip install -r requirements-dev.txt   # pytest, only needed to run tests
```

## Usage

```bash
# Review a PR (prints Markdown to stdout)
python claude_review.py --pr https://github.com/owner/repo/pull/123

# Shorthand form also works
python claude_review.py --pr owner/repo#123

# Save to a file
python claude_review.py --pr https://github.com/owner/repo/pull/123 --output review.md

# Post directly as a PR comment (requires `gh` + `gh auth login`; off by default)
python claude_review.py --pr https://github.com/owner/repo/pull/123 --post

# Machine-readable output for scripts / Actions
python claude_review.py --pr https://github.com/owner/repo/pull/123 --format json

# Review a local diff offline (no network at all)
python claude_review.py --diff-file changes.patch --output review.md

# Force the public-API path even when `gh` is installed (proves no-key operation)
python claude_review.py --pr https://github.com/owner/repo/pull/123 --no-gh
```

Exit codes: `0` ok · `2` usage/fetch error · `3` rate-limited (retry later or set `GITHUB_TOKEN`).

## GitHub Action

`workflow.example.yml` is a drop-in workflow: copy it to `.github/workflows/claude-review.yml` in the repo you want reviewed. It runs the reviewer on every opened/synchronized PR and posts the comment — no secrets needed for public repos (uses the automatic `GITHUB_TOKEN`).

```bash
cp workflow.example.yml /path/to/your/repo/.github/workflows/claude-review.yml
# then edit YOUR-ORG/claude-review-agent in the checkout step
```

## Heuristic rules

| Added-line pattern | Severity | Notes |
|---|---|---|
| Recursive `rm` (`rm -r`/`-R`/`--recursive`, incl. `sudo`, `/bin/rm`) | HIGH | `grep -r` and plain `rm file` do not match |
| `DROP TABLE`, `TRUNCATE` (any case) | HIGH | |
| `DELETE FROM` without `WHERE` on the same statement | HIGH | `... WHERE ...` on the same line is allowed |
| `curl`/`wget … \| sh` | HIGH | Piped remote code execution |
| Hardcoded secret (`AKIA…`, `ghp_…`/`gho_…`, `xox…`, private keys, `password = "…"`) | HIGH | Tokens are `[REDACTED]` in output, never echoed |
| `git push --force` / `-f` / `+refspec` | MEDIUM | `--force-with-lease` / `--force-if-includes` allowed |
| `eval(` / `exec(` / `os.system` / `shell=True` / `innerHTML` / `child_process` | MEDIUM | |
| String-built SQL (`f"SELECT …{x}"`, `"SELECT " + request…`) | MEDIUM | |
| `verify=False`, `ssl._create_unverified_context`, `hashlib.md5/sha1`, `MODE_ECB`, `chmod 777`, `0.0.0.0` | MEDIUM | |
| `pip install https://…`, `npm install git+https://…` | MEDIUM | Unpinned remote installs |
| Mentions inside docs (`*.md`/`*.rst`/…​) | capped at MEDIUM | Labelled “likely illustrative” |

Structural suggestions (not line findings): large diff >500 lines → suggest splitting; >20 files → scope check; source changed without tests → add regression tests; `.github/workflows` touched → permissions/trigger check; lockfile changed → confirm intent; migrations touched → reversibility check.

## Confidence rubric

Confidence describes the **review's completeness**, not the code's safety:

| Level | When |
|---|---|
| **High** | Focused diff, full patch analyzed (e.g. small or docs-only PR) |
| **Medium** | Moderate scope (>300 changed lines or >10 files) |
| **Low** | Large scope (>1000 lines or >20 files), or part of the diff unavailable (binary/oversize files — listed under “Review limitations”) |

## Optional: Claude API integration

Not required. The heuristic review is the default and needs no key. To add LLM polish, pipe the output into Claude Code:

```bash
python claude_review.py --pr <url> --output review.md
claude -p "Tighten this code review, keep the Summary/Risks/Suggestions/Confidence headings:" < review.md
```

(A CI variant is included commented-out in `workflow.example.yml`; it needs an `ANTHROPIC_API_KEY` secret.)

## Known limitations

Heuristic plaintext scan, not a semantic review: it matches added diff lines as written and can flag test fixtures / string literals that merely *mention* dangerous commands (conservative by design — see the `pr-4158-review.md` sample, where findings cluster in the guard's own test data). It does not decode obfuscation, follow multi-line SQL statements across lines, or judge correctness, performance, or design. Every review footer states the fetch path and these limits; a human reviewer still decides.
