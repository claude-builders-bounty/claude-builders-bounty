## Summary

This PR modifies the CI configuration to extend the `ci-component-fixtures` workflow to run on `release/*` branches in addition to the main branch. The change adds `release/*` to the push trigger conditions, ensuring that component fixture tests are executed during the release candidate validation phase. This helps catch fixture-related regressions before publishing stable releases.

## Identified Risks

- **Increased CI compute**: Running fixture tests on all release branches may significantly increase CI runtime and compute costs, especially during active release cycles with multiple RCs
- **Unversioned release branches**: Any branch matching `release/*` pattern will trigger tests, including work-in-progress release branches that may not be fully stable
- **No version gating**: The change lacks filters to distinguish between stable release branches (e.g., `release/1.90`) and feature branches accidentally named with the prefix
