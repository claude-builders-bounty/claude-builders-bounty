## Summary
This PR adds a new authentication middleware to handle JWT token validation for all API routes. The implementation includes token parsing, signature verification, and user context injection into the request object.

## Risks
- **Security**: JWT secret is loaded from environment variable without validation - could cause silent failures if unset
- **Breaking Change**: Middleware runs on all routes by default, may affect existing endpoints that don't expect authentication
- **Performance**: Synchronous token verification on every request could add latency for high-throughput endpoints
- **Error Handling**: Invalid tokens return 401 but log level is set to `debug` - may hide authentication issues in production

## Suggestions
1. Add validation for `JWT_SECRET` at startup - fail fast if not set rather than silently using empty string
2. Add an option to exclude certain routes from authentication middleware (e.g., `/health`, `/public`)
3. Consider making token verification async and cache valid tokens to reduce latency
4. Upgrade log level for authentication failures to `warn` or `error` for better observability
5. Add unit tests specifically for the token verification logic and edge cases (expired tokens, malformed tokens)
