# claude-review

A **Claude Code sub-agent** that takes a GitHub PR diff as input, analyzes it, and returns a
**structured Markdown review comment** — via CLI or as a GitHub Action.

Built for [issue #4](https://github.com/claude-builders-bounty/claude-builders-bounty/issues/4)
on the claude-builders-bounty board: *“[BOUNTY $150] AGENT: Claude Code sub-agent that reviews a PR and posts a structured comment.”*

## How it works

```
┌─────────────┐   GitHub REST API    ┌────────────────────────────┐
│ PR reference │ ──────────────────▶ │ PR metadata + changed files │
└─────────────┘                      └─────────────┬──────────────┘
                                                   │ unified diff (truncated)
                                                   ▼
                                        ┌────────────────────────┐
                                        │        Analyzer        │
                                        │ 1. Claude Code engine  │  ← `claude -p --output-format text`
                                        │    (headless sub-agent)│     (auto-detected on PATH)
                                        │ 2. Heuristic engine    │  ← built-in deterministic
                                        │    (fallback, no model)│     diff analyzer (zero deps)
                                        └─────────────┬──────────┘
                                                   │ structured Markdown
                                                   ▼
                              stdout   or   POST /issues/{n}/comments (--comment)
```

- **Engine `auto` (default):** uses the Claude Code CLI when it is installed on `PATH`,
  otherwise falls back to the built-in heuristic analyzer. The engine actually used is
  reported on stderr.
- **Claude Code engine:** the analysis prompt is handed to `claude -p --output-format text`
  (headless mode, prompt via stdin, no TTY). The model is instructed to emit only the fixed
  review structure; output is validated against that structure before it is printed or posted.
- **Heuristic engine:** a deterministic, dependency-free analyzer that extracts change stats,
  scans added lines for common risk patterns (secrets, `eval`, security-sensitive APIs),
  detects missing tests, lockfile-only changes, docs-only changes, large PRs, and missing
  PR descriptions. Confidence is capped at **Medium** in this engine.
- **Posting:** `--comment` posts the review as a comment on the PR via
  `POST /repos/{owner}/{repo}/issues/{n}/comments`. Requires `GITHUB_TOKEN` with write access.

## Requirements

- **Node.js 18+** (built-in `fetch` is used; tested on Node 24). **Zero npm dependencies.**
- Optional: [Claude Code CLI](https://docs.anthropic.com/en/docs/claude-code) on `PATH`
  plus `ANTHROPIC_API_KEY` (or an existing Claude Code login) for the LLM engine.
- Optional: a GitHub token for reading private repos or posting comments.

## Install

No dependencies to install. Use it directly:

```sh
# from the repo root (any OS)
node bin/claude-review.mjs --pr https://github.com/owner/repo/pull/123

# or use the provided wrappers
./claude-review --pr https://github.com/owner/repo/pull/123        # POSIX
claude-review.cmd --pr https://github.com/owner/repo/pull/123      # Windows
```

Or put it on your `PATH`:

```sh
npm link            # creates the `claude-review` command (no deps downloaded)
```

## Usage

```sh
claude-review --pr https://github.com/owner/repo/pull/123
claude-review --repo owner/repo --number 123
claude-review --pr https://github.com/owner/repo/pull/123 --comment   # also post it
claude-review --diff-file ./changes.diff                              # offline, no API
```

| Flag | Default | Description |
| --- | --- | --- |
| `--pr <url>` | — | GitHub pull request URL |
| `--repo owner/repo --number N` | — | Alternative to `--pr` |
| `--comment` | off | Post the review as a comment on the PR (needs `GITHUB_TOKEN`) |
| `--engine auto\|claude\|heuristic` | `auto` | Which analyzer to use |
| `--diff-file <path>` | — | Analyze a local unified diff file instead of calling the API |
| `--max-diff-chars N` | `60000` | Truncate the diff sent to the model |
| `--max-files N` | `300` | Max changed files fetched |
| `--timeout ms` | `30000` | GitHub API request timeout |
| `--help` | — | Usage |

**Environment variables**

| Variable | Purpose |
| --- | --- |
| `GITHUB_TOKEN` | Read private repos; required for `--comment` (needs `pull-requests` write) |
| `ANTHROPIC_API_KEY` | For the Claude Code engine (or an existing `claude` login) |
| `GITHUB_BASE_URL` | Point at a GitHub Enterprise instance, e.g. `https://ghe.example.com/api/v3` |

### Output format (fixed contract)

```markdown
## 🤖 PR Review — owner/repo#123

> Generated by claude-review · engine: heuristic · 2026-10-26T12:56:25.810Z

### Summary
Two to three sentences.

### Risks
- Bullet list of identified risks (or “- None identified.”)

### Suggestions
- Bullet list of improvement suggestions

**Confidence:** Low | Medium | High
```

## GitHub Action

A ready-to-use workflow is included at
[.github/workflows/pr-review.yml](.github/workflows/pr-review.yml). To activate it in your
own repo:

1. Copy the project into the repo root (`bin/`, `package.json`, this `README.md`) **and**
   copy the workflow to `.github/workflows/pr-review.yml` — or vendor this repo as a
   submodule checked out under `bin/`. A guard step in the workflow fails the run with a
   clear error if `bin/claude-review.mjs` is missing.
2. Nothing else is required: it reviews every opened/reopened/synchronized PR using the
   auto-provided `GITHUB_TOKEN` (which carries `pull-requests: write` on the repo it runs
   in) and posts one structured comment per event.

> If `ANTHROPIC_API_KEY` is not set (or the `claude` CLI install fails), the Action still
> posts a review — generated by the built-in heuristic engine and labeled as such.

## Testing

### Offline suite (no network, zero deps)

```sh
npm test        # or: node test/run-tests.mjs
```

Covers URL parsing, fixture-diff analysis, the required output sections, confidence
validation, summary length, and error handling (bad URL, no args, `--comment` without a
token, `--diff-file` + `--comment`). Verified on Node 24.18.0 — **14/14 passing**.

### Tested on 2 real GitHub PRs (outputs included)

Run with the heuristic engine (Claude Code CLI was not installed in the dev environment —
see Assumptions):

```sh
node bin/claude-review.mjs --pr https://github.com/expressjs/express/pull/7544
node bin/claude-review.mjs --pr https://github.com/prettier/prettier/pull/20348
```

Captured outputs:

- [examples/pr-expressjs-express-7544.md](examples/pr-expressjs-express-7544.md)
  — a docs-only typo fix: no risks, docs-consistency suggestion, confidence **Medium**.
- [examples/pr-prettier-prettier-20348.md](examples/pr-prettier-prettier-20348.md)
  — a 1-line CSS-print refactor: flags “no test files changed although source code
  changed”, suggests adding a test, confidence **Medium**.

### Comment posting

Posting is implemented via the GitHub API and is exercised up to the API boundary:
without `GITHUB_TOKEN` the CLI fails fast with a clear error (covered by the test suite);
with a token it calls `POST /repos/{owner}/{repo}/issues/{n}/comments` and prints the
comment URL. We deliberately did **not** post to the two demo PRs above (posting to
third-party public repos would be spam); in your own repo the Action path above posts
automatically on every PR event.

## Assumptions & deviations

1. **Engine in this dev environment:** the `claude` CLI is not installed on the build
   machine, so the captured live examples were generated by the heuristic engine (clearly
   labeled in each output). The Claude Code engine is the primary path in normal
   deployment: it auto-detects `claude` on `PATH`, prompts it headlessly, validates the
   structure, and only falls back if the engine is missing or its output is malformed.
   The CI workflow installs Claude Code explicitly so the LLM path is what runs there.
2. **“Posts a structured comment”** is satisfied by `--comment` (issue comment on the PR).
   The formal *review* endpoint (`POST /pulls/{n}/reviews`) was intentionally not used:
   comments are simpler to grant and match the issue title’s “structured comment” wording.
3. **Public repos need no token**; private repos require `GITHUB_TOKEN`. Unauthenticated
   reads are subject to GitHub’s 60 req/hour limit — the CLI surfaces rate-limit errors
   clearly and keeps each review to ~2 API calls.
4. **Large PRs:** the diff sent to the model is truncated at 60k chars by default
   (`--max-diff-chars`); truncation lowers the heuristic confidence score and is noted
   in the analysis prompt.
5. Heuristic-engine confidence is capped at **Medium** — the deterministic analyzer cannot
   be as sure as a full model review; the Claude engine reports Low/Medium/High from the
   model itself (validated against that exact set).
