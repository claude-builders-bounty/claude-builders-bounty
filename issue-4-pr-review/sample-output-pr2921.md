### Summary
This PR implements a pre-tool-use hook for Claude Code that intercepts and blocks destructive bash commands such as `rm -rf`, `DROP TABLE`, and `git push --force`. It includes the main hook script, an auto-installer, a comprehensive test suite with 24 test cases, and documentation.

### Risks
- The regex patterns use `re.IGNORECASE` which could cause false positives on unrelated commands containing keywords like "drop" or "truncate" in non-SQL contexts (e.g., `git stash drop`)
- `systemctl stop` blocking may be overly broad — stopping a dev service like `systemctl stop my-app` is common and safe in development
- The log file path `~/.claude/hooks/blocked.log` is hardcoded with no rotation, which could grow unbounded over time
- The hook reads all stdin at once (`sys.stdin.read()`) which could be problematic for very large inputs, though unlikely in practice

### Suggestions
- Consider adding `--force-with-lease` as a separate, softer check or allowlist since it's safer than `--force` and commonly used
- Add log rotation or a max file size check to prevent unbounded log growth
- The `install.py` script could validate that the existing `settings.json` is well-formed before overwriting it
- Consider adding a `--dry-run` or `BLOCK_DESTRUCTIVE_DRY_RUN` env var that logs but doesn't block, useful for testing before enforcement

### Confidence
High — the implementation is straightforward and well-tested with 24 test cases covering both blocked and allowed patterns.
