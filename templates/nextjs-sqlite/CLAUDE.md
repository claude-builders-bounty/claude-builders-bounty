# CLAUDE.md — Greenfield Next.js 15 + SQLite Project Guide

> Opinionated, battle-tested engineering standards for Claude Code when building with Next.js 15 App Router, React 19, TypeScript, and SQLite (via Drizzle ORM + better-sqlite3 / Turso).

---

## 🚀 Core Stack & Invariants

- **Framework**: Next.js 15 (`app/` directory App Router only — `pages/` directory is strictly forbidden).
- **Runtime**: React 19 (Async Server Components by default; `use client` strictly limited to interactive leaf nodes).
- **Language**: TypeScript 5.x (`strict: true`, no `any`, mandatory return type annotations on exports).
- **Database**: SQLite via Drizzle ORM (`drizzle-orm`) with `better-sqlite3` (local dev) or `@libsql/client` (Turso edge).
- **Styling**: Tailwind CSS v4 + `clsx` / `tailwind-merge`.
- **Validation**: Zod for all API input schemas and Server Action payloads.

---

## 📁 Directory Architecture

```
├── app/                  # Next.js App Router routes & layouts
│   ├── (auth)/           # Route group for auth (login, register)
│   ├── (dashboard)/      # Route group for authenticated UI
│   ├── api/              # Route handlers (REST/JSON endpoints)
│   ├── globals.css       # Tailwind CSS directives
│   └── layout.tsx        # Root layout
├── db/                   # Database schema, client, and migrations
│   ├── schema.ts         # Authoritative Drizzle table definitions
│   ├── index.ts          # Single-instance database client export
│   └── migrations/       # SQL migration files generated by Drizzle Kit
├── components/           # UI components
│   ├── ui/               # Reusable primitive UI components (buttons, inputs)
│   └── features/         # Domain-specific feature components
├── lib/                  # Business logic, server actions, and utilities
│   ├── actions/          # Next.js Server Actions ('use server')
│   ├── utils.ts          # Helper functions (cn, formatters)
│   └── validations/      # Zod schema definitions
├── public/               # Static assets
├── drizzle.config.ts     # Drizzle Kit configuration
└── package.json
```

## 🛠️ Essential Commands

- `npm run dev` — Start local development server (`http://localhost:3000`).
- `npm run build` — Typecheck and build production assets (`next build`).
- `npm run start` — Run production build locally.
- `npm run lint` — Execute ESLint quality gate.
- `npx drizzle-kit generate` — Generate SQL migrations from `db/schema.ts`.
- `npx drizzle-kit migrate` — Apply pending SQL migrations to local SQLite database.
- `npx drizzle-kit studio` — Launch interactive Drizzle Studio database viewer.
- `npm test` — Run test suite via Vitest / Jest.

## 🗄️ Database & Migration Conventions

1. **Schema Single Source of Truth**: All database schemas MUST be defined in `db/schema.ts` using Drizzle ORM syntax.
2. **Explicit Foreign Keys & Cascades**: Always specify explicit foreign key references (`references(() => table.id, { onDelete: 'cascade' })`).
3. **UTC Timestamps**: Use integer Unix timestamps (`mode: 'timestamp'`) or ISO text strings for all timestamp columns (`createdAt`, `updatedAt`).
4. **Migration Workflow**: Never modify `.db` files directly or run raw DDL scripts in production. Always generate a migration file (`npx drizzle-kit generate`) and run `npx drizzle-kit migrate`.
5. **WAL Mode**: Ensure SQLite connection executes `PRAGMA journal_mode = WAL;` and `PRAGMA busy_timeout = 5000;` on initialization for high concurrent throughput.

---

## 🧩 Component & React 19 Patterns

1. **Server Components by Default**: All components in `app/` and `components/` are React Server Components (RSC) unless marked with `'use client'`.
2. **Client Component Boundaries**: Push `'use client'` to the lowest possible leaf components (e.g. form inputs, modals, drop-downs). Do NOT mark entire page components as `'use client'`.
3. **Server Actions for Mutations**: Handle data mutations via Server Actions placed in `lib/actions/` with explicit `'use server'` directives.
4. **Zod Validation**: Always validate Server Action inputs using Zod schemas before querying or mutating the database:
   ```ts
   const validated = schema.parse(rawInput);
   ```
5. **Error Handling**: Use `try/catch` inside Server Actions and return structured response objects `{ success: boolean, error?: string, data?: T }`.

## 🚫 What We DON'T Do (And Why)

| Anti-Pattern | Why It Is Forbidden |
|---|---|
| ❌ **Pages Router (`pages/`)** | Next.js 15 App Router provides superior layout nesting, streaming SSR, and Server Components. |
| ❌ **`any` Types** | Undermines TypeScript safety contracts and causes runtime crashes. |
| ❌ **Client-Side DB Queries** | SQLite credentials and direct ORM imports must never leak into client JS bundles. |
| ❌ **Raw SQL Strings** | Vulnerable to SQL injection; use Drizzle ORM query builders for type safety. |
| ❌ **`'use client'` at Layout Level** | Destroys Server Component streaming and bloats client bundle sizes. |
| ❌ **Global Mutable State for DB** | Causes stale connection leaks in serverless environments; export a single memoized client instance in `db/index.ts`. |
