# CLAUDE.md — Next.js 15 App Router + SQLite SaaS Blueprint

This document defines architecture patterns, engineering conventions, and strict rules for this codebase. Claude Code must adhere to these directives without exception.

---

## 🛠️ Stack & Verified Versions

- **Framework**: Next.js 15 (App Router, Turbopack enabled)
- **Runtime**: Node.js 22 LTS / Bun
- **Language**: TypeScript 5.6+ (`strict: true`, zero `any`)
- **Database**: SQLite 3 via `better-sqlite3` (local development) / `@libsql/client` (Turso serverless edge)
- **ORM & Migrations**: Drizzle ORM + Drizzle Kit
- **Validation**: Zod 3.23+ (mandatory for all Server Actions and Route inputs)
- **Styling**: Tailwind CSS v4 + `shadcn/ui` (Radix Primitives)
- **Package Manager**: `pnpm` (strictly enforced)

## 🗄️ SQL & SQLite Database Conventions

### 1. Mandatory SQLite Pragmas (Applied on connection initialization)
```typescript
db.pragma('journal_mode = WAL');       // Write-Ahead Logging for high concurrency
db.pragma('synchronous = NORMAL');     // Optimal durability / throughput tradeoff
db.pragma('foreign_keys = ON');        // Enforce relational integrity
db.pragma('busy_timeout = 5000');      // Wait up to 5s on lock contention before busy error
```

### 2. Schema Design Rules
- **Primary Keys**: Always use `TEXT` with NanoID or ULID (`createId()`). Avoid autoincrementing integers for public-facing resource IDs to prevent enumeration attacks.
- **Timestamps**: Store all timestamps as integer Unix epoch seconds (`INTEGER`) or ISO-8601 UTC strings (`TEXT`). Never use local time offsets.
- **Foreign Keys**: Every foreign key must declare an explicit `ON DELETE CASCADE` or `ON DELETE RESTRICT` clause.
- **Prepared Statements**: Raw SQL queries must NEVER concatenate user variables. Always use Drizzle prepared statements or parameterized parameters: `sql` tagged template literals only.

### 3. Migrations Protocol
- Generate migrations with: `pnpm db:generate`.
- Apply migrations with: `pnpm db:migrate`.
- NEVER edit generated `.sql` migration files manually after commit. If schema alters, generate a sequential migration file.

## 🧩 Component & Rendering Patterns

- **Server Components by Default**: Every component in `app/` is a Server Component unless interactive event listeners (`onClick`, `onChange`, React hooks) are explicitly required.
- **Leaf-Only `'use client'`**: Push the `'use client'` boundary down to the smallest possible leaf component. Never mark entire page layouts as client components.
- **Data Fetching**: Fetch data directly in Server Components via standard `async/await` and Drizzle DB queries. Do NOT use `useEffect` or client-side SWR/React Query for initial page data.
- **Server Actions for Mutations**: All state modifications (`POST`, `UPDATE`, `DELETE`) must go through Server Actions located in `/actions/` with input Zod parsing and user session authentication checks.

## 🚫 What We Don't Do (And Why)

| Anti-Pattern | Why We Forbid It | Correct Pattern |
| :--- | :--- | :--- |
| **No Prisma ORM** | Prisma's binary query engine introduces heavy memory overhead (~150MB) and slow cold-starts in serverless edge environments. | Use **Drizzle ORM**; zero binary dependencies, direct SQL output, type-safe, sub-millisecond overhead. |
| **No Client-Side DB Calls** | Direct database imports in client bundles leak credentials and database connection details to the browser. | Always query via Server Components or Server Actions in `actions/`. |
| **No `useEffect` Data Fetching** | Causes network waterfalls, flashing loading states, and layout shift (CLS). | Fetch directly in React Server Components using `async/await`. |
| **No Untyped `any` in Actions** | Leads to silent runtime crashes on unexpected input payload structures. | Validate all parameters strictly using `zodSchema.parse(input)`. |
| **No Raw String SQL Concatenation** | Exposes the application to SQL Injection attacks. | Always use parameterized bindings: `db.prepare('... WHERE id = ?').get(id)`. |
| **No Client Secrets in Next Public Env** | Environment variables prefixed with `NEXT_PUBLIC_` are bundled into browser JavaScript. | Keep API keys, DB paths, and webhook secrets strictly in server env files (`.env.local`). |
