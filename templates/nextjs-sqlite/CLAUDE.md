# CLAUDE.md — Next.js 15 + SQLite SaaS

## Stack

| Layer | Choice | Why |
|-------|--------|-----|
| Framework | Next.js 15 App Router | RSC, server actions, stable |
| Database | SQLite via better-sqlite3 | Zero ops, fast local dev, good for single-tenant SaaS |
| ORM | Drizzle ORM | Type-safe, SQL-like syntax, no magic |
| Auth | NextAuth.js v5 (Auth.js) | Built for App Router, adapter pattern |
| UI | shadcn/ui + Tailwind CSS 4 | Accessible, composable, copiable |
| Validation | Zod | Schema sharing between client/server |
| Package Manager | pnpm | Strict, fast, disk-efficient |

## Conventions

### Server Actions
- One file per domain in `src/actions/`
- Actions are `async functions`, never call them from client components directly — pass to `<form action={}>`
- Always return `{ success: boolean; message?: string; data?: T }`
- Validate inputs with Zod before DB access

### Database
- Every table gets `id` (TEXT primary key, UUIDv7), `createdAt`, `updatedAt`
- Soft deletes via `deletedAt` column — never `DELETE FROM`
- Migrations are generated by `drizzle-kit push` / `drizzle-kit generate`
- Seed data goes in `db/seed.ts`, idempotent (upsert)

### Components
- Client components only when you need: `useState`, `useEffect`, `onClick`, browser APIs
- Default to Server Components. Move interactive parts to `'use client'` leaves.
- UI primitives from `shadcn/ui` — do not hand-roll buttons, inputs, dialogs
- Forms use `react-hook-form` + `zod` resolver

### Routes
- Public routes under `(auth)` group (no layout wrapper)
- Authenticated routes under `(dashboard)` group (has sidebar/header layout)
- API routes only for webhooks and external callers — internal logic uses Server Actions

### Environment Variables
- All validated at `src/env.ts` via Zod
- Never access `process.env.X` directly — import from `@/env`
- Prefix: `NEXT_PUBLIC_` only for values safe to ship to the browser

## Commands

```bash
pnpm dev          # Start dev server on :3000
pnpm build        # Production build (must pass locally before CI)
pnpm lint         # ESLint + Prettier
pnpm test         # Vitest (unit) + Playwright (e2e)
pnpm db:push      # Push schema changes to local DB
pnpm db:generate  # Generate migration file
pnpm db:seed      # Seed development data
pnpm db:studio    # Open Drizzle Studio
```

## What We Don't Do (and Why)

| Don't | Why |
|-------|-----|
| `DELETE FROM` in app code | Soft deletes prevent data loss and enable undo |
| `'use client'` on pages | Pages should be server components; wrap interactive parts in client components instead |
| Raw SQL strings | Drizzle gives typed queries — raw SQL bypasses type safety and is harder to refactor |
| `process.env` in components | Breaks in RSC, hard to mock in tests; use `env.ts` |
| Barrel exports (`index.ts` re-exports) | Causes circular deps and bloated bundles in Next.js |
| Default exports | Named exports are easier to refactor and tree-shake |
| CSS Modules | Tailwind + shadcn covers everything; mixing CSS modules adds cognitive overhead |

## Anti-Patterns to Flag in Reviews

- Server Action fetching data and passing it to a client component "because it's easier" — use the server component to render, or pass as props
- `useEffect` for data fetching — use Server Components or `use` in React 19
- Adding a dependency without `pnpm why` to check if we already have it
- Large client bundles — check for "use client" at the top of files that don't need interactivity
- Direct DB access from route handlers — use Server Actions for internal mutations
