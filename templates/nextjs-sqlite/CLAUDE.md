# CLAUDE.md — Next.js 15 App Router + SQLite SaaS Architecture

## Stack & Core Versions
- **Framework**: Next.js 15 (App Router, Server Actions, React Server Components)
- **Language**: TypeScript 5.6+ (Strict mode, no `any`)
- **Database**: SQLite via `better-sqlite3` (WAL mode, foreign keys enabled) or Turso (`@libsql/client`)
- **ORM / Query Builder**: Drizzle ORM (`drizzle-kit` for declarative migrations)
- **Validation**: Zod (all inputs validated at boundary: Server Actions & API routes)
- **Styling**: Tailwind CSS v4 + `shadcn/ui` (Radix UI primitives)
- **Authentication**: NextAuth.js v5 / Auth.js with Drizzle adapter

## SQLite & Database Conventions

### 1. Mandatory SQLite PRAGMAs
Every SQLite connection **must** execute these PRAGMAs immediately upon initialization (`db/index.ts`):
```typescript
db.pragma('journal_mode = WAL');         // High concurrency read/write
db.pragma('foreign_keys = ON');           // Enforce relational integrity
db.pragma('busy_timeout = 5000');         // Prevent locked DB panics under burst
db.pragma('synchronous = NORMAL');        // Safe durability in WAL mode
```

### 2. Migration Protocol
- Never hand-edit files in `db/migrations/`.
- Edit schema files in `db/schema/`.
- Generate migration: `npm run db:generate` (`drizzle-kit generate`).
- Apply migration: `npm run db:migrate` (`tsx db/migrate.ts`).
- Schema IDs must use UUIDv7 or `nanoid` (text primary keys), avoid autoincrementing integers for public IDs.

## Development Patterns to Follow

### 1. Server Components First
- Pages and parent containers are `async` Server Components by default.
- Fetch data directly inside Server Components using Drizzle queries:
  ```typescript
  export default async function DashboardPage() {
    const user = await getCurrentUser();
    const data = await db.select().from(workspaces).where(eq(workspaces.userId, user.id));
    return <WorkspaceList data={data} />;
  }
  ```

### 2. Mutations via Server Actions with Zod
- All mutations run in `actions/*.actions.ts` with `'use server';`.
- Always validate input with Zod and verify the user session:
  ```typescript
  'use server';
  import { z } from 'zod';
  import { auth } from '@/lib/auth';

  export async function updateWorkspaceAction(input: unknown) {
    const session = await auth();
    if (!session?.user) throw new Error('Unauthorized');

    const parsed = WorkspaceSchema.parse(input);
    await db.update(workspaces).set(parsed).where(eq(workspaces.userId, session.user.id));
    revalidatePath('/dashboard');
    return { success: true };
  }
  ```

## Anti-Patterns & What We DO NOT Do

1. **NO `useEffect` for Data Fetching:** Never use `useEffect` or client-side fetch loops for initial page loads. Use Server Components.
2. **NO Client-Side DB Calls:** Never import `db` in any file marked with `'use client'`. Bundling SQLite in browser bundles breaks builds.
3. **NO Raw Unparameterized SQL:** Always use Drizzle query builders or `sql` tagged template literals to eliminate SQL injection.
4. **NO In-Memory State for Ephemeral DB Connections:** SQLite is a single-file or localized DB. Keep the connection handle cached as a Node.js global singleton in development to prevent file lock saturation across Next.js HMR reloads.
