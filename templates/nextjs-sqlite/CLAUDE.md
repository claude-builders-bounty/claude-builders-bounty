# CLAUDE.md — Next.js 15 + SQLite SaaS

This file is the single source of truth for how Claude Code should work in this repo.
Read it before changing code. Prefer these rules over generic Next.js advice.

---

## Stack & versions

| Layer | Choice | Why |
|-------|--------|-----|
| Framework | Next.js 15 (App Router only) | Server Components by default; no Pages Router leftovers |
| Language | TypeScript strict | `tsconfig.json` must have `"strict": true` |
| DB | SQLite via `better-sqlite3` (local) or Turso (`@libsql/client`) | Same SQL dialect; sync API for better-sqlite3, async for Turso |
| ORM/query | Drizzle ORM | Schema-as-code, typed migrations, no runtime magic |
| Auth | Auth.js (NextAuth v5) or Lucia | Session in HTTP-only cookie; never localStorage |
| Validation | Zod | Parse at every system boundary (forms, API routes, env) |
| Styling | Tailwind CSS v4 | Utility-first; no CSS-in-JS in server components |
| Package manager | pnpm | Lockfile committed; do not use npm/yarn |

Node: `>=20`. Pin the major in `engines`.

## Project structure

```
app/
  (marketing)/          # public routes, no auth
  (app)/                # authenticated product shell
    layout.tsx          # requires session; redirects if logged out
    dashboard/
    settings/
  api/                  # Route Handlers only when the client cannot use Server Actions
  actions/              # Server Actions (default write path)
src/
  db/
    schema.ts           # Drizzle schema — ONLY place tables are defined
    migrations/         # generated by drizzle-kit; never hand-edit
    client.ts           # singleton connection (dev: globalThis cache)
    seed.ts
  lib/
    auth.ts
    env.ts              # zod-parsed process.env
    rate-limit.ts
  components/
    ui/                 # generic, no business logic
    features/           # one folder per product feature
tests/
  unit/
  e2e/
```

Rules:

- New page → `app/(app)/…` or `app/(marketing)/…`. Do not invent a third route group.
- New table → `src/db/schema.ts` + generated migration. No raw `CREATE TABLE` in app code.
- Shared logic → `src/lib/`. Feature-only logic stays next to the feature.
- No `src/app` — the App Router lives at repo root `app/`.

| Kind | Pattern | Example |
|------|---------|---------|
| Route segment | kebab-case | `app/(app)/billing/plans/page.tsx` |
| React component | PascalCase, named export preferred | `export function BillingTable()` |

| DB column | snake_case | `created_at`, `user_id` |

| Test file | `*.test.ts` next to unit / `*.e2e.ts` under tests | `rate-limit.test.ts` |

Do not use default exports for components (breaks fast-refresh metadata and refactoring).

## SQL / migration conventions

1. **Schema lives in Drizzle only.** Change `schema.ts`, then:

```bash
pnpm drizzle-kit generate
pnpm drizzle-kit migrate
```

2. **Migrations are append-only.** Never edit a file already in `migrations/`. Write a new one.
3. **Every table needs:**
   - `id` — `text` primary key (nanoid/uuid), not autoincrement integer
   - `created_at` — `integer` unix ms, default `now`
   - `updated_at` — same, updated on write
4. **Foreign keys** use `references(() => users.id, { onDelete: "cascade" })` where cascade is intended; document non-cascade FKs with a SQL comment.
5. **Indexes** on every FK and every column used in `WHERE` of list endpoints.
6. **No `SELECT *` in app code.** Always list columns (`db.select({ id: t.id, … })`).
7. **Writes go through transactions** when more than one table changes:

```ts
await db.transaction(async (tx) => {
  await tx.insert(projects).values(...);
  await tx.insert(projectMembers).values(...);
});
```

8. **Never** interpolate user input into SQL. Use Drizzle bindings only.
9. Local dev DB is `file:./dev.db` (gitignored). CI uses `file::memory:`.

## Component & data patterns

### Server Components are the default

- Fetch data in the component with `await db…`. No client-side fetch for initial page data.
- Pass serializable props down. Never pass `Date`, `BigInt`, or class instances to Client Components — convert first.

### Client Components only when needed

Mark `"use client"` **only** for: event handlers, browser APIs, local UI state, third-party client libs.
Keep them leaf-level. Do not wrap a whole page in `"use client"`.

### Server Actions for writes

```ts
"use server";
import { z } from "zod";
import { revalidatePath } from "next/cache";
import { auth } from "@/lib/auth";

const input = z.object({ name: z.string().min(1).max(80) });

export async function createProject(raw: unknown) {
  const session = await auth();
  if (!session) throw new Error("UNAUTHORIZED");
  const data = input.parse(raw);
  // …db write…
  revalidatePath("/dashboard");
}
```

- Always re-authenticate inside the action. Never trust the client.
- Always `zod.parse` the raw input.
- Always `revalidatePath` / `revalidateTag` after a write.

### Forms

Use a Server Action as `action={fn}`. Show errors with `useActionState` (or a form status object). No `fetch("/api/…")` for simple mutations.

## Patterns to follow

- **Env:** import `env` from `src/lib/env.ts` only. Accessing `process.env` outside that file is a bug.
- **Auth:** every `(app)` layout and every Server Action that mutates data checks `session`.
- **Multi-tenant:** every query filters by `organization_id` (or equivalent). Missing tenant filter is a P0.
- **Soft delete:** use `deleted_at` timestamps; default queries add `isNull(deleted_at)`.
- **Money:** store cents as `integer`. Never floats.
- **IDs:** generate in the app (`nanoid(12)`), not in SQL.
- **Errors:** throw typed errors (`UNAUTHORIZED`, `NOT_FOUND`, `VALIDATION`); map to HTTP in the route layer only.
- **Logging:** structured JSON via the project logger. No `console.log` in committed code.

## Anti-patterns (do not do — and why)

| Don't | Why |
|-------|-----|
| Prisma / TypeORM / raw `sqlite3` | Two ORMs drift; Drizzle is the contract |
| `useEffect` to fetch page data | Breaks RSC; slower; waterfalls |
| Editing generated migration files | Diverges from schema; next `generate` will fight you |
| Autoincrement integer PKs | Painful to merge across environments and clients |
| `any` / `@ts-expect-error` without a linked issue | Hides the exact bugs TypeScript is for |
| Storing JWT in localStorage | XSS exfiltration; use HTTP-only cookie sessions |
| Business logic in React components | Untestable; moves to `src/lib` or Server Actions |
| CSS-in-JS in Server Components | Not supported; use Tailwind |
| `SELECT *` | Breaks when columns are added; hides N+1 payloads |
| Committing `dev.db` or `.env` | Secrets and local state leak |

## What Claude Code should ask before doing

1. Adding a new third-party dependency (prefer stdlib / existing deps).
2. Changing an existing migration that is already on `main`.
3. Introducing a new route group outside `(marketing)` / `(app)`.
4. Any schema change that drops a column or table.

Everything else: implement, run the definition-of-done commands, then summarize.
