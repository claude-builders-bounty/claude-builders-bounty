# CLAUDE.md — Next.js 15 App Router + SQLite SaaS Architecture

> **Purpose:** This file defines the engineering standards, architecture, and constraints for Claude Code when developing and maintaining this Next.js 15 + SQLite SaaS project. Read this file completely before proposing or applying any code changes.

---

## 1. Stack & Versions

- **Framework:** Next.js 15+ (App Router only; Pages Router is forbidden)
- **Runtime & Language:** Node.js 22 LTS / TypeScript 5.6+ (`strict: true`, `noImplicitAny: true`)
- **Database Engine:** SQLite 3 via `better-sqlite3` (local / serverful) or `@libsql/client` (Turso serverless edge)
- **ORM & Migrations:** Drizzle ORM (`drizzle-orm` ^0.38+) + Drizzle Kit (`drizzle-kit` ^0.30+)
- **Validation:** Zod 3.23+ for all inputs, env vars, and server action contracts
- **Styling:** Tailwind CSS v4 + Lucide Icons + Radix UI primitives
- **Testing:** Vitest (unit/integration) + Playwright (E2E)
- **Package Manager:** `pnpm` (strictly enforced via `corepack`)

## 4. SQLite Database & Migration Rules

### 4.1 Connection Singleton & Mandatory PRAGMAs
SQLite must be initialized as a singleton to prevent multiple file handles in dev mode. Every connection **must** execute these 4 PRAGMA directives immediately on open:

```typescript
// src/db/index.ts
import Database from 'better-sqlite3';
import { drizzle } from 'drizzle-orm/better-sqlite3';
import * as schema from './schema';
import { env } from '@/lib/env';

const sqlite = new Database(env.DATABASE_PATH);

// 1. WAL mode: allows concurrent readers while writing
sqlite.pragma('journal_mode = WAL');
// 2. Synchronous NORMAL: optimal durability/performance balance for WAL
sqlite.pragma('synchronous = NORMAL');
// 3. Foreign Keys: SQLite disables foreign key constraints by default
sqlite.pragma('foreign_keys = ON');
// 4. Busy timeout: wait up to 5000ms instead of throwing SQLITE_BUSY error
sqlite.pragma('busy_timeout = 5000');

export const db = drizzle(sqlite, { schema });
```

### 4.2 Migration Protocol
- **Generate migrations:** Run `pnpm db:generate`. Never manually write raw SQL migration files without Drizzle Kit.
- **Apply migrations:** Run `pnpm db:migrate`.
- **Immutability:** Once a migration has been committed to version control, **never** alter it. Create a new migration file for changes.
- **Transactions:** Any multi-table insert/update must use `db.transaction(async (tx) => { ... })` to ensure atomicity.
- **Indexes:** Always create explicit indexes on every foreign key column (`index('user_id_idx').on(table.userId)`) because SQLite does NOT index foreign keys automatically.

## 5. Next.js 15 Component & Architecture Patterns

### 5.1 Server Components First
- Every component is a **React Server Component (RSC)** by default.
- Only add `'use client'` at the lowest possible leaf level that requires browser APIs (`useState`, `onClick`, `useForm`).
- Never pass sensitive database connection objects to Client Components.

### 5.2 Server Actions with Type-Safe Wrapper
Never expose unvalidated server actions. All mutations go through `createSafeAction`:

```typescript
// src/lib/safe-action.ts
import { z } from 'zod';
import { getSession } from '@/lib/session';

export function createSafeAction<TInput, TOutput>(
  schema: z.ZodSchema<TInput>,
  handler: (input: TInput, ctx: { userId: string }) => Promise<TOutput>
) {
  return async (rawInput: unknown): Promise<{ data?: TOutput; error?: string }> => {
    try {
      const session = await getSession();
      if (!session) return { error: 'Unauthorized' };

      const validated = schema.parse(rawInput);
      const data = await handler(validated, { userId: session.userId });
      return { data };
    } catch (err: any) {
      if (err instanceof z.ZodError) {
        return { error: err.issues.map((i) => i.message).join(', ') };
      }
      return { error: err.message || 'Internal Server Error' };
    }
  };
}
```

## 6. What We DO NOT Do (And Why)

1. **NO Prisma ORM:**  
   *Why:* Prisma introduces a heavy Rust engine binary, slow serverless cold starts, and higher memory overhead compared to Drizzle's direct native SQLite bindings.
2. **NO `useEffect` for Data Fetching:**  
   *Why:* Causes network waterfalls, flashing loading states, and layout shift. Fetch directly in Server Components or use Suspense.
3. **NO Internal REST API Routes (`src/app/api/...`):**  
   *Why:* Creating internal endpoints for internal frontend mutations adds boilerplate, serialization penalties, and redundant authentication layers. Use Server Actions.
4. **NO Raw String SQL Queries (`db.run("SELECT * FROM ...")`):**  
   *Why:* Bypasses TypeScript types and creates SQL injection vulnerabilities. Always use Drizzle query builders with parameterized inputs.
5. **NO Unindexed Foreign Keys in SQLite:**  
   *Why:* SQLite does not create indexes on foreign keys automatically. Omitting them causes full table scans on cascading joins and deletes.
6. **NO Skipping WAL Mode:**  
   *Why:* Default SQLite rollback journal locks the entire database on write, causing `SQLITE_BUSY` contention errors in web servers. WAL mode solves this.

## 7. Essential Development Commands

```bash
# Development
pnpm dev              # Start Next.js 15 dev server (port 3000)
pnpm build            # Production build with type checking
pnpm start            # Start production server

# Database & Migrations
pnpm db:generate      # Generate new migration from drizzle schemas
pnpm db:migrate       # Apply migrations to SQLite database
pnpm db:studio        # Launch Drizzle Studio web GUI
pnpm db:seed          # Seed database with sample test data

# Quality & Testing
pnpm lint             # Run ESLint check
pnpm typecheck        # Run tsc --noEmit
pnpm test             # Run Vitest test suite
pnpm test:e2e         # Run Playwright E2E tests
```
