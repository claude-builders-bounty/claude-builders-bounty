## 🏗️ Stack & Versions

| Layer | Technology | Version | Why |
|-------|-----------|---------|-----|
| Framework | Next.js | 15.x (App Router) | RSC, Server Actions, streaming |
| Language | TypeScript | 5.x strict mode | No `any`, no `// @ts-nocheck` |
| Database | SQLite via better-sqlite3 | 11.x (or Turso/libsql) | Zero ops, local-first, fast CI |

| Auth | NextAuth.js / Auth.js | 5.x (beta) | Standard, works with Drizzle adapter |
| Forms | React Aria Components | latest | Accessible, headless, composable |
| Schema | Zod | 3.23+ | Runtime validation, inferred types |
| CSS | Tailwind CSS | 4.x | Utility-first, no CSS-in-JS |
| Testing | Vitest + Playwright | latest | Fast unit + reliable E2E |

│   ├── seed.ts            # Development seed data
│   └── index.ts           # DB client singleton
├── lib/
│   ├── actions/           # Server Actions (one file per domain)

**Rule:** If a file doesn't fit this structure, add to `lib/` — not to a new top-level folder.

## 🗄️ SQL / Migration Conventions

### Schema Rules

- **One file per domain** in `db/schema/` (e.g., `users.ts`, `teams.ts`, `subscriptions.ts`)
- **Use `text()` for IDs** — UUIDs stored as strings, not integers
- **Timestamps** → `integer('created_at', { mode: 'timestamp_ms' }).notNull().defaultNow()`
- **Soft deletes** → add `deleted_at integer` column; never `DELETE FROM`
- **Foreign keys** → define in schema with `.references(() => otherTable.id)`
- **Indexes** → add for every column used in `WHERE`, `ORDER BY`, or `JOIN`

### Migration Workflow

```
1. Edit schema → 2. npm run db:generate → 3. Review SQL → 4. npm run db:push (dev)
                                         → 4. Commit migration → 5. Apply in prod via script
```

**No raw SQL migrations** without review. Drizzle-generated SQL is preferred.

### Anti-patterns ❌

- **`SELECT *`** in production queries — always name columns
- **N+1 queries** — use Drizzle `with` (eager loading) or batch
- **Migrations in `git push` hooks** — manual, reviewed, versioned
- **Default `NULL` for non-nullable columns** — always provide `default` or handle in code

## ⚛️ Component Patterns

### React Server Components (RSC) — Default

```tsx
// ✅ DO: Server Component by default
async function TeamPage({ params }: { params: { id: string } }) {
  const team = await db.query.teams.findFirst({
    where: eq(teams.id, params.id),
  })
  return <TeamDetail team={team} />
}
```

### Client Components — Only When Needed

Add `'use client'` ONLY for:
- `useState` / `useEffect` / `useRef`
- Event handlers (`onClick`, `onSubmit`)
- Browser APIs (`localStorage`, `navigator`)
- Third-party libs that need DOM access

### Server Actions — Mutations

```tsx
// lib/actions/team.ts (NOT inline in the component file)
'use server'

export async function updateTeamName(formData: FormData) {
  const { name, teamId } = updateNameSchema.parse({
    name: formData.get('name'),
    teamId: formData.get('teamId'),
  })
  await db.update(teams).set({ name }).where(eq(teams.id, teamId))
  revalidatePath('/settings')
}
```

### Form Handling

```tsx
// ✅ DO: Server Action + Zod
<form action={updateTeamName}>
  <Input name="name" />
  <Button type="submit">Save</Button>
</form>

// ❌ DON'T: useState for form state + fetch() to API route
```

### Data Fetching Pattern

```tsx
// ✅ DO: Fetch in Server Component, pass down
// ❌ DON'T: fetch in client component with useEffect
// ❌ DON'T: use SWR/React Query for server-fetched data
```

## 🧠 Architecture Decisions (Opinionated)

### What We DO

| Decision | Reason |
|----------|--------|
| Server Actions over API routes | Fewer files, type-safe, no serialization |
| Drizzle over Prisma | SQL-like, no hidden queries, smaller bundle |
| UUIDs over auto-increment | Safer for multi-tenant, no enumeration |
| Zod over Yup/Joi | Best TypeScript inference, smallest |
| Tailwind over CSS modules | No naming, easy responsive, no dead CSS |
| Single DB file per tenant | SQLite strength; keeps backups/export simple |

### What We DON'T Do (And Why)

- **No `useEffect` for data fetching** → RSC handles it; `useEffect` fetches are racy, hard to test, and break SSR
- **No Zustand/Redux** → RSC + URL state covers 95% of SaaS state; for the other 5%, React Context is enough
- **No `any` types** → Every `any` is a future prod bug; use `unknown` + Zod instead
- **No barrel exports (`index.ts` that re-exports)** → Breaks tree-shaking, slows HMR
- **No global CSS** → Tailwind + CSS modules only; no `styles.css` imports in layout
- **No `fetch` in `getServerSideProps`** → App Router doesn't have it; use direct DB calls
- **No runtime `process.env` checks** → Validate at startup with Zod, not in every handler
- **No `DELETE FROM` without WHERE** (obvious, but…) — the DB won't save you

## 🔐 Auth Pattern

```tsx
// app/(auth)/layout.tsx — protect everything in this group
import { auth } from '@/lib/auth'

export default async function AuthLayout({ children }: { children: React.ReactNode }) {
  const session = await auth()
  if (!session) redirect('/login')
  return <>{children}</>
}
```

Auth.js v5 with Drizzle adapter. Session fetched in layout — never in individual pages.

## 🧪 Testing

- **Unit** → Vitest for pure functions and Server Actions
- **Integration** → Vitest + SQLite in-memory for DB queries
- **E2E** → Playwright for critical paths (auth, billing, onboarding)
- **No snapshot tests** for components (brittle, low value)

```bash
npm run test       # Unit + integration
npm run test:e2e   # Requires dev server running
```

## 📝 Code Style (Beyond Prettier)

- **Imports**: `@/` for src, explicit relative for siblings (`./component`)
- **Error messages**: Start lowercase, no period — consistent with Node.js built-ins
- **Async functions**: Always return explicit type when the return is complex
- **File names**: `kebab-case.ts` for utils, `PascalCase.tsx` for components
- **CSS order**: Layout → Color → Typography → Spacing → Animation
