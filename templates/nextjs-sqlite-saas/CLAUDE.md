# CLAUDE.md — Next.js 15 + SQLite SaaS

> Opinionated project context for Claude Code. Every rule exists because we got burned without it.

## Stack

| Layer | Choice | Why |
|-------|--------|-----|
| Framework | Next.js 15 App Router | Server Components by default; client only when needed |
| Database | better-sqlite3 (local) / Turso (prod) | Zero-config local dev; Turso for edge部署 |
| ORM | Drizzle ORM | Type-safe SQL, no runtime overhead |
| Auth | better-auth | SQLite-native, no external deps |
| Styling | Tailwind CSS 4 + shadcn/ui | Consistent, no CSS-in-JS runtime |
| Validation | Zod | Co-located with Drizzle schemas |
| Testing | Vitest + Playwright | Unit + E2E, fast feedback |
| Package Manager | pnpm | Strict, fast, monorepo-ready |

**Rule: Routes are thin.** `app/` files import from `components/` and `lib/`. No business logic in route files.

## Database Rules

### Schema

```typescript
// db/schema.ts — ONE file, ALL tables
import { sqliteTable, text, integer } from "drizzle-orm/sqlite-core";

export const users = sqliteTable("users", {
  id: text("id").primaryKey(),          // nanoid or cuid
  email: text("email").notNull().unique(),
  createdAt: integer("created_at", { mode: "timestamp" }).notNull(),
});
```

**Rules:**
1. **IDs are always `text`** — use `nanoid()` or `cuid()`. Never auto-increment integers for entity IDs.
2. **Timestamps are `integer` with `mode: "timestamp"`** — SQLite has no datetime type. Store as Unix epoch.
3. **Every table has `createdAt`**. Add `updatedAt` if the row is mutable.
4. **No relations in schema file** — use `relations()` in a separate `db/relations.ts` file.
5. **One migration per PR** — never ship a PR that touches schema without a migration.

### Migrations

```bash
# Generate migration from schema changes
pnpm drizzle-kit generate

# Apply migrations
pnpm drizzle-kit migrate

# NEVER manually edit migration files after they're committed
```

**Rule: Migrations are append-only.** If you need to fix a migration, create a new one. Don't edit committed migrations.

### Queries

```typescript
// ✅ Correct: use db directly
const user = await db.query.users.findFirst({
  where: eq(users.id, userId),
});

// ❌ Wrong: don't use raw SQL unless Drizzle can't express it
const user = await db.get("SELECT * FROM users WHERE id = ?", userId);
```

## Component Patterns

### Server Components (default)

```typescript
// app/(dashboard)/page.tsx
import { db } from "@/db";
import { users } from "@/db/schema";

export default async function DashboardPage() {
  const userList = await db.query.users.findMany();
  return <UserTable users={userList} />;
}
```

**Rule: Fetch data in Server Components.** Never fetch in `useEffect` unless the data changes based on user interaction.

### Client Components

```typescript
// components/features/user-form.tsx
"use client";

import { useState } from "react";
import { Button } from "@/components/ui/button";

export function UserForm() {
  const [name, setName] = useState("");
  // ...
}
```

**Rule: "use client" only when you need interactivity.** If it's just display, keep it server-side.

### API Routes

```typescript
// app/api/users/route.ts
import { NextResponse } from "next/server";
import { db } from "@/db";
import { insertUserSchema } from "@/db/schema";

export async function POST(req: Request) {
  const body = await req.json();
  const parsed = insertUserSchema.safeParse(body);
  if (!parsed.success) {
    return NextResponse.json(parsed.error, { status: 400 });
  }
  const user = await db.insert(users).values(parsed.data).returning();
  return NextResponse.json(user);
}
```

**Rule: Validate every API input with Zod.** Never trust client data.

## Naming Conventions

| What | Convention | Example |
|------|-----------|---------|
| Files | kebab-case | `user-table.tsx` |
| Components | PascalCase | `UserTable` |
| Hooks | camelCase with `use` prefix | `useCurrentUser` |
| DB tables | snake_case, plural | `users`, `user_sessions` |
| DB columns | snake_case | `created_at`, `user_id` |
| API routes | kebab-case | `/api/user-profiles` |
| Env vars | SCREAMING_SNAKE | `DATABASE_URL` |

## What We Don't Do (and Why)

| Anti-Pattern | Why It Hurts |
|-------------|-------------|
| `any` type | Defeats TypeScript. Use `unknown` + type guards. |
| Barrel exports (`index.ts`) | Kills tree-shaking. Import from source files. |
| Global CSS modules | Tailwind handles it. Global CSS = specificity wars. |
| `useEffect` for data fetching | Use Server Components or React Query for client data. |
| Storing JWTs in localStorage | XSS-vulnerable. Use httpOnly cookies via better-auth. |
| ORM lazy loading | N+1 queries. Eager-load with `with:` or separate queries. |
| Environment-specific `.env` files | Use a single `.env.local` + `env.ts` validation. |
| Prisma | Heavy runtime, poor SQLite support. Drizzle is better here. |

**Rule: All env vars are validated in `env.ts` using Zod.** Never access `process.env` directly.

## Git Workflow

1. Branch from `main`: `feat/xxx` or `fix/xxx`
2. One feature per PR
3. PR must pass: `typecheck` + `lint` + `test`
4. Squash merge to `main`
5. Delete branch after merge

## Testing Rules

1. **Unit tests** for utility functions and business logic
2. **Integration tests** for API routes (mock DB or use test DB)
3. **E2E tests** for critical user flows (auth, checkout)
4. **No snapshot tests** — they break on every UI change and add no value

```typescript
// ✅ Good: test behavior
it("should reject invalid email", async () => {
  const res = await POST({ body: { email: "bad" } });
  expect(res.status).toBe(400);
});

// ❌ Bad: test implementation
it("should call validateEmail", async () => {
  const spy = vi.spyOn(validators, "validateEmail");
  await POST({ body: { email: "test@example.com" } });
  expect(spy).toHaveBeenCalled();
});
```

## Deployment

- **Local**: `pnpm dev` with SQLite file
- **Production**: Vercel + Turso (or any edge-compatible host)
- **Migrations**: Run `pnpm db:migrate` in CI before deploy
- **Never**: Commit `.env.local` or `*.db` files
