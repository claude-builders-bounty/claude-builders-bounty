# CLAUDE.md — Next.js 15 + SQLite SaaS Template

> **Production Guidelines & Architecture Contract for Claude Code**  
> This file establishes strict architectural conventions, code patterns, and constraints for this SaaS application. Adhere to all rules strictly.

---

## 1. Stack & Versions

- **Framework**: Next.js 15.x (App Router only, React 19, Server Components by default)
- **Language**: TypeScript 5.x (`strict: true`, zero `any`)
- **Styling**: Tailwind CSS v4 (or v3.4+) + `clsx` / `tailwind-merge` (`cn()` helper)
- **Database**: SQLite via `better-sqlite3` (local/container) or `libsql` / `@libsql/client` (Turso edge replication)
- **Query Builder / ORM**: Drizzle ORM (`drizzle-orm` + `drizzle-kit`) for type-safe SQL and deterministic migrations
- **Authentication**: Lucia Auth / Auth.js with SQLite session adapter or iron-session
- **Validation**: Zod 3.x for all runtime input/output boundaries (Server Actions, route handlers, forms)
- **Icons**: `lucide-react`
- **Testing**: Vitest (unit/integration) + Playwright (E2E)

## 4. SQLite & Database Conventions

1. **Always Enable WAL Mode & Foreign Keys**:
   SQLite defaults to rollback journals and ignores foreign keys unless explicitly toggled on every connection.
   ```typescript
   // src/db/index.ts
   import Database from 'better-sqlite3';
   import { drizzle } from 'drizzle-orm/better-sqlite3';
   import * as schema from './schema';

   const sqlite = new Database(process.env.DATABASE_URL || 'sqlite.db');
   sqlite.pragma('journal_mode = WAL');       // High concurrency read-write
   sqlite.pragma('foreign_keys = ON');         // Enforce referential integrity
   sqlite.pragma('busy_timeout = 5000');       // Prevent SQLITE_BUSY under parallel requests
   sqlite.pragma('synchronous = NORMAL');      // Optimal balance of durability and speed

   export const db = drizzle(sqlite, { schema });
   ```

2. **Deterministic Migrations**:
   - Never run raw `db.run("CREATE TABLE ...")` inside application code.
   - All schema modifications must live in `src/db/schema/*.ts`.
   - Run `pnpm db:generate` to produce timestamped, immutable `.sql` migration files.
   - Run `pnpm db:migrate` at deploy time before web process start.

3. **Multi-Tenancy & Data Isolation**:
   - Every tenant-scoped table MUST include a foreign key `organization_id: text('organization_id').notNull().references(() => organizations.id, { onDelete: 'cascade' })`.
   - Always index `organization_id` on tenant tables: `index('idx_org_id').on(table.organizationId)`.
   - Queries must filter by `eq(table.organizationId, currentOrgId)`. Never perform un-scoped queries in dashboard routes.

4. **IDs & Timestamps**:
   - Primary keys: use prefixed NanoID or ULID strings (e.g., `usr_01H...`, `org_01H...`) instead of auto-incrementing integers to prevent ID enumeration attacks.
   - All tables must track `createdAt` (`integer({ mode: 'timestamp' })` or `text`) and `updatedAt`.

## 5. Component & Server Action Patterns

1. **Server Components by Default**:
   - Every file in `src/app/` is a Server Component unless explicitly marked with `'use client'`.
   - Fetch data directly in Server Components using async/await and `db.query.*`.
   - Never pass client fetch waterfalls; pass data down as props.

2. **Client Components Boundary**:
   - Add `'use client'` only at the leaf level for user interaction (buttons, inputs, local state).
   - Do not wrap entire pages with `'use client'`.

3. **Mutations via Server Actions**:
   - Place mutation handlers in `src/actions/`.
   - Always validate inputs using a Zod schema before calling database operations.
   - Verify the authenticated session inside every Server Action:
   ```typescript
   'use server';

   import { z } from 'zod';
   import { requireAuth } from '@/lib/auth';
   import { db } from '@/db';

   const UpdateProfileSchema = z.object({
     name: z.string().min(2).max(100),
   });

   export async function updateProfileAction(formData: FormData) {
     const session = await requireAuth(); // Throws or redirects if unauthenticated
     const parsed = UpdateProfileSchema.safeParse({
       name: formData.get('name'),
     });

     if (!parsed.success) {
       return { success: false, errors: parsed.error.flatten().fieldErrors };
     }

     await db.update(users)
       .set({ name: parsed.data.name, updatedAt: new Date() })
       .where(eq(users.id, session.userId));

     return { success: true };
   }
   ```

## 6. What We Don't Do (And Why)

| Anti-Pattern | Why We Avoid It | What To Do Instead |
|---|---|---|
| **No API Routes for internal form mutations** | Traditional `/api/*` routes duplicate type definitions and lack native React 19 transitions. | Use Next.js **Server Actions** (`'use server'`) with Zod validation. Keep `/api/` solely for external third-party webhooks (e.g., Stripe). |
| **No `any` or loose casting (`as unknown as T`)** | Destroys TypeScript guarantees and causes subtle runtime runtime crashes in production. | Define strict TypeScript interfaces and derive DB types with `InferSelectModel` / `InferInsertModel`. |
| **No heavy ORMs (Prisma runtime)** | Prisma has large binary engine overhead and higher latency with SQLite on serverless/embedded targets. | Use **Drizzle ORM** — lightweight, zero binary dependencies, direct SQL transparency. |
| **No synchronous blocking DB calls on edge runtimes** | Native C++ bindings (`better-sqlite3`) will crash on Edge / Cloudflare Workers. | Run Node.js runtime for local/Docker deployments (`export const runtime = 'nodejs'`), or use `@libsql/client` (Turso) over HTTP when deploying to edge environments. |
| **No inline raw styles or CSS modules** | Inconsistent design token usage, bundle size bloat, and CSS naming conflicts. | Use utility-first **Tailwind CSS** with design tokens defined in `tailwind.config.ts`. |
| **No storing unhashed secrets or tokens in DB** | Security vulnerability if database file is exposed or backed up. | Always hash secrets with `argon2id` or `bcrypt` before storage. |

## 7. Naming Conventions

- **Directories**: kebab-case (`components/dashboard-header`)
- **React Components**: PascalCase (`ProjectCard.tsx`)
- **Server Actions**: camelCase with Action suffix (`updateTenantAction.ts`)
- **Database Tables**: snake_case plural (`users`, `organization_memberships`)
- **Database Columns**: snake_case in SQL, camelCase in TypeScript Drizzle schema
- **Environment Variables**: UPPER_SNAKE_CASE (`DATABASE_URL`, `STRIPE_SECRET_KEY`)
