## Database & Migrations

- Schema lives in `db/schema.ts` — Drizzle generates everything from it.
- Run migrations: `npx drizzle-kit generate` then `npx drizzle-kit migrate`.
- **Never write raw SQL migrations.** Let Drizzle generate them from schema changes.
- Foreign keys must use `onDelete: 'cascade'` unless there's a documented reason not to.
- Every table needs: `id TEXT PRIMARY KEY DEFAULT (uuid())`, `createdAt`, `updatedAt`.
- Use `TEXT` for all IDs — no auto-increment integers.
- **SQLite gotcha:** No array columns. Model 1:N with a join table, or use JSON + CHECK constraints.
- Seed script goes in `db/seed.ts` — run it with `tsx db/seed.ts` (never in production).

## Component Patterns

```tsx
// ✅ Server Component by default (no "use client" at top of file)
export default async function BillingPage() {
  const invoices = await db.select().from(invoicesTable);
  return <InvoiceList invoices={invoices} />;
}

// ✅ Client component only when you need interactivity
"use client";
export function InvoiceList({ invoices }: { invoices: Invoice[] }) {
  const [sort, setSort] = useState<"date" | "amount">("date");
  // ...
}
```

**State management:** useState/useReducer for local, URL search params for shareable state, Zod-validated server actions for mutations. No Redux, no Zustand — you don't need them yet.

**Data fetching:** Server Components fetch directly with Drizzle. No `useEffect` + fetch. If you need client-side revalidation, use `swr` or `react-query` with a route handler.

**Forms:** Zod schema → `zodResolver` → react-hook-form → server action. One schema, used everywhere.

## Server Actions

```ts
"use server";
export async function createWorkspace(formData: FormData) {
  const raw = Object.fromEntries(formData);
  const data = createWorkspaceSchema.parse(raw); // Zod validates, throws on bad input
  await db.insert(workspaces).values(data);
  revalidatePath("/dashboard");
  redirect(`/dashboard/${data.id}`);
}
```

- Every server action validates input with Zod.
- Every mutation revalidates the affected path.
- Return `{ error: string } | { success: true }` — never throw to the client.

## Auth Rules

- Better Auth handles sessions. Store session cookie, not JWTs.
- Middleware in `middleware.ts` redirects unauthenticated users from `(dashboard)` to `/login`.
- Every server action reads `getSession()` first — no implicit auth.
- API routes get auth from the `Authorization` header or session cookie.

## Anti-Patterns (Don't Do These)

| ❌ Don't | ✅ Do Instead | Why |
|---|---|---|
| Use `any` | `unknown` + type guard | Any defeats TypeScript |
| Fetch in useEffect | Server Component data fetching | Avoid waterfall, better SEO |
| `import * as X` | Named imports | Tree-shaking breaks with star imports |
| CSS-in-JS (styled-components, emotion) | Tailwind utilities | Server Components can't serialize CSS-in-JS |
| Store state in Context for everything | URL params + server data | Context re-renders everything |
| Write raw SQL | Drizzle query builder | Type safety, migration support |
| Default exports | Named exports | Better refactoring, consistent imports |
| Catch all errors silently | `return { error: "..." }` | Errors must be visible |
| Use `process.env.X` without validation | `envSchema.parse(processEnv)` | Runtime crash > silent undefined |
| Create a `components/index.ts` | Import from `components/features/Header` | Barrel files hide dependencies |

## Environment Variables

All env vars are validated at startup in `lib/env.ts`:

```ts
import { z } from "zod";

const envSchema = z.object({
  DATABASE_URL: z.string().url(),
  BETTER_AUTH_SECRET: z.string().min(32),
  BETTER_AUTH_URL: z.string().url(),
  // Add new vars here — the app crashes fast if they're missing
});

export const env = envSchema.parse(process.env);
```

**Never** access `process.env` directly elsewhere. Import `env` from `lib/env.ts`.

## What We Build Here

This is a SaaS. Users pay us. That means:

1. **Error states matter.** Every async operation has loading + error + empty + data states.
2. **Performance budget.** Largest Contentful Paint < 2s. Use `next/image`, lazy-load below fold.
3. **Accessibility is not optional.** Semantic HTML, aria-labels, keyboard nav.
4. **Security defaults on.** CSRF via server actions, rate limiting on auth endpoints, SQL injection prevented by Drizzle.
