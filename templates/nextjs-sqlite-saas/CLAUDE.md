# CLAUDE.md — Next.js 15 + SQLite SaaS

> Opinionated guide for Claude Code. Every rule has a reason. If a rule blocks you, **stop and ask** — don't silently route around it.

---

## Stack & Versions

- **Runtime:** Node.js 20 LTS (NOT edge — SQLite needs native bindings)
- **Framework:** Next.js 15 (App Router, React Server Components, Server Actions)
- **Database:** SQLite via `better-sqlite3` (local/VPS) or `@libsql/client` (Turso for prod)
- **ORM:** Drizzle ORM (`drizzle-orm` + `drizzle-kit`) — *not* Prisma. Reasons: zero codegen step, SQL-first, edge-compatible client, no rust binary churn.
- **Auth:** Lucia v3 with Drizzle adapter — *not* NextAuth. Reasons: cookie sessions stored in our DB, no opaque JWT magic, full control over user table.
- **Styling:** Tailwind v4 + shadcn/ui (copy-paste, not a dep)
- **Validation:** Zod everywhere user input crosses a boundary
- **Testing:** Vitest (unit) + Playwright (e2e). No Jest.
- **Package manager:** pnpm. Lockfile is committed and authoritative.
- **TypeScript:** strict mode, `noUncheckedIndexedAccess: true`. No `any` without a `// reason:` comment.

## Database & Migrations

### The DB client (`lib/db/index.ts`)

```ts
import { drizzle } from "drizzle-orm/better-sqlite3";
import Database from "better-sqlite3";
import { env } from "@/lib/env";
import * as schema from "./schema";

const sqlite = new Database(env.DATABASE_URL);
sqlite.pragma("journal_mode = WAL");        // concurrent reads, single writer
sqlite.pragma("foreign_keys = ON");          // SQLite defaults this OFF — always enable
sqlite.pragma("synchronous = NORMAL");       // safe with WAL, ~3x faster than FULL
sqlite.pragma("busy_timeout = 5000");        // wait 5s on lock instead of erroring

export const db = drizzle(sqlite, { schema });
```

For Turso, swap to `@libsql/client` — same Drizzle API.

### Migration rules

1. **Schema change → `pnpm db:generate` → review generated SQL → commit both `schema.ts` and the new `*.sql` file.**
2. **Never edit a migration after it's merged to main.** Add a new migration that fixes it.
3. **Never use `db:push` against a non-local DB.** Push is for prototyping only.
4. Every migration runs in a transaction. If you need a multi-step data backfill, write it as a TS script in `lib/db/scripts/` and document it in the PR.
5. SQLite quirks to respect:
   - No native `DROP COLUMN` on old SQLite versions — Drizzle handles via table rebuild, but it locks. Avoid in prod-hot tables.
   - No native `ALTER COLUMN` for type changes. Plan additive: add new col, backfill, switch reads, drop old in a later release.
   - Booleans are integers (0/1). Use Drizzle's `integer({ mode: "boolean" })`.
   - Timestamps: store as `integer({ mode: "timestamp" })` (unix seconds). Don't use TEXT for dates.
   - JSON: `text({ mode: "json" }).$type<MyType>()`. Validate with Zod on read.

### Query rules

- Always use Drizzle query builder or `db.query.*`. **No raw SQL strings** unless commented with a reason.
- Selects MUST narrow columns when the row is large. Don't `select *` a `text` blob you won't use.
- Wrap multi-statement writes in `db.transaction(...)`. SQLite has *one* writer — keep transactions short.
- Pagination: cursor-based on indexed columns. `OFFSET` is a footgun past page 100.

## Auth (Lucia v3)

- Sessions live in the `session` table, cookie is `auth_session` (httpOnly, secure, sameSite=lax).
- Session lookup happens in a single helper: `getSession()` from `lib/auth.ts`. Cache with React's `cache()` per-request.
- The `(app)` route group's `layout.tsx` calls `getSession()` and `redirect("/login")` if absent. Pages inside trust the session exists.
- Password hashing: `@node-rs/argon2`. Never bcrypt (slower, weaker memory hardness).
- OAuth: `arctic` library. Store provider tokens in `oauth_account` table, not on `user`.
- **Never read cookies in a Server Component to check auth** — use `getSession()`.
- **Never call `getSession()` from middleware.** Middleware runs on edge; do auth checks in the layout.

## Server Actions vs API Routes

**Default to Server Actions.** Use API routes only when you need:
- A webhook receiver (Stripe, Resend, etc.)
- A public JSON API for a 3rd party / mobile client
- Streaming responses outside React (SSE, file downloads)
- A health check / cron endpoint

Server Action conventions:
- Live in `lib/actions/<domain>.ts`, top of file is `"use server"`.
- Every action: (1) validate input with Zod, (2) check session, (3) authorize (does this user own this resource?), (4) mutate, (5) `revalidatePath` or `revalidateTag`, (6) return `{ ok: true, data }` or `{ ok: false, error }` — never throw to the client.
- Wrap with a `withAuth(action)` helper to dedupe steps 2+3.
- Rate limit mutating actions. Use a simple SQLite-backed bucket in `lib/rate-limit.ts`.

API route conventions:
- One handler per file, named `route.ts`.
- Webhooks verify signatures BEFORE parsing body. Use the `req.text()` raw body, not `req.json()`.
- Return `Response` directly. No helper wrappers.

## Components

- **Server Components by default.** Add `"use client"` only when you need state, effects, or browser APIs.
- A client component should not import a server-only module. Use the `server-only` package to enforce.
- Forms use `<form action={serverAction}>` + `useFormState` for progressive enhancement. No fetch-from-onClick.
- Loading states via `loading.tsx` and `<Suspense>`. Don't roll your own spinner state.
- Error boundaries via `error.tsx`. Log to your observability stack, show a friendly message.

## Environment Variables

`lib/env.ts` is the only file that reads `process.env`:

```ts
import { z } from "zod";
const schema = z.object({
  DATABASE_URL: z.string().min(1),
  AUTH_SECRET: z.string().min(32),
  STRIPE_SECRET_KEY: z.string().startsWith("sk_"),
  STRIPE_WEBHOOK_SECRET: z.string().startsWith("whsec_"),
  RESEND_API_KEY: z.string().optional(),
  NODE_ENV: z.enum(["development", "test", "production"]),
});
export const env = schema.parse(process.env);
```

`.env.example` is committed and complete. `.env.local` is gitignored.

## Testing

- **Unit (Vitest):** pure functions, Zod schemas, action logic with a mocked db. Fast, runs on every save.
- **Integration:** spin up an in-memory SQLite (`:memory:`), run real migrations, hit real actions. One DB per test file.
- **E2E (Playwright):** smoke tests for signup → checkout → core flow. Run against `next start` with a seeded test DB.
- Coverage target: 70% on `lib/`. App routes are tested via e2e, not unit.
- Snapshot tests are banned except for generated SQL migrations.

## Deployment

- **Recommended:** Fly.io / Railway / a VPS with a persistent volume mounted at `/data`. SQLite file lives there.
- **Turso (libSQL):** good for multi-region reads. Use it when you have one. Same Drizzle code.
- **Vercel + serverless SQLite:** don't. The filesystem is ephemeral and writes from concurrent lambdas corrupt the DB. If you must Vercel, use Turso.
- Run `pnpm db:migrate` as a release step, not at app boot (avoids races on rolling deploys).
- Back up the SQLite file with Litestream → S3. Set this up on day one, not after the first incident.
- Health check at `/api/health` — pings DB with `SELECT 1`.

## What We Don't Do (and Why)

- **No Prisma.** Codegen step + binary churn + worse SQLite story than Drizzle.
- **No NextAuth.** Opaque, hard to customize the user table, JWT-by-default leaks our schema decisions.
- **No tRPC.** Server Actions cover 90% of what tRPC did, with less ceremony. Use API routes for the rest.
- **No Redux / Zustand by default.** RSC + URL state + `useState` covers most needs. Reach for Zustand only if a real cross-tree client state appears.
- **No CSS-in-JS runtime.** Tailwind compiles. Runtime CSS-in-JS is a perf tax we don't pay.
- **No `useEffect` for data fetching.** Fetch in Server Components or via Server Actions. `useEffect` is for syncing with non-React systems.
- **No `any`, no `as` casts** without a comment explaining why the type system is wrong.
- **No new dependency** without a one-line PR justification. Bundle size and supply chain matter.
- **No edge runtime** for anything that touches the DB. Edge is for redirects and rewrites.
- **No `db:push` to prod.** Migrations are auditable; push is not.
- **No clever abstractions.** If a function is used once, inline it. Extract on the second use, not the first.
