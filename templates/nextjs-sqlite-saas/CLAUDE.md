# CLAUDE.md - Next.js 15 App Router + SQLite SaaS Blueprint

> Production-ready, highly opinionated architectural guidelines for building full-stack SaaS applications with Next.js 15, React 19, TypeScript, and SQLite (better-sqlite3 / Turso) via Drizzle ORM.

---

## 1. Stack & Pinned Versions

- **Framework**: Next.js 15.x (`app` router exclusively, React 19 Canary/GA, React Server Components by default).
- **Language**: TypeScript 5.6+ with `strict: true` and `noUncheckedIndexedAccess: true`.
- **Database**: SQLite (local `better-sqlite3` in development, `@libsql/client` / Turso in production edge/serverless).
- **ORM & Migrations**: Drizzle ORM (`drizzle-orm` + `drizzle-kit`).
- **Authentication**: Auth.js / Lucia or signed HTTP-only JWT sessions stored in SQLite.
- **Styling**: Tailwind CSS v4 + `shadcn/ui` components (Radix primitives).
- **Validation**: Zod for Server Action and API payload validation.

```
│   └── page.tsx              # Marketing landing page
├── components/
│   ├── ui/                   # Unmodified shadcn/ui primitives (button, dialog, input)
│   └── shared/               # Composed UI widgets (UserNav, SubscriptionCard, DataGrid)
├── lib/
│   ├── db/
│   │   ├── schema.ts         # Consolidated or domain-partitioned Drizzle table definitions
│   │   ├── index.ts          # Singleton DB client initialization with WAL pragmas
│   │   └── migrations/       # SQL migration files generated by drizzle-kit
│   ├── actions/              # Server Actions (mutations: billing.ts, user.ts, teams.ts)
│   ├── auth/                 # Session parsing, cookie helpers, and permission guards
│   ├── email/                # Transactional email templates (React Email / Resend)
│   └── utils.ts              # cn helper and formatting functions
└── drizzle.config.ts         # Drizzle kit configuration
```

### Naming Conventions
- **Files**: `kebab-case.ts` for utilities and actions; `PascalCase.tsx` only for components (`UserMenu.tsx`).
- **Database Tables**: Plural snake_case (`users`, `teams`, `subscriptions`, `audit_logs`).
- **Database Columns**: Singular snake_case (`id`, `user_id`, `created_at`, `is_active`).
- **TypeScript Types**: PascalCase (`User`, `NewUser`, `SubscriptionPlan`).

## 4. SQLite Performance & Migration Invariants

SQLite requires explicit PRAGMAs to deliver concurrency and sub-millisecond response times:

1. **WAL Mode is Mandatory**: Always initialize connections with Write-Ahead Logging:
   ```typescript
   // lib/db/index.ts
   import Database from "better-sqlite3";
   import { drizzle } from "drizzle-orm/better-sqlite3";
   import * as schema from "./schema";

   const sqlite = new Database(process.env.DATABASE_URL || "local.db");
   sqlite.pragma("journal_mode = WAL");
   sqlite.pragma("synchronous = NORMAL");
   sqlite.pragma("foreign_keys = ON");
   sqlite.pragma("busy_timeout = 5000");

   export const db = drizzle(sqlite, { schema });
   ```
2. **Never Edit Generated SQL Migrations**: Always edit `lib/db/schema.ts` and run `npx drizzle-kit generate`.
3. **Index Every Foreign Key**: SQLite does not automatically index foreign key columns. Explicitly add `.index()` on any `team_id`, `user_id`, or `org_id` column.
4. **Transactions for Multi-Write Operations**: Wrap all interdependent inserts/updates in `db.transaction(async (tx) => { ... })`.

## 5. Architectural Patterns to Follow

### 1. Server Components by Default
- Fetch data directly in Server Components using async/await:
  ```tsx
  // app/(dashboard)/dashboard/page.tsx
  import { db } from "@/lib/db";
  import { requireUser } from "@/lib/auth";

  export default async function DashboardPage() {
    const user = await requireUser();
    const stats = await db.query.userStats.findFirst({
      where: (t, { eq }) => eq(t.userId, user.id)
    });

    return <DashboardView user={user} stats={stats} />;
  }
  ```

### 2. Server Actions for Mutations (Zero REST Boilerplate)
- Place mutations in `lib/actions/*.ts` with `"use server"`.
- Always validate input with Zod.
- Always verify authentication inside the Server Action:
  ```typescript
  "use server";
  import { z } from "zod";
  import { db } from "@/lib/db";
  import { users } from "@/lib/db/schema";
  import { requireUser } from "@/lib/auth";
  import { eq } from "drizzle-orm";
  import { revalidatePath } from "next/cache";

  const UpdateNameSchema = z.object({
    name: z.string().min(2).max(50)
  });

  export async function updateProfileName(input: z.infer<typeof UpdateNameSchema>) {
    const user = await requireUser();
    const { name } = UpdateNameSchema.parse(input);

    await db.update(users).set({ name, updatedAt: new Date().toISOString() }).where(eq(users.id, user.id));
    revalidatePath("/settings");
    return { success: true };
  }
  ```

### 3. Leaf Client Components Only
- Only mark leaf elements requiring browser APIs, local state (`useState`), or event handlers (`onClick`) with `'use client'`. Never mark page layouts or top-level route wrappers as client components.

## 6. What We DON'T Do (and Why)

- ❌ **No Client-Side Direct DB Queries**: Never import `@/lib/db` into a file marked `'use client'`. Next.js build will fail or expose credentials.
- ❌ **No `useEffect` for Primary Data Fetching**: Causes network waterfalls, layout shift, and SEO degradation. Use React Server Components and React Suspense boundaries instead.
- ❌ **No Prisma with Serverless SQLite**: Prisma's binary engine introduces 300ms–800ms cold starts. Drizzle ORM has zero binary dependencies and executes queries in <1ms.
- ❌ **No Storing Unbounded Blobs in SQLite**: Store files (avatars, attachments) in an S3-compatible object store (Cloudflare R2 / AWS S3) and store only the public URL or object key in SQLite.
- ❌ **No Raw SQL Strings Without Parametrization**: Always use Drizzle query builders or `sql` tagged template literals to guarantee 100% protection against SQL injection.
- ❌ **No `any` Types in TypeScript**: Use `unknown` with Zod type narrowing or generate types directly from Drizzle schemas (`typeof users.$inferSelect`, `typeof users.$inferInsert`).
