# CLAUDE.md — Next.js 15 App Router + SQLite SaaS

This file defines non-negotiable architectural standards for this codebase. Every rule has a concrete operational reason; do not override without explicit approval.

---

## 1. Stack & Pinned Versions
- **Runtime:** Node.js 22 LTS (native `--test` runner and Web Crypto support; avoids polyfill bloat).
- **Framework:** Next.js `15.x` (App Router, React 19, Server Actions). Never mix `pages/` router files into `src/app/`.
- **Language:** TypeScript `5.x` with `"strict": true` and `"noUncheckedIndexedAccess": true` (catches null/undefined indexing bugs at compile time before runtime).
- **Database:** SQLite via `better-sqlite3` (`11.x`, single-node VPS/Fly volume) or `@libsql/client` (Turso edge replicas), wrapped with Drizzle ORM (`drizzle-orm` + `drizzle-kit`). Do **not** pull in Prisma's Rust query engine binary for SQLite—`better-sqlite3` gives synchronous, zero-IPC in-process reads with ~10x lower tail latency.
- **Validation:** `zod` for all request bodies, Server Action `FormData`, searchParams, and environment variables.
- **Auth / Sessions:** HTTP-only signed/database-backed cookies (`oslo` / `jose`), never `localStorage` tokens (prevents XSS token exfiltration and keeps SSR consistent).

## 2. Folder Structure
```text
src/
  app/                  # Next.js App Router segments ONLY (pages, layouts, route handlers)
    (marketing)/        # Unauthenticated public routes
    (app)/              # Authenticated dashboard routes
    api/webhooks/       # External signed webhooks ONLY (Stripe, Resend, etc.)
  server/
    db/
      schema.ts         # Drizzle SQLite tables & relations
      migrations/       # Committed SQL migration files (generated by drizzle-kit)
      index.ts          # Singleton DB connection + WAL/foreign_keys pragmas
    dal/                # Data Access Layer (auth-checked queries & mutations)
    actions/            # Next.js Server Actions ("use server") calling DAL
  lib/
    env.ts              # Zod-validated process.env parser (fails fast at boot)
    errors.ts           # Typed Result<T, E> & domain error classes
  components/
    ui/                 # Pure presentational components (zero DB imports)
```
**Why:** Strict separation prevents Client Components from accidentally importing `better-sqlite3` (native C++ addon fails webpack bundling) and concentrates every authorization check inside `server/dal/`.

## 3. SQLite & Migration Rules
1. **Enable WAL & Foreign Keys at startup (`src/server/db/index.ts`):**
   ```ts
   db.pragma("journal_mode = WAL");
   db.pragma("busy_timeout = 5000");
   db.pragma("foreign_keys = ON");
   ```
   *Reason:* Default SQLite rollback journal locks readers during writes and silently ignores `FOREIGN KEY` constraints unless enabled per connection.
2. **Every timestamp is INTEGER Unix epoch milliseconds (or ISO-8601 UTC TEXT).** Never mix formats across tables.
3. **Never write raw `drizzle-kit push` against production.** Always generate versioned SQL files via `npm run db:generate` and apply forward-only migrations via `npm run db:migrate`.
4. **Transactions for multi-row invariants:** Wrap balance transfers, credit deductions, and webhook idempotency ledger writes in `db.transaction(() => { ... })`. Never perform check-then-act across separate queries (prevents TOCTOU double-spend races).
5. **Parameterized queries only:** Never interpolate user variables into `sql.raw()`.

## 4. Coding Patterns & Anti-Patterns

### DO
- **Validate + Authenticate inside every Server Action & DAL call:** Treat Server Actions as public HTTP POST endpoints. Always call `const user = await requireSession()` and `schema.parse(input)` first.
- **Co-locate `loading.tsx` and `error.tsx` per route group** so slow queries isolate to a segment rather than crashing the root shell.
- **Return `{ ok: true, data } | { ok: false, error }` from Server Actions** instead of throwing expected validation errors (Next.js strips thrown error messages in production builds).
- **Use `import "server-only"`** at the top of `src/server/db/index.ts` and every `src/server/dal/*.ts` module.

### DO NOT (Anti-Patterns)
- **NEVER expose internal DB IDs as sequential integers** in public URLs (`/invoices/42` leaks tenant volume and invites IDOR enumeration). Use `crypto.randomUUID()` / ULIDs as public identifiers.
- **NEVER call internal API routes from Server Components (`fetch("/api/...")`)**: Call `src/server/dal/*` directly in the Server Component to avoid extra network hops and cookie-forwarding bugs.
- **NEVER trust client-supplied `userId` or `orgId`:** Derive tenant ownership strictly from the verified server session + membership join.
- **NEVER commit `.sqlite`, `.db-wal`, or `.env` files.**

## 5. Standard Commands
```bash
npm run dev            # Next.js dev server (Turbopack)
npm run typecheck      # tsc --noEmit (must pass 0 errors before commit)
npm run lint           # eslint --max-warnings 0
npm run db:generate    # Generate SQLite migration from server/db/schema.ts
npm run db:migrate     # Apply pending migrations safely
npm test               # Run unit & integration tests (isolated tmp SQLite file)
```

## 6. Verification Checklist Before Any PR
1. `npm run typecheck` exits `0`.
2. Any new table has an indexed `created_at` / foreign key column and a generated SQL migration.
3. Every new Server Action or Route Handler validates input with Zod and checks tenant authorization in the DAL.
