# CLAUDE.md — Next.js 15 + SQLite SaaS Architecture Guide

This document is the authoritative developer guide and context reference for Claude Code working on this production SaaS repository.

---

## 1. Core Stack & Versions

- **Framework**: Next.js 15 (App Router, React 19, Turbopack enabled)
- **Language**: TypeScript 5.6+ (Strict mode: `strict: true`, `noImplicitAny: true`)
- **Database**: SQLite (embedded `better-sqlite3` for local development, Turso / `@libsql/client` for serverless production)
- **ORM / Query Builder**: Drizzle ORM (`drizzle-orm` + `drizzle-kit`)
- **Authentication**: Auth.js / Lucia Auth (Session tokens stored in SQLite sessions table)
- **Validation**: Zod 3.23+ (Strict schema validation for all Server Actions and route handlers)
- **Styling**: Tailwind CSS v4 + Radix UI Primitives / `shadcn/ui`
- **Icons**: `lucide-react`

## 3. SQLite & Database Conventions

### A. Connection Pragmas (Mandatory)
Every SQLite connection initialization in `src/db/client.ts` **must** execute:
```sql
PRAGMA journal_mode = WAL;        -- Enables concurrent readers and fast writes
PRAGMA foreign_keys = ON;         -- Enforces relational integrity across tables
PRAGMA busy_timeout = 5000;       -- Prevents immediate SQLITE_BUSY lock errors
PRAGMA synchronous = NORMAL;      -- Optimal balance of durability and write throughput
```

### B. Migration Rules
1. Never edit existing applied migration files.
2. All schema modifications require generating a new migration:
   ```bash
   npm run db:generate
   npm run db:migrate
   ```
3. Always provide default values or nullable types when adding new columns to existing tables.
4. Foreign keys must specify explicit `onDelete: 'cascade'` or `onDelete: 'restrict'`.

## 4. Component & Server Action Patterns

### A. Server Components by Default
- All pages and components in `src/app/` are **React Server Components (RSC)** by default.
- Fetch data directly in Server Components using async/await without `useEffect`.
- Only add `'use client'` at the leaf component level when interactive state (`useState`), event handlers (`onClick`), or browser APIs are required.

### B. Server Actions with Zod Validation
All mutations must follow this standard pattern:
```typescript
'use server';

import { z } from 'zod';
import { db } from '@/db/client';
import { requireAuth } from '@/lib/auth';

const UpdateProfileSchema = z.object({
  name: z.string().trim().min(2).max(100),
  email: z.string().email(),
});

export async function updateProfileAction(formData: FormData) {
  const user = await requireAuth();
  
  const parsed = UpdateProfileSchema.safeParse({
    name: formData.get('name'),
    email: formData.get('email'),
  });

  if (!parsed.success) {
    return { success: false, errors: parsed.error.flatten().fieldErrors };
  }

  await db.update(users).set(parsed.data).where(eq(users.id, user.id));
  return { success: true };
}
```

## 5. What We DO NOT Do (And Why)

1. **DO NOT use raw SQL string interpolation**:
   - *Why*: Prevents SQL injection vulnerabilities. Always use Drizzle query builder or parameterized statements.
2. **DO NOT use `useEffect` for data fetching**:
   - *Why*: Causes waterfalls and layout shifts. Fetch directly in Server Components or use React Cache.
3. **DO NOT import server-only code (DB client, secrets) into Client Components**:
   - *Why*: Bundles secrets to the browser and causes build failures. Keep sensitive imports in `src/db/` or `src/lib/actions/`.
4. **DO NOT store plaintext passwords or API keys in SQLite**:
   - *Why*: Always hash credentials using Argon2id or bcrypt with appropriate work factors.
5. **DO NOT bypass foreign key constraints**:
   - *Why*: SQLite ignores foreign keys by default unless `PRAGMA foreign_keys = ON;` is explicitly set on every connection.

## 6. Development Commands

```bash
npm run dev          # Start Next.js development server with Turbopack
npm run build        # Type-check and create production build
npm run db:generate  # Generate migration from schema diff
npm run db:migrate   # Apply pending migrations to SQLite database
```
