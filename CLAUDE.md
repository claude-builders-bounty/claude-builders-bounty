# CLAUDE.md — Next.js 15 + SQLite SaaS Project

## Stack

- **Framework**: Next.js 15 (App Router, Turbopack dev)
- **Database**: SQLite via better-sqlite3 (never Turso for single-region)
- **ORM**: Drizzle ORM (not Prisma — see anti-patterns)
- **Auth**: NextAuth v5 (Auth.js) with Drizzle adapter
- **UI**: shadcn/ui + Tailwind CSS v4
- **Forms**: react-hook-form + zod
- **Payments**: Stripe (webhooks → Drizzle upsert)
- **Hosting**: Vercel (serverless — see limits below)

## Project Structure

```
│   └── forms/              # react-hook-form wrappers
├── db/
│   ├── schema/             # Drizzle schema files (one per domain)
│   │   ├── users.ts
│   │   ├── teams.ts
│   │   └── subscriptions.ts
│   ├── migrations/         # Auto-generated by drizzle-kit
│   └── index.ts            # DB client singleton
├── lib/
│   ├── auth.ts             # NextAuth config
│   ├── stripe.ts           # Stripe client wrapper
│   ├── email.ts            # Resend / React Email

```

**Why this layout**: Flat is better than nested. `app/` is Next.js routing (don't fight it). `db/` is separate because Drizzle is not coupled to Next.js. `actions/` mirrors the old `lib/actions` but keeps route handlers clean.

## SQL / Migration Rules

1. **Always use Drizzle ORM** — never raw SQL except for full-text search or migrations.
2. **One migration per schema change** — `drizzle-kit generate` then `drizzle-kit migrate`. Never edit migration files manually.
3. **Foreign keys are explicit** in schema. Drizzle infers relations from references.
4. **Timestamps are `integer` (Unix ms)** — NOT SQLite datetime text. JS `Date.now()` everywhere.
5. **Soft deletes** via `deletedAt: integer` column. Filters added as Drizzle `where` helper.
6. **Index every foreign key** and any column used in `WHERE` clauses. Use `drizzle-kit push` for dev only.
7. **No migrations on Vercel** — run `drizzle-kit migrate` in CI/CD pipeline script:

```json
// package.json
"db:migrate": "drizzle-kit migrate",
"db:generate": "drizzle-kit generate"
```

## Component Patterns

1. **Server Components by default** — only add `"use client"` when you need browser APIs, state, or event handlers.
2. **Page = Server Component** that fetches data and passes props to client islands.
3. **Forms** → Server Actions with `useActionState`. Never client-side form handlers.
4. **Revalidation** → `revalidatePath()` or `revalidateTag()` in the Server Action. Never `router.refresh()`.
5. **Shared UI** → shadcn/ui registry. Custom components go in `components/`.
6. **Error boundaries** → one `error.tsx` per route segment. Always log via `console.error()`.

## Auth Convention

- NextAuth callbacks in `lib/auth.ts` only.
- `auth()` helper returns `session | null`. Use in layout.tsx for gate logic.
- Middleware in `src/middleware.ts` — protect routes via `matcher` config, not inline checks.
- Webhook auth → verify Stripe signature, verify Resend webhook secret. No session cookies.

## Anti-Patterns (Why)

| Don't | Why |
|-------|-----|
| Prisma + SQLite | Prisma's edge adapter is buggy with SQLite in serverless. Drizzle is 2x faster, 10x smaller bundle. |
| Pages Router | App Router is production-ready in Next.js 15. Don't mix. |
| .env.local committed | Vercel env vars > local files. Use `vc env pull`. |
| Nested `page.tsx` beyond 3 levels | Component should carry complexity, not the file tree. |
| `useEffect` for data fetching | Server Actions + `revalidatePath()` or `use()` with Suspense. |
| Catch-all API routes | Each API route is one file. If it has switches, extract to a lib function. |

## Performance Rules

- `dynamic = 'force-static'` for marketing pages.
- `dynamic = 'force-dynamic'` for dashboard (SQLite is fast enough).
- Images: `next/image` with WebP, sizes attribute, blur placeholder.
- DB queries: use Drizzle `prepare()` for hot paths.
- Avoid: `'use client'` on entire pages. Leak only the interactive parts.

## What We Don't Do

- **No Redis** — SQLite handles session cache. Add Redis only if measured >50ms P99.
- **No tRPC** — Server Actions replace tRPC for mutating. Route handlers replace it for external APIs.
- **No Zustand/Redux** — `useState` + URL search params + Server Actions cover 99% of state needs.
- **No Docker** for local dev — SQLite file is simpler.
- **No microservices** — Squint until the team is 10+ engineers.
