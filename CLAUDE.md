# CLAUDE.md — Next.js 15 + SQLite SaaS Template

## Stack & Versions

- **Framework**: Next.js 15 (App Router, React 19, `next@15`)
- **Database**: SQLite via `better-sqlite3` (production) + `libsql` (Turso-compatible for edge)
- **ORM**: Drizzle ORM (`drizzle-orm`, `drizzle-kit`)
- **Auth**: Lucia v3 (`lucia-auth`) with SQLite adapter
- **Validation**: Zod (server) + `react-hook-form` + `@hookform/resolvers` (client)
- **Styling**: Tailwind CSS v4 + `tailwind-merge` + `clsx`
- **Payments**: Stripe (`stripe` SDK + webhooks)
- **Task Queue**: In-process via `p-queue` (no Redis needed at small scale)

## SQL / Migration Conventions

### DO
- **One migration per schema change.** Run `npx drizzle-kit generate:sqlite` after every schema edit.
- **Always wrap schema changes in transactions.** Drizzle generates migration files as transactions by default — never manually split them.
- **Add `index()` for any column used in `WHERE` or `ORDER BY`** — SQLite has no query planner magic.
- **Use `text()` for IDs**, not `integer()` — UUIDs avoid enumeration attacks and simplify data migration.
- **Prefer `integer` booleans** (`0`/`1`) over actual boolean columns — SQLite stores them identically but querying is faster with integers.
- **Add `notNull().default()` for every boolean** — never allow NULL where a boolean is expected.

### DON'T
- **Don't use foreign key constraints in SQLite.** They hurt write performance and Drizzle handles relational integrity in application code. If you must, enable `PRAGMA foreign_keys = ON` and document why.
- **Don't cascade deletes in the schema** — use application-level cascading via Server Actions so you can log/audit.
- **Don't alter existing migrations** — always create a new one. `drizzle-kit` will diff correctly.

## Component Patterns

### Server Components First
- Every page and API route is a **Server Component** by default.
- Only add `'use client'` when you need: `useState`, `useEffect`, `onClick`, browser APIs, or context.

### Data Fetching
- Use **Server Actions** (`'use server'` in `src/actions/`) for mutations.
- Use **React `cache()`** for deduplicated server-side data fetching — NOT `fetch()` directly.
- Example:
```ts
import { cache } from 'react'
import { db } from '@/db'
import { projects } from '@/db/schema/projects'
import { eq } from 'drizzle-orm'

export const getProject = cache(async (id: string) => {
  return db.select().from(projects).where(eq(projects.id, id)).get()
})
```

### Forms
- Server Actions call Zod validation → return `{ success, error, data }` shape.
- Client forms call Server Actions via `useActionState` (React 19). **No `react-query`** — unnecessary weight.

### Error Boundaries
- Every route group gets an `error.tsx` and `loading.tsx`.
- API routes wrap in `try/catch` and return `{ error: string }` — never throw HTTP 500 raw.

## What We Don't Do (And Why)

| Thing | Why Not |
|-------|---------|
| **Redis / BullMQ** | Too heavy for a SQLite-backed SaaS. In-process `p-queue` handles webhook ordering correctly at <10k users. |
| **Prisma** | Drizzle is faster, has better SQLite support, and generates smaller bundles. Prisma's SQLite adapter is experimental. |
| **`pages/api` routes** | Next.js 15 App Router has been stable for over a year. Route handlers are simpler and tree-shakeable. |
| **Environment variables for secrets at runtime** | Use `next.config.ts` `env` block or `@next/env` at build time. Runtime `process.env` in browser gets inlined. |
| **`react-query` / TanStack Query** | Server Actions + React `cache()` + `useActionState` cover 95% of data needs. Skip the 20KB dependency. |
| **CSS Modules** | Tailwind CSS v4 + `tailwind-merge` is faster to write, consistent, and removes naming debates. |

## Dev Commands

```bash
# Start dev server
pnpm dev

# Generate & apply migration
npx drizzle-kit generate:sqlite     # creates migration file
npx drizzle-kit migrate:sqlite       # applies pending migrations

# Seed database
pnpm db:seed

# Run tests
pnpm test

# Type-check
pnpm typecheck
```

## Migration Workflow

1. Edit schema in `src/db/schema/*.ts`
2. Run `npx drizzle-kit generate:sqlite` → new migration in `src/db/migrations/`
3. Run `npx drizzle-kit migrate:sqlite` → applies to local SQLite file
4. Commit both schema AND migration file together
5. Never edit a migration file after commit

> **Why?** Migration files are append-only. Editing one after it's been applied to any environment (including a teammate's dev DB) creates unrecoverable drift.
