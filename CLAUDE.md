# CLAUDE.md — Next.js 15 + SQLite SaaS

## Stack & Versions

| Layer | Choice | Rationale |
|---|---|---|
| Framework | Next.js 15 (App Router) | React Server Components by default, built-in streaming, server actions |
| Language | TypeScript 5.x (strict) | Catch category errors at build, not runtime |
| Database | SQLite via better-sqlite3 (dev) / Turso libsql (prod) | Zero-config local dev, edge-compatible in production |
| ORM | Drizzle ORM | SQL-like syntax, tree-shakeable, excellent SQLite support |
| Validation | Zod | Composable schemas, RSC-safe, TypeScript inference |
| Styling | Tailwind CSS v4 | Utility-first, no runtime, easy custom design system |
| Auth | Lucia v3 + better-sqlite3 adapter OR next-auth v5 SQLite adapter | Session-based, no JWTs for web apps |

## SQL / Migration Conventions

### Drizzle schema rules

```typescript
// ✅ CORRECT: explicit column types, singular table names
export const users = sqliteTable("users", {
  id: text("id").primaryKey(),
  email: text("email").notNull().unique(),
  name: text("name"),
  createdAt: integer("created_at", { mode: "timestamp" })
    .notNull()
    .default(sql`(unixepoch())`),
});

// ❌ AVOID: plural table names, implicit defaults
export const usersTable = sqliteTable("users_table", { ... });
```

### Migration workflow

```bash
# Generate migration from schema changes
bun drizzle-kit generate

# Apply migrations (dev)
bun run db:migrate

# One-way only. NEVER edit generated migration files manually.
# If you need to change a migration, create a new schema change.
```

## Component Patterns

### Server-first

```typescript
// ✅ CORRECT: server component by default
export default async function DashboardPage() {
  const teams = await db.select().from(teams).all();
  return <TeamList teams={teams} />;
}

// ❌ AVOID: use client unless you explicitly need interactivity
"use client";
```

### Client components are leaf nodes

```typescript
"use client";

// ✅ CORRECT: client component is a thin interactive leaf
export function DeleteTeamButton({ teamId }: { teamId: string }) {
  return (
    <form action={deleteTeamAction}>
      <input type="hidden" name="teamId" value={teamId} />
      <Button variant="destructive">Delete Team</Button>
    </form>
  );
}
```

### Data mutations go in Server Actions

```typescript
// ✅ CORRECT: actions/auth.actions.ts
"use server";

export async function signupAction(formData: FormData) {
  const data = signupSchema.parse({
    email: formData.get("email"),
    password: formData.get("password"),
  });

  const user = await db.insert(users).values({
    email: data.email,
    hashedPassword: await hash(data.password),
  }).returning();

  redirect("/dashboard");
}
```

### Forms use react-hook-form + Zod

```typescript
// ✅ CORRECT: client form with server action
export function SignupForm() {
  const form = useForm<z.infer<typeof signupSchema>>({
    resolver: zodResolver(signupSchema),
  });

  return (
    <form action={signupAction}>
      <Input {...form.register("email")} />
      {form.formState.errors.email && (
        <p className="text-red-500">{form.formState.errors.email.message}</p>
      )}
      <Button type="submit">Sign Up</Button>
    </form>
  );
}
```

## What We Don't Do (and Why)

| Anti-pattern | Why we avoid it |
|---|---|
| **Prisma** | Connection pooling is overengineered for SQLite; Drizzle's SQL-like API maps better to SQLite's feature set |
| **Pages Router** | App Router has been stable since Next.js 14; mixing routers creates confusion |
| **API Routes for mutations** | Server Actions handle mutations with zero boilerplate and work without JS enabled |
| **Redux / Zustand** | Server Components + URL state + React Context covers 99% of SaaS state needs |
| **Barrel exports** (`index.ts` re-exports) | Breaks tree-shaking, slows HMR, causes circular imports |
| **Styled-components / CSS-in-JS** | RSC-incompatible; Tailwind + CSS Modules solve the same problems without runtime cost |
| **Separate API server** | Next.js Route Handlers + Server Actions serve double duty; splitting adds deployment complexity for no benefit |
| **Raw SQL in components** | Every query goes through Drizzle or a named action function — keeps the query layer auditable and testable |

## Naming Conventions

| What | Convention | Example |
|---|---|---|
| Files | kebab-case | `team-settings.tsx` |
| Components | PascalCase | `TeamSettings` |
| Functions | camelCase | `fetchTeamMembers` |
| Server Actions | camelCase + Action suffix | `inviteMemberAction` |
| Database tables | snake_case, plural | `team_members` |
| Database columns | snake_case | `created_at` |
| Types/Interfaces | PascalCase, no prefix | `TeamMember` |
| Environment variables | UPPER_SNAKE_CASE | `DATABASE_URL` |
| CSS classes | Tailwind utility classes | No custom CSS classes by default |

## Tailwind Conventions

Use the built-in Tailwind design tokens. Avoid arbitrary values (`w-[372px]`) unless absolutely necessary.

```typescript
// ✅ CORRECT: use design tokens
<div className="p-4 sm:p-6 lg:p-8" />

// ❌ AVOID: arbitrary values without a reason
<div className="p-[18px]" />
```

Theme colors go in `tailwind.config.ts` and follow this naming:

```typescript
colors: {
  brand: {
    50:  "#f0f9ff",
    500: "#3b82f6",
    900: "#1e3a5f",
  },
}
```
