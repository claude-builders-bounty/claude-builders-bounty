# CLAUDE.md — Next.js 15 + SQLite SaaS Project

## Stack & Versions
- **Next.js 15** with App Router (server-first, React Server Components)
- **SQLite** via `better-sqlite3` (local development) / Turso (production edge)
- **Drizzle ORM** with Drizzle Kit for migrations
- **Zod** for schema validation (both client and server)
- **shadcn/ui** for component library
- **Tailwind CSS v4** for styling
- **NextAuth.js v5** for authentication (Auth.js)
- **tRPC** (optional, if API routes needed) — prefer Server Actions for mutations

## Naming Conventions
- **Files & Folders**: `kebab-case` (e.g., `user-avatar.tsx`, `api/route.ts`)
- **Components**: PascalCase for component names and files (e.g., `UserAvatar.tsx`)
- **Database schemas**: PascalCase for table names (e.g., `users`, `subscriptions`)
- **Zod schemas**: PascalCase with `Schema` suffix (e.g., `CreateUserSchema`)
- **Types/interfaces**: PascalCase with no prefix (e.g., `User`)
- **Environment variables**: `UPPER_SNAKE_CASE` (e.g., `DATABASE_URL`, `AUTH_SECRET`)

## Database & Migration Rules
- **Always use Drizzle ORM** — no raw SQL in application code (exception: raw SQL in migrations if needed)
- **Migrations generated via `drizzle-kit generate`** — never write by hand
- **Migration naming**: `YYYYMMDDHHMMSS_description.ts` (auto-generated)
- **Run migrations only in development** — for production, use CI/CD to apply via `drizzle-kit migrate`
- **Seed scripts** go in `scripts/seed.ts` using Drizzle's `insert`
- **Relationships**: use Drizzle's `relations` functionality for type-safe joins
- **Indexes**: add indexes for foreign keys and frequently queried columns
- **SQLite specifics**:
  - Use `integer` for `id` (auto-increment) or `text` for UUIDs
  - Timestamp columns: `createdAt` (default `sql`)
  - Avoid `ENUM` — use `text` with check constraint or a string union in Zod

## Dev Commands
- `pnpm dev` — start dev server
- `pnpm build` — production build
- `pnpm lint` — ESLint + Prettier
- `pnpm db:generate` — `drizzle-kit generate`
- `pnpm db:migrate` — `drizzle-kit migrate`
- `pnpm db:push` — `drizzle-kit push` (for prototyping, skip migrations)
- `pnpm db:seed` — run seed script
- `pnpm test` — Vitest + Playwright (if configured)

## Component Patterns
- **Server Components by default** — only use client components when needed (`use client`)
- **Data fetching** in Server Components (direct `db.query()` calls) — never in client components
- **Client components** for interactivity: forms, UI state, contexts (`useState`, `useRef`, `useEffect`)
- **Form handling**: React Server Actions with Zod validation (no separate API routes for mutations)
- **Error boundaries**: use `error.tsx` and `loading.tsx` files in route segments
- **Composition**: small, focused components; prefer composition over props drilling
- **Styling**: Tailwind utility classes; avoid custom CSS unless absolutely necessary

## What We Don't Do (Anti-Patterns)
- ❌ **No `fetch` in client components** — data fetching belongs in server components or Server Actions
- ❌ **No raw SQL** in application code — always use Drizzle queries
- ❌ **No `useEffect` for data fetching** — use React Query (`@tanstack/react-query`) for client-side data needs (rare)
- ❌ **No `any` types** — strict TypeScript; use `unknown` if necessary
- ❌ **No barrel files** (index.ts re-exports) — import directly from file path to avoid circular deps
- ❌ **No global state management** (Redux, Zustand) — use URL state, React Context for themes/auth, or `useSearchParams`
- ❌ **No direct mutation of database in components** — always use Server Actions or API routes
- ❌ **No page-level `getServerSideProps`** — use async Server Components instead

## General Rules
- **Every new feature starts with a Zod schema** (validates input at the boundary)
- **Environment variables validated at build time** using `@t3-oss/env-nextjs`
- **Auth**: protect routes via `middleware.ts` + the `auth()` helper from NextAuth.js
- **API rate limiting**: use `@upstash/ratelimit` (Turso + Upstash) for production
- **Logging**: `pino` for server-side; no console.log in production
- **Commit messages**: `conventional commits` (feat:, fix:, chore:, etc.)

> This project uses `pnpm` as package manager. All scripts assume `pnpm`. Do not use `npm` or `yarn`.
