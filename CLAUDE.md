# CLAUDE.md — Next.js 15 + SQLite SaaS Template

## Stack & Versions

- **Framework**: Next.js 15+ (App Router — no `/pages` directory)
- **Language**: TypeScript 5.7+ (strict mode, no `any`)
- **Database**: SQLite via Turso (production) / better-sqlite3 (development)
- **ORM**: Drizzle ORM 0.41+ (zero-runtime, type-safe SQL generation)
- **Auth**: NextAuth.js v5 (Auth.js) with Drizzle adapter
- **UI**: shadcn/ui + Tailwind CSS v4 + Radix primitives
- **Forms**: React Hook Form + Zod schemas
- **Payments**: Stripe (webhook-driven, server-side)
- **Tests**: Vitest (unit) + Playwright (E2E) + Drizzle test helpers (integration)
- **Package Manager**: pnpm — never use npm or yarn

Pin exact versions for devDependencies; allow minor bumps for dependencies with `^`.

## Database Migration Rules

1. **NEVER edit migration files directly.** Migrations are generated by Drizzle Kit.
2. **Migration workflow:**
   ```
   pnpm db:generate    # Generate migration from schema changes
   pnpm db:migrate     # Apply pending migrations
   pnpm db:push        # Push schema directly (dev only, never in prod)
   ```
3. **Schema files**: One file per domain entity. `User.ts`, `Team.ts`, `Subscription.ts`, `ApiKey.ts`, `AuditLog.ts`.
4. **Relations**: Define in a separate `relations.ts` file per domain.
5. **Timestamps**: Every table MUST have `createdAt` and `updatedAt` (use Drizzle's `sql` helper for defaults).
6. **Soft deletes**: Use `deletedAt: timestamp()` instead of hard `DELETE`. Add `where: isNull(deletedAt)` to all queries.
7. **Indexes**: Index foreign keys, `email`, `slug`, `userId`, `teamId`.
8. **Avoid SQLite pitfalls**:
   - No `ALTER COLUMN` — create new column, migrate data, drop old
   - No `ENUM` — use `text()` with Zod validation
   - No `BOOLEAN` — use `integer()` with `0`/`1`
   - No JSON functions inside transactions on Turso (HTTP limitation)

### SQL Query Patterns

```typescript
// GOOD: Use Drizzle query builder
const user = await db.query.User.findFirst({
  where: eq(User.email, email),
  with: { subscriptions: true },
})

// BAD: Raw SQL unless Drizzle can't express it
const user = await db.run(sql`SELECT * FROM user WHERE email = ${email}`)

// GOOD: Transaction pattern
await db.transaction(async (tx) => {
  await tx.insert(User).values({ email })
  await tx.insert(AuditLog).values({ action: 'user.created' })
})

// GOOD: Paginated list with cursor
const items = await db.query.Item.findMany({
  where: gt(Item.id, cursor),
  limit: 20,
  orderBy: desc(Item.createdAt),
})
```

## What We DON'T Do (And Why)

1. **No Redux / Zustand / Jotai.** Server Components + Server Actions eliminate 90% of client state needs. The remaining 10% (auth session, UI state) is handled by cookies or URL search params.

2. **No `useEffect` for data fetching.** Server Components fetch on the server. `useEffect` for data means loading spinners, waterfall requests, and stale data. Server Actions handle mutations.

3. **No API routes for our own frontend.** Server Actions call the database directly. API routes are for: webhooks (Stripe), public endpoints, and third-party integrations.

4. **No barrel exports (`index.ts` re-exports).** They cause circular dependency issues, confuse Vercel's tree-shaking, and make finding imports harder. Import from the actual file.

5. **No `.env.local` in production.** Secrets go in the platform's environment variable manager (Vercel, Fly.io, etc.).

6. **No relative paths past 2 levels deep.** Use TypeScript path aliases (`@/components/ui/button`).

7. **No Drizzle `$inferSelect` or `$inferInsert` at module scope.** They generate types eagerly at import time. Use manual type aliases or `Pick<>` from the schema for public interfaces.

8. **No WAL mode on serverless SQLite.** WAL mode requires file-system access. Use `DELETE` mode on Turso/HuggingFace. WAL is fine for local dev.

## Component Patterns

**Rules:**
1. **Server Components by default.** Only add `"use client"` when you need: `useState`, `useEffect`, browser APIs, event handlers, or `useContext` of a client provider.
2. **One component per file.** No exceptions. Named exports only (no default exports).
3. **Props interface defined above the component**, same file, prefixed: `interface UserAvatarProps`.
4. **No prop drilling past 2 levels.** Use Server Components + async data fetching or a lightweight context.
5. **Data fetching**: Use Server Components + `async` directly. No `useEffect` fetching, no SWR, no React Query.
6. **Mutations only via Server Actions.** Forms use `useActionState` + Server Actions.
7. **Error boundaries**: Each major route section gets a `error.tsx` and `loading.tsx`.
