# Project: Next.js 15 + SQLite SaaS

You are working on a SaaS application built with Next.js 15 (App Router) and SQLite.

## Stack & Versions

- **Runtime**: Node.js 20+ with Next.js 15 (App Router, not Pages Router)
- **Language**: TypeScript 5.x (strict mode, `noUncheckedIndexedAccess: true`)
- **Database**: SQLite via `better-sqlite3` (local) or Turso (`@libsql/client`) — pick one
- **ORM**: Drizzle ORM (`drizzle-orm`, `drizzle-kit`) — no Prisma, no Sequelize, no TypeORM
- **Auth**: NextAuth.js v5 (`next-auth@beta`) with Drizzle adapter — or Lucia v3
- **Styling**: Tailwind CSS 4.x (CSS-first, `@import "tailwindcss"`)
- **Validation**: Zod v4 schemas in `lib/validators/`
- **Testing**: Vitest (unit) + Playwright (e2e) — React Testing Library optional
- **Forms**: `react-hook-form` + `@hookform/resolvers/zod` on client; Server Actions on server
- **Email**: Resend or Nodemailer via `nodemailer`
- **Deployment**: Vercel (recommended) or Docker on Fly.io/Railway

## SQL / Migration Rules

- **Never edit migration files** — they are generated by `drizzle-kit generate`. Modify `schema.ts` and regenerate.
- **Always use parameterized queries** — raw SQL only through Drizzle's `sql` template tag.
- **Every table** must have: `id` (text, PK, `nanoid()`), `created_at` (integer, unix ms), `updated_at` (integer, unix ms, auto-update via trigger).
- **Foreign keys** use `ON DELETE CASCADE` for dependent records; `SET NULL` for optional relations.
- **Indexes** on columns used in `WHERE`, `JOIN`, and foreign keys — add via `index()` in schema.
- **Seed data** goes in `db/seed.ts`, runnable via `npm run db:seed` (idempotent).
- **No ORM magic methods** — prefer explicit selects. Use `db.select().from(users).where(eq(users.id, id))` not query builders with implicit joins.
- **Transactions** for multi-table writes: `await db.transaction(async (tx) => { ... })`.

## Component Patterns

### Server Components (default)

- All components in `app/` are Server Components by default — no `"use client"` unless needed.
- Fetch data directly in Server Components via `db` or Server Actions — no `useEffect` for data fetching.
- Pass server data to Client Components via props; avoid prop drilling with Context only for truly global state (theme, auth).

### Client Components

- Only mark `"use client"` when you need: interactivity (state, effects), browser APIs, or event handlers.
- Keep Client Components small — move data fetching to the parent Server Component.
- Put Client Components in `components/`, never in `app/` route folders.

### Forms

- Use **Server Actions** for form submissions, not API routes.
- Validate with Zod on the server side (in the Action). Client-side validation via RHF is UX only.
- Show validation errors inline next to fields, not as toast messages.
- Return `{ success: true, data } | { success: false, error: string, fieldErrors?: Record<string, string> }`.

### Data Fetching & Caching

- Prefer Server Components + `db.select()` over API routes.
- Use `unstable_cache()` from `next/cache` for expensive queries (keys: `['users', userId]`).
- Use `revalidatePath()` or `revalidateTag()` for cache invalidation after mutations.
- **Never** use `fetch()` in Client Components for internal data.

## What We Don't Do (and Why)

| Anti-pattern | Reason |
| ------------ | ------ |
| `useEffect` for data fetching | Causes waterfalls, loading states, race conditions. Use Server Components. |
| `fetch` in Client Components | Couples rendering to network. Fetch in Server Components, pass as props. |
| Prisma | Heavy binary, slow cold starts with SQLite, poor App Router integration. Drizzle is lighter and type-safe. |
| `pages/` router | Legacy. App Router is the standard since Next.js 13. |
| Barrel exports (`index.ts` re-exporting multiple modules) | Hurts tree-shaking. Import directly from source files. **Exception**: single-purpose entrypoints like `src/db/index.ts` (exports only DB client) or `src/lib/validators/index.ts` (exports all schemas) are OK. |
| `any` type | Defeats TypeScript. Use `unknown` and narrow with Zod. |
| Inline styles / `style={{}}` | Use Tailwind utility classes. Consistent, themeable, no runtime cost. |
| Global state (Redux, Zustand) for server data | The server is the source of truth. Use Server Components + URL state (search params). |
| Putting business logic in `page.tsx` | Page files are thin. Logic goes in `actions/`, `lib/`, `db/queries/`. |
| `try/catch` in Server Actions for control flow | Return `{ success: false, error }` instead. Reserve `try/catch` for unexpected errors. |
| `console.log` in production code | Use `lib/logger.ts` (pino or consola) with level-based output. |

## Auth Pattern (NextAuth.js v5)

- **Session stored in SQLite** via Drizzle adapter (`@auth/drizzle-adapter`).
- **Middleware** (`middleware.ts`) handles redirects: unauthenticated → `/login`, authenticated away from auth pages → `/dashboard`.
- **Server-side session access**: Use `auth()` helper (v5) — returns `Promise<Session | null>`.

```ts
// In Server Component or Server Action
const session = await auth()
if (!session?.user) redirect('/login')
```

- **Client-side**: Use `useSession()` from `next-auth/react`.
- **Never expose** user passwords, hashed passwords, or raw tokens to the client.
- **API routes / Server Actions** call `auth()` to verify session — never trust client-only guards.
- **Role-based access**: Check `session.user.role` in Server Actions/middleware.

## Error Handling

- **Route-level**: `error.tsx` in each route segment for caught errors (shows friendly UI, logs to console).
- **404s**: `not-found.tsx` in route segments + `notFound()` from `next/navigation`.
- **Loading**: `loading.tsx` for Suspense boundaries — prefer over manual spinners.
- **Server Actions**: Return `{ success: boolean, error?: string, fieldErrors?: Record<string, string> }` — **never throw** for expected failures.
- **Unexpected errors**: Log via `lib/logger.ts` (structured JSON in prod, pretty in dev).
- **Client errors**: Use `react-hot-toast` or `sonner` for toasts; show field errors inline on forms.

## Security Checklist

- All Server Actions validate input with Zod — no raw `request.formData()` without schema.
- CSRF protection via NextAuth (built-in) + SameSite cookies.
- Rate limiting on auth endpoints via `@upstash/ratelimit` or middleware.
- `Content-Security-Policy` header in `middleware.ts` (nonce-based for inline scripts).
- Secrets in `.env.local` (dev) / Vercel Environment Variables (prod) — never in repo.
- Dependency audit: `npm audit` in CI, `npm audit fix` for non-breaking updates.

## Database-Specific Notes

### better-sqlite3 (local file)

- Sync API, zero-config, great for dev + single-server deployments.
- Use `drizzle-orm/better-sqlite3` driver.
- Connection: `new Database('sqlite.db')` — enable WAL mode: `db.pragma('journal_mode = WAL')`.

### Turso (@libsql/client)

- HTTP-based, works on serverless/edge, syncs from primary.
- Use `drizzle-orm/libsql` driver.
- Connection: `createClient({ url: process.env.TURSO_DATABASE_URL!, authToken: process.env.TURSO_AUTH_TOKEN! })`.
- **Local dev**: `turso dev` creates local replica.
