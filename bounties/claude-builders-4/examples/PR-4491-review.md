### Summary

This PR adds an importable n8n workflow (`workflows/weekly-summary/workflow.json`) that fetches commits, closed issues, and merged PRs for the last 7 days, calls `claude-sonnet-4-20250514` to generate a narrative summary, and delivers it via Discord/Slack webhook with three configurable variables (`githubRepo`, `language`, `webhookUrl`). The change is focused (4 files, +182/-0) with a Friday 5pm cron trigger, a `Set Config` node, and supporting `README.md`/`EXECUTION.md` docs.

### Risks

- **No pagination — incomplete weekly data**: All three GitHub fetches use `per_page=100` with no `Link` header pagination. Any week with >100 commits or PRs silently drops data, and the Claude summary will be incomplete without warning (contrast with #4490 which pages correctly).
- **Merge node misconfiguration**: `Aggregate Weekly Data` uses `mode: combine` with empty `mergeByFields`, which in n8n merges by *position* not by key — if any of the three HTTP requests returns fewer items, the merged output can interleave incorrectly or drop branches under load.
- **No error handling for Anthropic/webhook failures**: The workflow has no `IF` or `Stop and Error` branches for 401/429 or empty Claude responses; a failed Claude call still proceeds to the webhook node with undefined `content`, producing a silent empty delivery.
- **Binary asset bloat**: `execution.png` is committed as a binary (43,397 bytes) with no `.gitattributes` — future screenshot updates will bloat the repo history.
- **Model pin may be stale**: `claude-sonnet-4-20250514` is pinned as required, but note #4490 documents retirement on 2026-06-15 — confirm maintainer still expects this exact string vs. successor `claude-sonnet-4-6`.

### Suggestions

- Add pagination handling (loop on `Link: <...>; rel="next"` or use n8n's pagination option) for all three GitHub HTTP Request nodes; or document the 100-item limit as a known constraint.
- Filter `issues` to exclude PRs (`pull_request` field) and filter `pulls` to `merged_at != null` with `since` cutoff — currently `pulls?state=closed` includes unmerged PRs, inflating the summary counts.
- Add credential validation / fallback: gate `Claude - Generate Summary` and `Deliver` with error branches that post a clear message instead of empty content; validate `webhookUrl` format before POST.
- Switch `execution.png` to a compressed artifact or host externally and link in `EXECUTION.md` to avoid binary churn; add `*.png` to `.gitattributes` with `filter=lfs` if binaries are required.
- Add a minimal local test harness (e.g., `node --test` against a fixture of synthetic GitHub responses) so reviewers can verify the workflow without a live n8n instance.
