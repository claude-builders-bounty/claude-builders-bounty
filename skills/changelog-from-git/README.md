# generate-changelog

A Claude Code **skill** + **bash script** that generates a structured `CHANGELOG.md` from a project's git history since the last tag, auto-categorized into Added / Fixed / Changed / Removed.

Submitted for [claude-builders-bounty issue #1](../../issues/1).

## Setup (3 steps)

1. **Copy the skill into your Claude Code skills folder** (so `/generate-changelog` works in any project):
   ```bash
   mkdir -p ~/.claude/skills/generate-changelog
   cp SKILL.md ~/.claude/skills/generate-changelog/
   ```
2. **Make the bash fallback executable** (so `bash changelog.sh` works without Claude):
   ```bash
   chmod +x changelog.sh
   ```
3. **Run it from any git repo**:
   ```bash
   /generate-changelog          # in Claude Code
   # or
   bash /path/to/changelog.sh   # standalone
   ```

That's it.

## What it does

- Reads `git log <last-tag>..HEAD`. If the repo has no tags, reads from the root commit.
- Categorizes each commit by its conventional-commit prefix:
  - `feat` / `feature` → **Added**
  - `fix` / `bugfix` / `hotfix` → **Fixed**
  - `perf`, `refactor`, `style`, `docs`, `ci`, `build`, `chore`, `test` → **Changed**
  - `revert`, `remove`, `delete`, `deprecate` → **Removed**
  - No prefix → **Changed**
  - `feat!:` or a `BREAKING CHANGE:` footer → tagged `**BREAKING:**`
- Prepends a new section to `CHANGELOG.md` (creates the file if missing, in Keep-a-Changelog format).
- Skips empty categories.
- Reports counts to stderr so a CI run sees them.

## Usage

```bash
bash changelog.sh                # uses [Unreleased] as the version header
bash changelog.sh 1.4.0          # uses [1.4.0]
bash changelog.sh --stdout       # prints the new section, doesn't touch CHANGELOG.md
bash changelog.sh -h             # help
```

In Claude Code:
```
/generate-changelog
/generate-changelog 1.4.0
```

## Why it's deterministic (no LLM in the categorization)

Bounty acceptance criteria asked for "auto-categorize." This implementation does it from commit prefixes, not from an LLM summarization pass. Reasons:

- **Reproducible:** same input → same output. Diff-review actually works.
- **Cheap:** no API calls, no rate limits, runs offline.
- **Honest:** if the team writes `chore: fix typo` it shows up under Changed, not Fixed. The fix for that is to write better commit messages, not to ask an LLM to guess.

The Claude Code `SKILL.md` route (vs the bash route) is provided so the skill is invocable from a Claude Code session where the user can also ask follow-up questions ("group by author too" / "exclude scope `(deps)`").
