# generate-changelog

Generate a structured `CHANGELOG.md` from a project's git history. Ships as
both a **Claude Code skill** (`SKILL.md`) and a standalone **bash script**
(`changelog.sh`) — use whichever fits your workflow.

Output follows the [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)
format, with commits grouped into `Added` / `Changed` / `Fixed` / `Removed`
sections based on conventional-commit prefixes (with a keyword fallback so
no commit is silently dropped).

## Setup (3 steps)

1. **Copy the folder** into your project (or clone this repo and use it
   directly):
   ```bash
   cp -r skills/generate-changelog /path/to/your/project/.claude/skills/
   chmod +x /path/to/your/project/.claude/skills/generate-changelog/changelog.sh
   ```
2. **Preview** the changelog for the commits since your last tag:
   ```bash
   bash .claude/skills/generate-changelog/changelog.sh --stdout
   ```
3. **Write** it to `CHANGELOG.md` (the script prepends a new section if the
   file already exists):
   ```bash
   bash .claude/skills/generate-changelog/changelog.sh
   ```

Inside Claude Code, the same skill is invokable as `/generate-changelog`.

## Options

```
bash changelog.sh [--from <ref>] [--to <ref>] [--version <label>]
                  [--output <file>] [--stdout]
```

| Flag         | Default                                            | Purpose                                                 |
|--------------|----------------------------------------------------|---------------------------------------------------------|
| `--from`     | last tag (`git describe --tags --abbrev=0`)        | Lower bound of the commit range.                        |
| `--to`       | `HEAD`                                             | Upper bound of the commit range.                        |
| `--version`  | the `--to` ref if it is a tag, else `Unreleased`   | Heading label for the new section.                      |
| `--output`   | `CHANGELOG.md`                                     | File to write or prepend to.                            |
| `--stdout`   | off                                                | Print the rendered changelog instead of writing a file. |

## Categorization

| Conventional-commit prefix | Section |
|---------------------------|---------|
| `feat`, `add`, `new`      | Added   |
| `fix`, `bugfix`, `hotfix`, `patch` | Fixed |
| `refactor`, `perf`, `change`, `update`, `chore`, `docs`, `style`, `build`, `ci`, `test`, `deps` | Changed |
| `remove`, `delete`, `revert`, `drop` | Removed |

Scopes (`feat(api):`) and breaking-change markers (`feat!:`) are stripped
before matching. Subjects without a recognizable prefix are bucketed by
keyword sniff; anything still ambiguous lands in `Changed`.

## Requirements

- `bash` ≥ 4 (for `mapfile`)
- `git`
- POSIX `sed`, `tr`, `date` — present on Linux, macOS, and Git Bash on
  Windows.
