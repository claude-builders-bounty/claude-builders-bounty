# generate-changelog

Produce or update a `CHANGELOG.md` for the current git repository in
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format. Commits since
the most recent tag are collected, categorized by conventional-commit type
(with a keyword fallback), and rendered into `Added`, `Changed`, `Fixed`,
`Removed` sections.

## When to use

Trigger this skill when the user:

- types the slash command `/generate-changelog`
- asks to "generate", "update", or "regenerate" a `CHANGELOG.md`
- asks to "summarize commits since the last tag/release"
- is preparing a release and needs release notes

## How it works

The skill ships a reference shell implementation at
`skills/generate-changelog/changelog.sh`. It is the source of truth for
categorization rules — when running the skill, **prefer invoking the script**
over reproducing its logic by hand, so output stays consistent across runs.

```
bash skills/generate-changelog/changelog.sh [--from <ref>] [--to <ref>] [--version <label>] [--output <file>] [--stdout]
```

Defaults:

- `--from` → output of `git describe --tags --abbrev=0`; if no tags exist,
  the full history is used.
- `--to` → `HEAD`.
- `--version` → the `--to` ref if it is a tag, otherwise `Unreleased`.
- `--output` → `CHANGELOG.md` (prepended in-place if it exists).

## Workflow

1. **Verify you are in a git repo** with at least one commit.
   ```bash
   git rev-parse --show-toplevel
   ```
2. **Preview** the changelog without touching files:
   ```bash
   bash skills/generate-changelog/changelog.sh --stdout
   ```
3. **Apply** to `CHANGELOG.md`:
   ```bash
   bash skills/generate-changelog/changelog.sh
   ```
   For a tagged release, pass `--version v1.2.0` (or first tag the release
   and rerun — the script auto-labels when `--to` is a tag).
4. **Review the diff** before committing. The script only edits
   `CHANGELOG.md`; nothing else is touched.

## Categorization rules

Conventional-commit prefixes are matched first (case-insensitive, scope and
breaking-change marker are stripped):

| Prefix                                                                        | Section   |
|-------------------------------------------------------------------------------|-----------|
| `feat`, `add`, `new`                                                          | Added     |
| `fix`, `bugfix`, `hotfix`, `patch`                                            | Fixed     |
| `refactor`, `perf`, `change`, `update`, `chore`, `docs`, `style`, `build`, `ci`, `test`, `deps` | Changed   |
| `remove`, `delete`, `revert`, `drop`                                          | Removed   |

When a commit has no recognizable prefix, the subject is scanned for keywords
(`add`, `fix`, `remove`, `revert`, etc.). Anything still unclassified lands in
`Changed` so no commit is silently dropped. Merge commits are excluded.

## Editorial pass (optional)

The script produces a faithful, deterministic dump of git history. If the user
wants a polished release-notes version:

1. Run the script with `--stdout` to get the raw grouped output.
2. Rewrite bullets to be user-facing: drop internal refactors that ship no
   behavior change, merge duplicates, and surface breaking changes at the top
   of the section.
3. Write the curated result back to `CHANGELOG.md`. Keep the
   `## [version] - date` heading format so the next run continues to prepend
   cleanly.

## Failure modes

- **Not a git repo** → the script exits with a clear error.
- **No commits in range** → the script prints `no commits found in range`
  and exits 0 without modifying files.
- **No tags exist** → the script falls back to the full history and labels
  the section `Unreleased`.
