# Changelog Generator

Generate a structured `CHANGELOG.md` from the current repository's git history.

## Usage

1. Copy `changelog.sh` into the root of a git repository.
2. Run `bash changelog.sh` or `bash changelog.sh path/to/CHANGELOG.md`.
3. Review and commit the generated changelog.

## What it does

- Detects the latest git tag with `git describe --tags --abbrev=0`.
- Reads non-merge commits since that tag, or all commits when the repository has no tags.
- Groups commit subjects into `Added`, `Fixed`, `Changed`, and `Removed` sections.
- Writes a Markdown changelog with short commit hashes for traceability.

## Categorization rules

The script uses lightweight commit-subject matching so it works without extra dependencies:

- `feat:`, `feature:`, `add:` and similar subjects -> `Added`
- `fix:`, `bugfix:`, `hotfix:` and similar subjects -> `Fixed`
- `remove:`, `delete:`, `deprecate:` and similar subjects -> `Removed`
- `change:`, `refactor:`, `update:`, `docs:`, `test:`, `ci:` and unknown subjects -> `Changed`

## Sample output

This sample was generated by running `bash changelog.sh SAMPLE_CHANGELOG.md` in this repository.

Generated from git history from repository start on 2026-05-28.

## Fixed

- No changes.

## Changed

- No changes.

## Removed

- No changes.
